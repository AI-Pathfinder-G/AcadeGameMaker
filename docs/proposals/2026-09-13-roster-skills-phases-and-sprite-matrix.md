# 로스터·기술·국면·스프라이트 매트릭스

- 상태: **Draft / Astra 검토·승인 대기**, 2026-09-13.
- 범위: 현재 로스터의 출처를 하나의 제작용 표로 정리하고, 이후 보스·일반 적의 행동·예고·시각 레이어를 **제안**한다. 수치가 있는 항목도 이 문서의 신규 런타임 권한, 피해 판정, AI, 충돌체, Animator, Unity 임포트 권한은 아니다.
- 선행 순서: 사용자 지시에 따라 **세령 복장 작업의 수용이 먼저**다. 이 문서는 병렬 문서 작업일 뿐 보스 모션·VFX·스프라이트 생성·후처리·임포트를 시작시키지 않는다.
- 권위: [보스전 캐논](../canon/boss-encounter-direction.md), [서사 캐논](../canon/narrative-canon.md), [크리처 명단](../canon/creature-roster.md), [BOSS-F](../specs/boss-encounter-framework.md), [VD-03](../specs/vertical-demo/03-combat-and-enemies.md), [VD-06](../specs/vertical-demo/06-humanity-choice-and-narrative.md), [오프라인 스프라이트 계약](../specs/work-contracts/2026-09-09-offline-sprite-atlas-production.md)을 따른다.

## 1. 읽는 법과 승인 경계

`T/E/R`은 각각 예고·실행·회복의 제안 틱이다. 별도 계약 전에는 60 Hz의 실제 타이머, 피해 판정, 프레임 이벤트가 아니다. `형상 봉투`는 아트와 후속 전투 계약이 함께 검토할 화면상의 위험 범위 후보이며, 실제 hitbox가 아니다. 모든 제안 행동은 **Body/Prop**, **Telegraph**, **Execute**, **Impact**, **Recovery**의 다섯 분리 레이어로 그린다. 위험 예고는 세계 팔레트의 중립 W11 계열과 무기·발·장치의 형태로 읽고, 조준 백색·전이 청록·쿨다운 호박·차단 적색은 해당 실제 상태가 이미 존재할 때만 UI/상태 오버레이로 쓴다. 일반 위험선에 청록 또는 조준 백색을 쓰지 않는다. 색은 판정이나 상태를 소유하지 않는다.

각 전투 행의 `6/6/6`은 최소 키포즈 수가 아니라 T/E/R에 필요한 최소 소스 프레임 수다. 최종 시트는 [REQ-SPR-001..010](../specs/work-contracts/2026-09-09-offline-sprite-atlas-production.md)을 따라 각 생산 행에 여섯 개의 서로 다른 키포즈를 보존한다. VFX는 몸 그림에 붙여 구워 넣지 않으며 별도 투명 레이어·별도 프레임 표로 남긴다.

`Approved`는 이미 승인된 정확한 행동 계약이 있다는 뜻이다. `Canon roster`는 이름·생태만 등록된 뜻이다. `Draft`는 아래의 행동, 수치, 배치, 공략이 모두 Astra 승인 전이라는 뜻이다. NPC의 대화·상점·거점 동작을 전투 예고로 만들거나 NPC에 런타임 전투 상태를 새로 만들지 않는다.

### VFX 메타데이터 제안 — 모든 아래 VFX에 필수

아래 표에서 이름 붙인 **각 단일 VFX**는 별도 파일/아틀라스 행을 갖는다는 제안이다. 각 행은 `logicalEnvelopePx`, `pivotOrAttachment`, `paletteRole`, `sortOrder`, `blend`, `light`, `visualTicks`, `loop`, `source`를 반드시 기록한다. 이는 순수 시각 메타데이터이며 위험 판정·조명 영향·충돌·상태 전이를 소유하지 않는다.

| VFX 종류 | logicalEnvelopePx / pivotOrAttachment | paletteRole / sort·blend·light | visualTicks·loop / source |
|---|---|---|---|
| 무기 arc·집게·낫·꼬리 arc | 48×32 / `weaponTip` 또는 `clawTip` | W11 중립 명암 / Body 위 +20, Alpha, no-light | 6, false / 해당 행동의 `visual_proposal_only` 행 |
| 바닥 먼지·자갈·충격 | 48×24 / `groundContact` | W11 토사 명암 / Body 뒤 -10, Alpha, no-light | 8, false / 해당 행동 행 |
| 유한 궤적·착탄·파동 | 64×48 / `projectileOrigin` 또는 `impactPoint` | W11 중립 명암, 실제 상태 없으면 의미색 금지 / Body 위 +30, Alpha, no-light | 12, false / 해당 행동 행 |
| 케이블·릴·판·장치 기계 효과 | 64×64 / `reelSocket`, `plateAxis`, `deviceSocket` | W11 금속 명암 / Prop 위 +10, Alpha, no-light | 10, false / 해당 행동 행 |
| 취약·전이·포착 오버레이 | 48×48 / 기존 target anchor | **실제 승인된** 취약·전이·포착 상태의 의미색만 / UI 상태 위 +100, Alpha, no-light | 상태 소유자가 제공한 기간, false / VD-03 또는 VD-02/07의 기존 상태 |
| 공중 바람·부력·막 효과 | 64×48 / `wingRoot` 또는 `sacRoot` | W11 대기 명암 / Body 뒤 -5, Alpha, no-light | 10, false / 해당 행동 행 |

각 표의 `VFX N`은 위 종류 중 필요한 N개 프레임의 드로잉 예산이며, 실제 파일명이 아니다. 최종 원본에는 이 표의 8개 필드를 빠짐없이 적고, `source`에는 Approved 기계 출처 또는 `visual_proposal_only/combat_pending`을 적는다.

## 3. 공통 공정·공정성 제안

후속 개별 계약은 모든 공격마다 (1) 화면 안의 소유자와 예고를 먼저 보여 주고, (2) 예고 중 목표·방향·경로가 언제 고정되는지, (3) 실행 후 회복 중 안전한 반격 창이 있는지를 명시해야 한다. 카메라 밖 생성, 입력을 읽어 즉시 방향을 바꾸는 회피 불능 공격, 첫 피격이 다음 피격을 확정하는 연계, 낙사 강제, 무적 대시·신규 패링 전제는 반려한다. Heavy 또는 무게 전이에 대한 반응은 기존 단일 대상·LOS·잠금 규칙을 보존하는 별도 계약에서만 확정한다.

| 레이어 | 최소 드로잉 봉투 | 역할 | 금지 |
|---|---|---|---|
| Body/Prop | 본체·무기·장치 1개 | 실루엣, 방향, 회복 자세 | 위협 범위나 포착 상태를 몸 색만으로 숨김 |
| Telegraph | 무기 자세 + 바닥/궤적 1개 | 공격 종류·고정 시점·안전측 | 화면 밖 표적, 깜빡임만 있는 예고 |
| Execute | 무기 궤적 또는 투사 경로 1개 | 실제 움직임을 읽게 함 | 무한 잔상, 유도처럼 보이는 재조준 |
| Impact | 접촉점 1개, 2~4프레임 | 타격이 끝났음을 전달 | 지속 장판으로 오인되는 과도한 잔류 |
| Recovery | 자세 붕괴/재장전/노출 1개 | 반격 창을 시각화 | 예고 없이 다시 예고로 연결 |

1. CH2~CH8의 제안 `T/E/R`과 형상 봉투를 후속 보스별 행동 계약의 시작점으로 채택할지 결정한다.
2. E3~E6, M1~M3, CRX-01~06 중 어떤 로스터를 실제 다음 계약 범위로 좁힐지 결정한다.
3. CH7 공통 전반전·선택·분기 후반전의 행동과 저장/재도전 경계를 별도 계약으로 분리한다.
4. 세령 복장 수용 뒤에만 원본 시트를 오프라인 생산 행렬에 넣고, 어떤 Draft 보스가 아트 우선순위를 얻는지 결정한다.
