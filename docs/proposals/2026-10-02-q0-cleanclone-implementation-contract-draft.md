## 문맥 선택과 실제 검증 순서

1. **외부 계획 권위.** 새 큐는 복제 밖 읽기 전용 계획 파일의 경로와 **승인된 정확 SHA**를 명시적으로 받고, 시작 시 원시 SHA·스키마·후속 source/input/selection/row/tool SHA·534 원장 SHA·허용/제외 경로를 먼저 검증한다. 시험에 전달하는 경로·SHA는 문맥 선택 신호일 뿐 단독 권한이 아니다. 시험은 이를 다시 읽어 같은 계획/근거 결속과 정확 `CurrentPublicationCleanClone` 값을 확인한다. 계획 부재·다른 SHA·알 수 없는 문맥이면 실패한다. 원래 `HistoricalQ0Delta` 실행은 기존 실제 Git 변경 목록과 원시 핀을 검사하는 별도 역사 계획에서만 유지한다. 임의 환경변수만으로 분기를 켜거나 실제 Git 출력을 주입하지 않는다.
2. **깨끗한 복제의 실물.** 새 계획은 복제의 정규화 절대 경로, 실제 `.git` 저장소/HEAD/tree, 승인된 원격 HEAD와 파일별 blob·후보 SHA, 정확 포함/제외 목록을 결속한다. 새 시험은 `git status --porcelain=v1 -z --untracked-files=all`의 **실제 결과**가 시작·선택 직전·종료에 비어야 한다고 검증하고, staged/unstaged/삭제/이름 변경/untracked를 모두 거절한다. `git ls-files`와 실제 파일 SHA로 허용 파일의 tracked 존재·내용·짝 메타/GUID를 검사하고 누락·추가·중복·경로 이탈·reparse/symlink를 거절한다. 단순히 빈 status를 성공으로 보지 않는다. 기록 출력은 복제 **밖**의 승인된 별도 증거 루트에만 `CreateNew`로 써서 실제 작업 상태를 오염시키지 않는다. 현재 도구가 출력 위치를 분리할 수 없으면 실행 전 중단한다. 입력 전후 파일 목록과 SHA, Git 상태/HEAD/tree를 별도 원장으로 비교한다.
3. **Q0 시험 본문.** 기존 `AC011_ActualRepositoryManifestClassifiesTheExactQ0DeltaWithoutFolderInference`(65–89행)와 `AC011_ActualRepositoryManifestPermitsOnlyIndividuallyNamedQ0Metas`(147–160행)는 역사 문맥에서 현재 동작을 유지한다. 현재 문맥에서는 같은 메서드명이 실제 청결 상태와 정확 tracked 허용 목록·필수 Q0 경로의 **게시 현재 바이트**·메타를 대조한다. Q0 필수 여섯 경로가 Git 변경 목록에 나타날 것을 요구하지 않되, 여섯 모두 정확 포함/출처/바이트·금지 권한 검사를 받아야 한다. `AC011_EvidenceBackedHistoricalSourcesAndPinnedC2C2RSuccessorsMatchTheirSeparateManifests`(91–132행)는 역사 9+7+두 successor 역할과 원시 바이트를 별도로 유지하고 현재 두 successor는 새 `Current` 바이트 핀으로 검증한다. `AC011_StaticProductionAuditFindsOneGeneratedSubscriberAndOneSemanticSource`(134–145행)의 단일 구독·금지 구조 검사는 그대로 실행한다. 메서드명·기존 선택·기존 음성 기준을 삭제하거나 건너뛰지 않는다.
4. **원문 25개와 현재 핀.** 534 원장의 25 `CRLF→LF` 행 각각에 실제 **원문 바이트를 읽을 수 있는 불변 별도 경로/객체**, `OriginalSha256`, `CandidateSha256`, 변환쌍 수, 정확 출처를 기록한다. Approved 원문 보존 도구의 `CurrentRawBaseline`은 현재 534 원문 역할에 한정되며 역사 14개 전이를 복원하지 않는다. 원문을 현 후보에서 역추정해 역사 증거로 만들지 않는다. 검사기는 원문 바이트에서 `0D 0A` 쌍의 `0D`만 제거한 결과가 현 후보의 실제 바이트와 같음을 검증한다. 역사 review `03AC446E...`와 LF review `A2CCBB58...`는 별도 역할이다. 원래 Q0 자원 SHA `5DD70E7A...`, predecessor `C8FD2B74...`도 원문 역할로 보존하고 LF 후보 SHA `47B1CB42...`, `983DA25E...`는 현재 게시 바이트만 증명한다. 과거 루나 문서는 새 소스·새 시험의 독립 검수가 아니다. 원문 객체 하나라도 실제 재조회할 수 없으면 역사 원시 검증은 미입증으로 남고 전체 현재 수용은 중단한다.
5. **엄격 감사·자기 지문.** `C4ExecutionBridgeStrictAuditTests.cs` 284–338행의 원래 자원 우선 SHA·본문 구조·predecessor·review 역할 검증, 343–369행의 predecessor 9행·선택 7개 SHA/이름/순서 단언을 현재 문맥에서도 동등 강도로 유지한다. 과거 SHA를 정규화 SHA로 단순 치환하거나 역사 검수를 `Current`로 변경하지 않는다. 새 자원에는 `Historical` 원시 출처와 `Current` 정규화 출처를 분리하되 자기 Q0 시험 소스 SHA나 미래 루나 문서 SHA를 넣지 않는다. Q0 시험은 새 자원의 SHA만 원시 바이트로 검사하고, 최종 source manifest가 Q0·엄격 감사·fixture·자원을 **편집 완료 후** 고정한다. 그 동결을 새 루나가 독립 검수한 뒤 별도 최종 수용 문서가 검수 SHA를 묶는다. 계획/소스/검수 문서 사이 순환이 생기면 발급을 중단한다.
6. **전체 선택과 결과.** 새 빌더는 과거 139/32/5/91/149/15/562/51/610의 정확 이름·순서·selector·부모를 유지하고, C4 **188행**, C3 **377행**의 ID·내용·순서·권한 관찰을 전부 보존한다. 현재 문맥의 Q0 기대 사실이 달라지는 행은 별도 명시적 `Current` 행/증거로 제안하되 원래 행을 재해석하거나 지우지 않는다. 새 선택 수/행 수는 최종 소스 파서 결과로 실행 전에 동결하며 기존 숫자를 자동 통과 선언하지 않는다. 모든 실행에서 180초, native/QA/outer 종료 0, 실패·건너뜀·불확정 0, 전후 동일 입력, 예상 밖/누락/중복 행 거절, 루나 P0/P1=0, 아스트라 별도 수용을 요구한다. 이것은 **실행 계약 후보**이고 이번 문서 작성은 실행 증거가 아니다.

## 필수 음성·중단 사례

실제 tracked 수정 1개, staged 1개, 삭제/이름 변경 1개, 허용 밖 untracked 1개를 각각 `Current`에서 거절한다. Git status가 빈데 필수 파일/메타·GUID·SHA·remote blob·predecessor 또는 25 원문 중 하나가 빠진 경우도 거절한다. 외부 계획 한 바이트 변경, 계획 SHA 교체, 잘못된 문맥, source/selection/row/tool SHA 차이, 출력 루트가 복제 안인 경우, 링크를 통한 경로 이탈, 과거 review를 새 검수로 표시한 경우, 원래 188/377행 또는 선택 이름이 빠진 경우는 모두 실행 전 또는 결과 판정에서 실패한다. 음성 사례는 승인 후 격리된 복제/합성 자료에서만 수행하며 실제 제품 권한·Git 상태를 시험에 주입하지 않는다. 현재 501 내용 조사, 534 도구 검수, 새 현재 바이트 루나 검수, 원격 재대조와 의존 폐쇄가 완료되기 전에는 `PublicationApproved=false`, `LunaReviewed=false`, `WholeAccepted=false`다.
