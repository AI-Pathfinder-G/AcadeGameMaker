## 승인 후보의 가장 작은 계약 분해

1. **문맥·바이트 권위 계약.** 역사 `HistoricalQ0Delta`와 새 `CurrentPublicationCleanClone`을 명시적으로 분리한다. 역사 문맥은 원래 변경·미추적 Git 상태와 원시 핀·승인 원문을 그대로 보존한다. 현재 문맥은 발급된 정확 파일별 허용/제외 목록, 534 바이트 전이, 원격 정확 HEAD/tree/blob 충돌 판정, 조립/자산/설정/QA 의존 폐쇄, Git 필터를 거친 복제 실제 SHA를 결속한 **새 불변 계획**에서만 선택한다. 루트·계획 SHA·허용 경로·시험 소스 SHA를 외부 선행 검증기로 잠그며 문자열 환경변수 하나, 파일명 관습, 테스트가 스스로 만든 목록으로 모드를 바꾸지 않는다. `Historical`에는 역사 SHA와 당시 승인 대상 버전을, `Current`에는 현재 원시 SHA·현 출처·현재 독립 검수 상태를 별개 필드로 둔다. 현재 `StaticReview`에 역사 루나 문서의 LF 후보 SHA를 넣어 새 검수라고 표시하지 않는다. 승인 전 `Current` 독립 검수 필드는 미충족이다.
2. **Q0 시험의 정확 후속.** 허용 소스는 `HubUiOnlyQ0ScopeAuditEditModeTests.cs`와 `C4ExecutionBridgeStrictAuditTests.cs`, 필요 시 두 파일의 `.meta`는 GUID·내용 불변 확인 대상으로 한정한다. 기존 AC011 메서드명·역사 시험 본문·정확 Q0 경로 분류 규칙을 보존한 채, 승인된 현재 계획에서만 별도 현재 문맥 검사를 선택한다. 현재 문맥에서도 **실제 Git 상태를 직접 읽어** 시작·선택 실행 직전·종료 시 tracked 수정/삭제·untracked가 없음을 요구한다. Q0 원래 변경 경로가 없다는 사실은 실패가 아니라 깨끗한 복제의 기대 사실로 기록하고, 대신 정확 허용 파일의 Git tracked 존재·tree/blob·후보 원시 SHA·짝 `.meta`/GUID·금지 경로 부재를 직접 대조한다. 폴더/접두사 허용, synthetic status, 임의 상태 보정은 없다. Unity/QA의 출력은 복제 밖 별도 정확 증거 루트에 기록해 시험 중 실제 Git 상태를 오염시키지 않는다. 출력이나 필수 입력이 복제 밖으로 이동하지 못하면 현재 문맥 실행은 중단한다.
3. **교차 감사·자기 지문 계약.** 엄격 감사는 원래 AC009/010 토큰·금지 API·원본 본문·predecessor·선택 이름/순서 단언을 유지하면서 두 문맥이 각각 어떤 원시 바이트를 검증하는지 구조적으로 확인한다. 현재 자원은 별도 새 경로·정확 SHA와 `Historical`/`Current` 역할을 갖되 기존 `c4-audit-current-source-pins-v2.json`, predecessor 원장, 루나 원문을 고치지 않는다. Q0 소스가 읽는 자원 SHA를 코드에 고정한다면 자원에는 Q0 소스 SHA나 미래 루나 검수 SHA를 되먹이지 않는다. 먼저 source manifest가 최종 Q0 소스·자원·엄격 감사 소스를 묶고, 그 동결을 루나가 독립 검수한 **뒤에** 별도 최종 수용 원장이 루나 문서 SHA까지 묶는다. 루나 문서가 역으로 자신의 SHA를 포함하는 source manifest의 필수 입력이 될 수 없다. 과거 원시 review 바이트를 검증할 별도 불변 원본이 없으면 역사 결속은 미입증으로 남긴다.
4. **선택·행·실행 계약.** 정확 후속 QA 도구와 계획·선택·행 원장은 기존 9개 묶음의 메서드명·번호·순서·selector·부모·전체 기대 행을 비교하고 변경된 시험 소스 SHA만 명시적으로 재발급한다. 현재 문맥 분기를 넣어 원래 시험을 선택에서 빼거나 건너뛰지 않는다. Q0 `AC011`의 현재 문맥 기대값은 별도 행/증거로 발급하되 역사 `AC011` 결과를 덮어쓰지 않는다. 전후 동일 입력, 실제 Git 청결, 180초, native/QA/outer 0, 실패·건너뜀·불확정 0, C4 188행 전체·기존 377행, 루나 독립 P0/P1=0과 아스트라 별도 수용이 필요하다. 선택 수·행 수 또는 이름이 변경되어야 한다면 실행 전 정확 새 계획과 승인 계약에서 먼저 동결하고 과거 139/32/5/91/149/15/562/51/610을 조용히 대체하지 않는다.

깨끗한 복제의 실질 목적은 게시될 **추적된 정확 바이트**가 오염되지 않은 Git 상태에서 같은 시험과 금지 범위 검사를 통과한다는 것이다. 원래 Q0 시험이 증명한 과거 작업 상태의 귀속은 역사 증거로 유지하고, 현재 게시 문맥은 실제 청결 상태·정확 파일 출처·메타·의존·동일 입력을 새 검증으로 충족한다. 현재 534 후보의 독립 내용 판정, 클린 복제의 전체 의존, 출력 경로 변경의 QA 도구 폐쇄, 새로운 루나 현재 바이트 검수는 아직 미완료다. 하나라도 없으면 후속 계약을 Approved 또는 전체 회귀 수용으로 승격하지 않는다.
