# Sol P0 통합 기본안

- Status: **Proposed — 사용자 승인 필요**
- Owner: GPT-5.6 Sol
- Review: Terra 구현성 PASS, Luna 결정성·검증성·캐논 PASS
- Date: 2026-08-24
- Scope: `OD-WT-001`, `OD-ROOM-001`, `OD-RUN-001`, `OD-CHOICE-001`, `OD-CHOICE-002`, `OD-COM-001`

이 문서는 여섯 P0을 하나의 약 15분 흐름으로 묶는 기본안이다. 승인 전에는 캐논이나 구현 계약이 아니며 스펙 상태를 변경하지 않는다.

사용자가 별도로 승인한 플랫폼 기준은 Windows x64, 키보드와 XInput 게임패드, 16:9 1920×1080, 60 FPS, 물리 고정 간격 1/60초, Unity 온라인 기능 기본 비활성이다. 이 문서는 의미 입력만 소유하고 실제 바인딩은 P1 플랫폼 계약에 둔다.

## 1. 데모의 한 문장

주인공은 탈락 구역의 불법 하방권 장부를 추적해 인간 징수자들과 싸우고, 장부를 몸에 숨긴 인간의 거부를 짓밟아 힘을 빼앗을지 그가 정한 조건으로 힘을 나눌지 선택한 뒤, 선택한 기술로 같은 봉쇄선을 서로 다른 방식으로 돌파하고 자신을 추적해 온 히로인과 처음 마주친다.

## 2. 15분 성공 경로

| 구간 | 목표 시간 | 내용 |
|---|---:|---|
| 거점 | 1분 | 기본 이동·공격 확인, 원정 시작 |
| 고정 진입방 `R01` | 2분 | 상자 대상 무게 전이 학습 |
| 변주방 A `R02` 또는 `R03` | 2분 | 이동·위험 또는 부유 적 대응 |
| 변주방 B `R04` 또는 `R05` | 3분 | 혼합 전투·환경 문제 |
| 고정 수렴방 `R06` | 1분 | 유담과 환수관의 갈등 제시 |
| 중간보스 | 3분 | 무게 전이로 대응 창 확대 |
| 선택 | 1분 | 수탈 또는 연대 확정, 기술 획득 |
| 비치명 봉쇄선 | 1분 | 선택 기술을 즉시 한 번 사용 |
| 히로인 첫 등장 | 1분 | 분기 반응 후 데모 종료 |

실패·재도전 시간은 15분 성공 경로에 포함하지 않는다.

## 3. `OD-WT-001` — 무게 전이 계약

### 대상과 조준

- 한 번에 활성 대상은 **1개**다.
- 유효 거리는 플레이어 중심 **6.0 월드 유닛**이다.
- 대상은 조준 방향 기준 **총 100도 원뿔** 안에 있고 지형에 가려지지 않아야 한다.
- `Aim` 의미 입력이 있으면 명시 조준을 사용한다. 조준 입력이 없으면 플레이어가 바라보는 방향에서 가장 가까운 유효 후보를 고른다.
- 실제 적용 전 선택 후보를 외곽선과 연결선으로 표시한다. 각 후보의 `angleKey = Round(angleDegrees × 10, AwayFromZero)`, `distanceKey = Round(distanceSquared × 1000, AwayFromZero)`를 정수로 계산한다. `(angleKey ASC, distanceKey ASC, TransferTargetId ordinal ASC)`의 사전식 비교로 정렬하고 첫 대상을 고른다. 별도 1차 점수, 가중치, epsilon 비교는 사용하지 않는다.

### 적용과 회수

- `Transfer`를 누르면 후보에게 전이한다.
- 활성 전이가 있으면 같은 입력은 거리와 시야에 관계없이 즉시 회수한다.
- 성공한 전이 또는 회수 뒤 **21 고정 틱(0.35초)** 동안 다시 바꿀 수 없다. 실패 시 상태 쿨다운은 없고 피드백 반복만 6틱 제한한다.
- 지속 시간 제한은 없다.
- 대상 제거, 방 이탈, 실패, 컷신 강제 진입 시 먼저 회수하고 참조를 제거한다.

### 데모 기준 보정값

| 상태 | 기준값 |
|---|---|
| 가벼운 주인공 | 기준 `gravityScale ×0.65`, 공중 가속 ×1.25, 최대 낙하 속도 ×0.70, 점프 충격량은 유지 |
| 무거운 상자 | 기준 `mass ×3.0`, 기준 `gravityScale ×2.0`, 충돌 피해 배율 ×1.5 |
| 무거운 일반 적 | 기준 `gravityScale ×2.2`, 이동 속도 ×0.75, 공중 제어 ×0.35, 넉백 저항 ×2.0 |
| 중간보스 | 몸 전체 직접 전이 불가, 패턴 중 노출되는 `압류추`와 상자만 전이 가능 |

모든 값은 기본값에 곱하는 배율이다. 튜닝 허용 범위와 최종 이동 수치는 P1 `OD-MOV-001`에서 고정한다.

- 입력은 프레임에서 수집하고 물리 보정은 다음 FixedUpdate 한 번에 원자 적용한다.
- 후보 검색은 반각 50도, 대상 중심점, `TransferLineOfSight` 지형 레이어, 트리거 제외를 사용한다.
- 동점 안정 ID는 데이터에 저작한 문자열 `TransferTargetId`이며 생성 순서나 Unity instance ID를 사용하지 않는다.
- VD-02는 원본 mass/gravityScale/AI 배율을 보관하지 않고 대상이 제공하는 기본값에 가역 modifier를 합성한다. 회수 뒤에는 modifier만 제거한다.
- 충돌 피해는 VD-03이 상대 법선 속도와 `ImpactDamageMultiplier`를 읽어 `DamageRequest`로 계산한다. Rigidbody2D mass 자체를 피해량으로 간주하지 않는다.
- 정리는 중복 호출 가능한 `TransferCleared(reason)`이며 대상이 이미 제거됐으면 복원 시도 없이 참조와 효과만 제거한다.

## 4. `OD-ROOM-001` — 방 풀과 시드

방 풀은 정확히 6개이며 한 런은 서로 다른 방 4개를 사용한다.

- `R01 진입 검량소`: 항상 첫 방, 상자 전이 학습
- `R02 끊어진 계단`: 이동·낙하 위험 변주
- `R03 부유 압류창`: 부유 원거리 적 변주
- `R04 체납물 보관고`: 근접 전투·상자 충돌 변주
- `R05 역류 계량관`: 혼합 전투·위험 변주
- `R06 공동장부실`: 항상 마지막 방, 유담과 보스 갈등 진입

지원 시드는 네 개의 **저작된 불변 `RoomPlanSnapshot`**으로 고정한다. 런타임에서 방이나 소켓을 무작위 생성하지 않는다.

| Seed | Room plan | Socket plan IDs |
|---:|---|---|
| 101 | R01 → R02 → R04 → R06 | S01-A, S02-A, S04-A, S06-A |
| 202 | R01 → R02 → R05 → R06 | S01-A, S02-B, S05-A, S06-A |
| 303 | R01 → R03 → R04 → R06 | S01-A, S03-A, S04-B, S06-A |
| 404 | R01 → R03 → R05 → R06 | S01-A, S03-B, S05-B, S06-A |

- 같은 시드는 방·소켓 변주까지 완전히 재현한다. 각 snapshot은 정규화 JSON과 SHA-256을 검수 증적으로 남긴다.
- 자동 선택은 `selectionRuleVersion=1`과 고정 순환 `101 → 303 → 202 → 404 → 101`을 사용한다.
- 신규 프로필은 `lastOfferedSeed=null`이며 다음 자동 시드는 101이다. 원정 시작 요청 시 다음 시드를 계산하고 `lastOfferedSeed`를 원자 저장한 뒤에만 `RunStarted`를 발행한다. 저장 실패 시 원정을 시작하지 않는다.
- 실패나 앱 재시작 뒤에도 다음 값으로 진행하므로 같은 초기 프로필은 항상 같은 순서를 만든다. 검증 메뉴의 명시 시드는 `lastOfferedSeed`를 변경하지 않는다.
- 사용자가 검증 메뉴에서 시드를 지정하면 반복 제한을 적용하지 않는다.
- 보스방, 선택 장면, 봉쇄선은 방 풀 6개에 포함하지 않는 고정 장면이다.

`RoomPlanSnapshot`은 숫자 좌표 대신 정수 격자와 안정 문자열 ID만 사용한다. RFC 8785 JSON Canonicalization Scheme payload 뒤에 단일 LF를 붙여 UTF-8 without BOM 파일로 저장하고, **저장된 파일 전체 바이트**에 SHA-256 lowercase hex를 적용한다. 해시 대상에서 제외되는 필드는 없다. 기준 파일과 해시는 `docs/verification/room-plans/`에 둔다.

## 5. `OD-RUN-001` — 실패와 보존

### 실패 조건

- 체력이 0이 됨
- 낙하 한계선을 통과함
- 명시적으로 `Lethal`인 압착 위험에 닿음

시간 초과, 길 찾기 지연, 일반 메뉴 진입은 실패가 아니다. 동일 프레임의 복수 원인은 첫 유효 실패만 확정한다.

### 상태 보존표

| 상태 | 실패 후 | 앱 재시작 후 |
|---|---|---|
| 현재 체력·위치·속도 | 초기화 | 초기화 |
| 활성 전이·대상 참조 | 제거 | 제거 |
| 방 순서·현재 방·적·위험·보상 | 제거 | 제거 |
| 원정 중 임시 자원 | 제거 | 제거 |
| 설정·입력 바인딩 | 보존 | 보존 |
| 튜토리얼 확인 플래그 | 보존 | 보존 |
| 확정된 인간성 선택·해금 기술 | 보존 | 보존 |
| 완료한 데모 분기 기록 | 보존 | 보존 |

- 활성 런은 저장하거나 이어 하지 않는다. 앱을 끄거나 비정상 종료한 뒤에는 거점의 새 원정 상태로 시작한다.
- 실패 전 선택이 없으면 거점으로 복귀해 새 시드로 시작한다.
- 선택 뒤 봉쇄선은 비치명 구간이므로 확정된 선택이 실패 처리와 충돌하지 않는다.
- 수직 데모 저장은 단일 로컬 프로필과 별도 설정 파일을 사용하며 구체 JSON 필드는 P1 플랫폼 계약에서 고정한다.
- 두 분기 반복 검증은 Editor/Development Build 전용 `ResetDemoProfile` 명령으로만 수행한다. 일반 플레이 메뉴에는 노출하지 않는다.
- 선택 확인 직후 프로필을 원자 저장하고, 임시 파일 쓰기 실패 시 기존 정상 snapshot을 유지한다.

## 6. `OD-CHOICE-001` — 선택 대상과 장면

### 선택 대상: 공동장부 보관자 `유담`

유담은 전직 하방권 검침관인 인간이다. 그는 탈락 예정 시민 47명의 동의를 받아 각자의 중력 서명을 한 장의 불법 공동장부로 묶었고, 중앙 환수망이 장부를 읽지 못하도록 자신의 신경계에 보관했다. 그는 영웅이 아니라 위조 과정에서 타인을 위험에 빠뜨린 책임도 지며, 장부를 어떻게 쓸지 스스로 정할 권리를 끝까지 주장한다.

### 장면 순서

1. `R06`에서 유담과 환수관 오르단의 대립을 목격한다.
2. 오르단은 공동장부가 도시 기준면을 무너뜨린다고 주장하고 유담을 압류한다.
3. 주인공이 오르단을 쓰러뜨리지만 유담은 압류 침에 고정되어 있고 봉쇄선이 닫히기 시작한다.
4. 유담은 장부의 일부를 **조건부로 함께 쓰는 계약**은 허용하지만 소유권 이전과 강제 추출은 거부한다.
5. 플레이어가 수탈 또는 연대를 명시적으로 확정한다.
6. 기술 획득 뒤 비치명 봉쇄선에서 선택 기술을 사용한다.
7. 출구에서 히로인이 별도 추적자로 처음 등장한다.

히로인은 선택을 보상하지 않는다. 수탈 경로에서는 유담의 상태를 먼저 확인하고 주인공을 경계하며, 연대 경로에서도 즉시 신뢰하지 않고 약속을 실제로 지키는지 보겠다고 선언한다.

### 동의와 침해의 관찰 가능한 상태

| 단계 | 유담 상태 | 사건 | 관찰 결과 |
|---|---|---|---|
| 선택 전 | `RefusesOwnershipTransfer` | `ConsentRefused` | 장부 소유권 이전을 명시적으로 거부 |
| 연대 제안 | `OffersScopedResonance` | `ConsentOffered(scope=BarrierAndSkill)` | 사용 범위와 철회권을 말하고 확인 동작을 요구 |
| 연대 확정 | `ResonanceLender` | `ChoiceCommitted(Solidarity)` | 유담의 각인과 공동장부가 남고 사용 권한만 주인공에게 기록 |
| 수탈 확정 | `ImprintSevered` | `ChoiceCommitted(Extraction)` | 거부를 무시하고 각인 사본을 강제 절단, 유담의 장부 빛과 조작 능력이 사라짐 |

- 확정 전 취소는 `ConsentOfferCancelled`로 돌아가며 선택을 기록하지 않는다.
- 연대 권한은 유담의 소유권을 이전하지 않는 `ResonanceLease`다. 봉쇄선 앵커는 유담의 확인 동작 뒤에만 켜진다.
- 실제 무게 전이 대상은 상자·적 규칙을 유지한다. 유담이나 앵커 자체를 `TransferTarget`으로 추가하지 않는다.

## 7. `OD-CHOICE-002` — 분기 기술

두 기술은 같은 의미 입력 `ChoiceSkill`을 사용하고 선택 전에는 비활성이다. `GameplayEnabled` 입력 모드에서만 동작하며 UI, 컷신, 방 전환, 실패, 종료 상태에서는 잠긴다. 재사용 시간은 60 Hz 고정 시뮬레이션 틱으로 계산하고 성공한 발동이 확정된 틱부터 시작한다.

### 수탈 기술 `압착 판결`

- 조건: 활성 전이 대상이 존재함
- 동작: 대상에게 모인 무게를 0.60초 동안 강제 압축한 뒤 반경 2.5의 충격파를 발생시킨다.
- 효과: 중심 대상 4 피해, 주변 적 2 피해와 1.0초 경직, 금이 간 봉쇄물 파괴
- 비용: 발동 즉시 활성 전이를 강제 회수
- 재사용: 300틱(5초)
- 성격: 빠르고 파괴적이며 별도 협력 대상이 필요 없다.
- 같은 대상이 중심과 주변 판정을 모두 충족하면 중심 피해만 한 번 받는다. 피해 요청은 안정 `DamageRequestId`로 중복 제거한다.

### 연대 기술 `공동 기준면`

- 조건: 활성 전이 대상이 존재함
- 동작: 발동 틱의 플레이어 X와 대상 X를 양 끝으로 고정하고 대상 Y에 150틱(2.5초) 동안 임시 수평 기준면을 만든다.
- 발판: 길이 1.5~6.0, 두께 0.25의 kinematic one-way platform이며 `PlayerOnlyPlatform` 레이어를 사용한다. 생성 뒤 플레이어나 대상 이동을 추적하지 않는다.
- 효과: 플레이어가 처음 접지하면 점프와 대시를 한 번 회복한다. 적과 상자는 발판 collider를 무시하지만 활성 대상 하나에는 `ResonanceHold`를 60틱 적용한다.
- `ResonanceHold`: 대상 소유 시스템이 속도·중력·AI 이동을 멈추고 종료 시 저장한 속도를 대상별 최대 속도로 clamp해 복구한다. 제거·사망·장면 전환 시 속도를 복구하지 않고 상태만 정리한다.
- 환경: 유담의 동의로 켜진 공동 서명 앵커는 새 collider를 만들거나 발판을 늘리지 않고 `BarrierGate-ConsentLock`만 해제한다. 봉쇄선의 전이 가능 상자 `BarrierCounterweight`와 플레이어 사이에 생긴 기존 발판으로 통로를 건넌다.
- 비용: 활성 전이를 유지하며 종료 뒤 자동 회수하지 않는다.
- 재사용: 420틱(7초)
- 성격: 직접 피해는 없지만 이동, 군중 제어, 환경 해결을 한 규칙으로 결합한다.

### 선택 직후 검증 봉쇄선

- 봉쇄선에는 방 전환 뒤에도 존재하는 안정 ID `BarrierCounterweight` 상자 하나가 반드시 배치된다. 선택 기술 안내 전에 이 상자에 활성 전이가 성립하지 않으면 장면을 시작하지 않고 계약 오류를 기록한다.
- `BarrierStarted` 시작점에서 상자는 플레이어로부터 6.0 유닛 이내이고 LOS가 보장되며, gap 폭은 5.5 유닛 이하로 저작한다.
- 수탈 경로는 `BarrierCounterweight`에 `압착 판결`을 사용해 `BarrierGate-Fractured`를 부순다.
- 연대 경로는 같은 상자에 `공동 기준면`을 사용하고, 유담이 켠 `ConsentAnchor-Barrier`가 `BarrierGate-ConsentLock`만 해제해 기존 발판으로 끊어진 통로를 건넌다.
- 두 경로의 이동 시간 차이는 10초 이내로 제한한다.

같은 틱에 `ChoiceSkill`과 `Transfer`가 들어오면 유효한 `ChoiceSkill`을 먼저 처리한다. 수탈은 발동 뒤 전이를 회수하므로 같은 틱의 `Transfer`를 소비하고, 연대는 전이를 유지하므로 같은 틱의 `Transfer`를 무시한다. 실패한 `ChoiceSkill`은 전이 입력을 막지 않으며 `NoActiveTransfer`, `Cooldown`, `InputLocked`, `InvalidTarget` 중 하나를 반환한다.

## 8. `OD-COM-001` — 적과 중간보스

### 일반 적 A `징수보행관`

- 인간 근접 집행자, 방패와 충격봉 사용
- 접근·방어·짧은 돌진으로 공간을 압박한다.
- 무거워지면 이동 속도가 줄고 돌진 뒤 회복 시간이 늘어난다.
- 기본 공격만으로 격파할 수 있으며 무거운 상자 충돌이 방패를 즉시 연다.
- 체력 9, 접촉·충격봉 피해 1, 방패가 열린 시간 90틱(1.5초)을 기준으로 한다.

### 일반 적 B `부유측량사`

- 개인 부력 장치와 계량선 발사기를 쓰는 인간 원거리 집행자
- 공중에서 위치를 바꾸며 플레이어의 이동 지점을 짧게 봉쇄한다.
- 무거워지면 부력 장치가 과부하되어 지면으로 내려오고 1.25초 동안 사격하지 못한다.
- 기본 공격만으로도 점프 접근 후 격파할 수 있다.
- 체력 6, 계량선 피해 1, 과부하 사격 잠금 75틱(1.25초)을 기준으로 한다.

### 중간보스 `환수관 오르단`

오르단은 공동장부를 도시 붕괴의 원인으로 믿는 인간 환수 집행관이다. 세 개의 압류추를 단 외골격을 사용하며 유담을 단순 악당이 아니라 위험한 질서 파괴자로 본다.

| 패턴 | 신호 | 기본 대응 | 무게 전이 이점 |
|---|---|---|---|
| `체납선 긋기` | 바닥에 직선 측량광 0.8초 | 점프 또는 대시 | 없음, 기본 이동 검증 |
| `압류추 투하` | 천장 압류추가 플레이어 위치를 표시 | 이동 후 빈틈 공격 | 압류추를 무겁게 해 더 빨리 낙하시켜 오르단을 맞히면 2.0초 취약 |
| `균형 감사` | 외골격 고정 후 상자 흡인 | 상자 뒤 엄폐 후 충격파 회피 | 상자를 무겁게 해 흡인을 끊으면 패턴 중단과 1.5초 취약 |

- 플레이어 체력 5, 기본 공격 피해 3, 기본 공격 최소 간격 21틱(0.35초), 피격 무적 45틱(0.75초)을 검수 기준으로 한다.
- 오르단 체력 60, 오르단 공격 피해 1, 압류추 역충돌 피해 8을 기준으로 한다.
- 평균 보스 전투 목표는 첫 완주 90~150초, 검수 상한 180초다. 같은 검수자의 3쌍 표본에서 전이 사용 평균 완료 시간은 미사용 평균의 85% 이하여야 한다.
- 상태는 `Idle → Telegraph → Execute → Recovery | Vulnerable → Defeated` 단방향 전이로 처리한다.
- 패턴 순서는 `체납선 → 압류추 → 체납선 → 균형 감사`를 반복하며 런타임 RNG를 사용하지 않는다.

| 패턴 | Telegraph | Execute | Recovery | 특수 규칙 |
|---|---:|---:|---:|---|
| 체납선 | 48틱 | 21틱 | 39틱 | 직선 판정은 Execute 첫 틱에 한 번 생성 |
| 압류추 | 60틱 | 최대 72틱 | 48틱 | 노출된 scripted handle 하나만 전이 가능, 성공은 패턴당 한 번 |
| 균형 감사 | 60틱 | 90틱 | 48틱 | 상자 전이 성공 시 Execute를 중단하고 90틱 취약 |

- 압류추는 Dynamic joint가 아니라 보스 소유 kinematic scripted payload다. Telegraph 동안 안정 ID `BossWeight-0..2` 중 하나의 전이 handle만 켜고, 전이 성공 → 가속 낙하 → 보스 피해 → 120틱 취약 순서로 사건을 발행한다.
- 체력 42와 21을 처음 밑돌면 현재 피해 요청을 끝낸 뒤 단계 전환을 예약한다. Execute와 Telegraph를 중간 취소하지 않는다.
- 2·3단계 속도 배율은 Execute/Recovery에 각각 1.10, 1.20을 적용하되 Telegraph는 항상 최소 48틱(0.8초)을 유지한다.
- 선택 기술 없이 격파 가능해야 한다.
- 성공은 오르단의 체력이 처음 0이 된 순간 한 번 확정한다.
- 실패는 승인된 런 실패 조건을 사용하며 보스만의 즉사·시간 제한은 없다.
- VD-03은 안정 `DamageRequestId`를 한 번만 수락한다. 같은 틱 복수 요청은 ID 오름차순으로 처리하며 사망 확정 뒤 나머지를 무시한다.

## 9. 히로인 첫 등장 분기 톤

대사는 확정안이 아니라 장면 의도를 보여 주는 표본이다.

- 수탈: “그 힘을 누구에게서 빼앗았는지부터 말해.” 유담을 먼저 살핀 뒤 주인공과 거리를 둔다.

- `TransferStateChanged(targetId, playerModifier, targetModifier, tick)`
- `TransferCleared(reason, previousTargetId, tick)`

## 11. 검증 표본과 추적성

- 네 지원 시드 × 두 선택의 **8개 성공 경로**를 숙련 검수자가 각각 1회 이상 완주해 진행 불능 여부와 시간을 기록한다.
- `AC-SCOPE-003` 시간 판정은 신규 프로필·자동 시드 101로 시작하는 첫 플레이 검수자 3명의 성공 경로 중앙값이 12~18분인지 측정한다. 선택은 검수자가 자유롭게 하되 분기를 기록한다.
- 같은 초기 프로필에서 자동 시드 순환을 두 번 재생해 `101, 303, 202, 404` 순서와 snapshot SHA-256 일치를 확인한다.
- 수탈·연대 분기 사이 봉쇄선 통과 시간 차이가 10초 이내인지 확인한다.
- 보스는 같은 검수자·시드 101·신규 프로필로 무게 전이 미사용/사용 3쌍을 `미사용→사용`, `사용→미사용`, `미사용→사용` 순서로 수행한다. 여섯 성공 표본이 모두 180초 이내이고 사용 평균 완료 시간이 미사용 평균의 85% 이하여야 한다. 사망·진행 중단 표본은 평균에서 제외하고 같은 조건으로 최대 2회 재시도하며, 여섯 성공 표본을 확보하지 못하면 AC는 실패다.

## 12. 승인 시 처리

사용자 승인 뒤 Sol이 다음을 수행한다.

2. VD-02~VD-07과 SYSTEM-CONTRACTS에 수치·명령·사건·AC를 반영한다.
