## 현재 확인된 사실과 결정의 범위

기존 후보와 겹친 C4 변경 10파일은 원래 후보 SHA와 현재 실물·v19 SHA가 각각 맞다. v1–v19 동결에서 다른 지문으로 바뀐 전이는 14개다. 승인 문맥 45개, 독립 검토 인용 40개, 동결 지문은 원장과 맞지만, **14개 전이 모두 당시 구현 바이트가 없다.** 따라서 열린 간격은 14/14, 완전한 파일 사슬은 0/10이다. 변경의 관측, 승인 문장의 존재, 현재 코드의 시험 통과는 그 시점의 실제 바이트가 승인 범위 안에서 구현·검수됐다는 증명과 다르다. 원래 후보 바이트 자체도 현재 보유되지 않았다는 원장 표시를 유지한다.

최초 원장은 초기 후보489와 추가 C4 후보12의 고유 501경로를 분류한다. 역사적 직접 근거61 중 현재 동일 지문은 60이며, 원래 근거 공백428은 남아 있다. C4 신규 source/test6·meta6은 기존 변경10과 별도이며, 신규 meta6의 현재 바이트 제한 수용도 전체 이전→현재 사슬을 폐쇄하지 않는다. 원장의 게시 허용 집합은 비어 있고 501행의 `PublicationApproved`는 모두 거짓이다. 이 제안의 두 선택지는 그 값을 곧바로 바꾸지 않는다.

| 선택 | 출처를 입증하는 방식 | 얻는 것과 감수할 위험 |
| --- | --- | --- |
| **A. 역사 바이트 사슬 엄격 유지** | 원래 후보 바이트와 14개 전이의 `FromSha256`·`ToSha256` 실제 구현 산출을 찾아, 각 바이트의 생성 시점·Approved 정확 파일/수정 범위·독립 루나 검수·다음 동결을 끊김 없이 연결한다. | 당시 승인 범위와 실제 구현의 연속성을 증명할 수 있다. 보존되지 않은 바이트 또는 시점별 자료를 찾지 못하면 10파일은 계속 미입증이고 게시 허용 목록에 넣을 수 없다. 지문만 적힌 원장이나 뒤의 현 파일로 당시 바이트를 재구성했다고 주장하지 않는다. |
| **B. 사용자 명시 결정 뒤 현재 바이트를 새 기준으로 독립 검증** | 과거 14개 간격과 원래 후보 바이트 부재를 영구히 기록한 채, 별도 새 출처 계약이 **정확 파일·현재 SHA·새 기준 시점**을 정한다. 그 기준에서 실제 코드·자산·메타·설정·패키지·조립 의존, Approved 요구와 금지 범위, 시험을 처음부터 파일별 독립 검증한다. | 보유하지 않은 역사 바이트에 막힌 게시 검토를 앞으로 진행할 수 있는 후보가 된다. 대신 과거 각 구현이 당시 승인됐다는 주장은 포기하며, 현재 바이트를 과거 C3/C4 수용 지문으로 소급 승격할 수 없다. 새 기준 검증의 범위·비용·불확실성을 명시적으로 받아들여야 한다. |

**B는 현재 계약의 해석만으로 실행할 수 없다.** 사용자가 역사 출처 연속성 대신 새 현재 기준을 선택할지 명시하고, 아스트라가 원본 규범과 충돌 여부를 판정하여 새 Approved 출처·검증 계약을 발급해야 한다. 그 계약은 원래 501행과 역사 승인·실패 기록을 원본 그대로 보존하고, 새 기준의 포함/제외 후보를 파일별로 다시 승인해야 한다. 과거 14개 간격의 `ChainClosed=false`는 그대로이며, 새 기준의 검증 상태를 별도 필드·원장·증거로 기록한다. 새 기준 성공을 역사 사슬 폐쇄나 과거 승인으로 표기하지 않는다.

## 어느 선택에서도 남는 게시 게이트

428개 원래 공백은 실행 자산17, 설정10, 조립파일154, 파일 메타190, 폴더 메타36, QA 도구·선택 원장13, Q0 직접 읽기 문서4, 외부 작업자2, 감사 선행 원문1, 패키지·바이트 기반1로 남는다. C4 신규12의 최초 생성·정확 허용·현재 지문과 변경10의 선택별 출처도 별도다. 파일별 승인/검수와 `Renderer2D` 미해석 GUID의 실제 출처, 자산·프리팹·장면 GUID, `asmdef`/참조, 패키지·설정 호환성을 확인해야 한다. 원격 기본 가지의 현재 트리도 게시 직전에 다시 대조한다. 당시 원격 스냅샷의 존재·지문 수치를 현재 상태로 재사용하지 않는다.

정확 포함/제외 목록이 승인된 뒤에야 격리된 깨끗한 복제에 그 목록만 반영하고 실제 Unity 6000.6.0f1의 패키지 해석·가져오기·컴파일·참조·자산, 승인된 C3/C4 선택·행·종료값·전후 입력 지문을 검증할 수 있다. Q0의 Git 변경·미추적 상태를 요구하는 시험이 깨끗한 게시 복제에서 어떻게 성립하는지도 별도 계약으로 판정해야 한다. 구현 담당자 자체 결과와 독립 루나 검수, 아스트라의 파일별 승인 및 최종 게시 판단을 분리한다. 어느 경로도 이번 문서만으로 빌드 가능성, 전체 수용, 게시 가능성을 입증하지 않는다.

결정을 준비할 때 사용자가 비교할 핵심은 **당시 바이트까지 추적하는 연속성(A)**과 **역사 공백을 공개한 채 새 기준으로 현재 자료를 검증하는 방식(B)**이다. 자료를 찾지 못했다는 이유만으로 B를 자동 선택하거나 승인하지 않는다. 이번 문서는 새 파일 한 개만 작성했으며 기존 소스·자산·설정·원장·계약·QA·Git·원격을 바꾸거나 Unity/클린 복제를 실행하지 않았다. 이 경로는 작성 전 부재했고 v19 입력1084·source193의 경로 밖이었다.
