# Q0 깨끗한 복제 구현 전 독립 반대 검토

대상: `docs/proposals/2026-10-02-q0-cleanclone-implementation-contract-draft.md` (Draft). 판독은 정적 문서·소스 검토뿐이며 구현·실행·Git·네트워크를 수행하지 않았다. Draft의 REQ-PLAT-061/062 및 AC-PLAT-059/060은 미승인 후보 ID다. 새 구현·제품 승인·게시 승인을 뜻하지 않는다.

## 판정

- P0: 0건. P1: 2건의 구현 전 차단점. Draft는 일부를 위험으로 적었으나 실제 권위·시험 경계가 아직 구현 가능한 계약으로 닫히지 않았다.
- 승인 후보로 진행하기 전, 아래 권위 루트와 깨끗한 복제 시험을 별도 Approved 계약에서 결정해야 한다. 현재 적용된 승인 범위는 원문 보존 도구와 원격 객체 결속의 제한 수용뿐이다. 전체 501 의미 의존 폐쇄·게임 회귀·클린 복제·게시 권한은 미수용이다.

## 후속 승인 시 필수 / 금지

1. **P1 — 계획 SHA는 권위가 아니다.** 기존 다섯 QA 도구 가운데 큐는 `artifacts/c4-final-validation-queue.ps1:1-15`에서 호출자가 준 `PlanPath`/`PlanSha256` 일치만 확인하고, 선택 실행도 `artifacts/c4-final-selected-run.ps1:1,11-13`에서 같은 입력을 신뢰해 계획을 읽는다. 자체 일치 SHA는 임의 계획의 승인을 증명하지 않는다. 복제 밖 승인 원장/서명 등 신뢰 기준을 먼저 정하고, 정확 승인 계획 지문과 승인자를 그 기준에 결속하라. 시험에 전달된 임의 caller SHA를 승인 상태로 승격하지 말 것. 현재 승인 자료에는 Q0 게시 계획의 승인 SHA가 없다.
2. **P1 — 기존 Q0는 깨끗한 복제 시험이 아니다.** `HubUiOnlyQ0ScopeAuditEditModeTests.cs:65-89,147-160`은 실제 변경·미추적 목록에서 Q0 경로가 나타나야 하고, 시험 당시 저장소가 이미 dirty였다고 명시한다. 이 시험을 `CurrentPublicationCleanClone` 통과로 재명명하거나 옛 역사 Q0 플래그를 재사용하지 말 것. 역사 분기는 별도 유지하고 새 문맥은 별도 AC·별도 상태로 기록해야 한다.
3. **필수 — 실제 Git 상태를 독립 증명.** Draft `:19-20`의 시작·선택 직전·종료 status, HEAD/tree, `ls-files`, 원격 출처 및 파일 SHA 대조는 기존 도구에서 확인되지 않았다. `c4-capture-inputs.ps1:4-13`은 `Assets/Packages/ProjectSettings/qa` 입력을 열거·해시할 뿐 `.git` 상태나 문서·원장 전부의 청결을 증명하지 않는다. 새 검증 경계가 실제 상태를 직접 읽고, staged/unstaged/delete/rename/untracked 및 링크 이탈을 거부하도록 명시하라. 상태가 없거나 관측이 불완전하면 실패로 남겨라.
4. **필수 — 결과를 복제 밖에 원자 생성.** 기존 큐 결과는 `artifacts/c4-final-validation-queue.ps1:11,22,31-44`의 저장소 내부 고정 경로이며, 자식 결과도 계획의 저장소 내 출력 경로를 사용한다. `c4-verify-run.ps1:7,23-24`는 그 결과를 읽고 같은 트리 안에 검증 보고를 쓴다. 이 도구들의 결과를 클린 상태 증거로 재사용하지 말 것. 새 증거 루트의 정규화 경로·복제 이탈·`CreateNew`·충돌 중단을 실행 전 확인해야 한다.
5. **필수 — 원문 25개는 역할 한정.** `docs/approvals/2026-10-02-raw-lineage-limited-acceptance.md`는 현재 기준 원문 보존만 수용하고 역사 14전이 복원을 부인한다. Q0 초안 `:21`도 25개 원문 객체와 LF 후보를 별도 결속하라고 제안한다. 이를 현재 25개 기준의 재현으로만 취급하고 과거 14전이/428 공백이나 게시 적합 증거로 승격하지 말 것.
6. **필수 — 역사 선택·행 보존과 현재 증거 분리.** Draft `:24,28`의 188 C4행·377 C3행 및 선택 이름/순서는 변경 전 실제 선택 원장·파서와 대조해 별도 역사 입력으로 고정해야 한다. `C4ExecutionBridgeStrictAuditTests.cs:281-338`는 현재 successor 두 개의 출처·승인·검수 결속을, `:340-369`는 predecessor 9개와 선택 7개의 정확 SHA를 강제한다. 기존 행을 현재 기대행으로 재해석하거나 이전 SHA를 LF 후보 SHA로 덮어쓰지 말 것. 이 정적 보존만으로 게임 전체 회귀 충족을 주장하지 말 것.
7. **필수 — fixture 핀은 역사 사례 경계.** Edit fixture `C4ActualExecutionEditFixtureV1.cs:834-855,1128-1146,1329-1349`는 v16/v1 원장 및 특정 runtime 바이트를 실제 실행 fixture에서 검증한다. Play fixture `C4ActualExecutionPlayFixtureV1.cs:821-842,879-893,976-998`는 v1/v17 원장과 runtime 바이트를 검증한다. 새 Current 핀을 추가하더라도 기존 역사 원장·전제·본문을 별도 보존하고 새 clean-clone 출처를 증명하는 것으로 혼동하지 말 것.
8. **필수 — 검수 자기참조 금지.** Draft `:22`의 최종 소스 고정→독립 Luna 검수→별도 수용 순서를 유지하되, 계획·소스·검수 보고가 서로의 미래 SHA를 요구하는 순환을 허용하지 말 것. Luna 보고의 해시는 보고 완료 후 외부 수용 문서가 기록해야 한다. 과거 루나 문서나 이 사전 검토를 새 구현의 독립 검수로 표시하지 말 것.
9. **필수 — 제한 수용의 경계 유지.** `docs/approvals/2026-10-02-content-survey-evidence-limited-acceptance.md`는 조사 기록·원격 객체 결속만 수용하고 의미상 간접 의존 폐쇄를 미수용한다. 최신 원격 보완 결과는 기록 시점의 트리 관측이다. 둘 다 지금의 원격 HEAD, 501 콘텐츠 전부, Q0 clean-clone 실행 또는 게시 승인으로 주장하지 말 것.
10. **최소 구현 순서 제안:** (a) Astra가 별도 소유 Approved 계약에서 신뢰 가능한 외부 승인 계획 기준·현재/역사 상태·정확 허용 범위를 승인하고 미수용 선행 조건을 명시, (b) 출력 없는 정적 검증기에서 고정 HEAD/tree·tracked 집합·파일/메타/GUID/SHA·25 역할·188/377·선택 파서 결속 및 fail-closed를 구현, (c) 격리 복제에서 상태별 양성/음성·링크·임의계획 SHA 거절과 복제 밖 출력 경계를 검증, (d) 소스·계획·도구·결과 핀을 동결, (e) 새 Luna 독립 검수와 Astra 제한 수용을 별도 수행. 각 단계 승인 전 실제 게임 실행·게시로 넘어가지 말 것.
