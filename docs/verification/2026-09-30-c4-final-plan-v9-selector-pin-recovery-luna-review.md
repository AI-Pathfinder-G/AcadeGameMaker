# C4 최종 계획 v9 선택 지문 복구 설계 검토

검토 대상 제안 `docs/proposals/2026-09-30-c4-final-plan-v9-selector-pin-recovery-design.md`의 SHA-256은 `785660FA689413B8F3BF9C4D1CCDC6D2C5349AAA6B13CA6408D6E94F673919BC`이다. 근거 계획 v9은 `F978880C873D668497D695944BE3D054BA0B998E994054C67EC84B0AAF4DFED0`, 소스 원장 v13은 `E4D55B1923547F9347E0A1DB61355007B7608EA1BC240D0F7EA503CAADBD530D`, 입력 목록 v13은 `9C4C09B574779DE53E6E5CA48F942AF73BAA04E14253B36F2F8F6EE71849538D`이다.

제안의 제한된 수정 범위는 적절하다. 기존 생성기로 Edit v6과 Hub v3을 새로 만들고 각 원본과 구조 비교해 Bridge 열거형 SHA 한 값만 달라지도록 한다. 이전 선택·계획·원장·입력은 보존한다. 원장 v14는 기존 v13 항목을 유지하면서 새 두 선택과 v13 원장·제안·독립 검토·후속 승인 문서를 증거로 추가한다. 입력 v14는 기존 경로와 사유를 보존하고 같은 신규 자료를 포함한다. 새 계획 v10은 이 자료에 결속하며 아홉 선택 전부의 실제 소스 SHA, 선택 이름·순서·선택식, 행과 선행 지도를 실행 전에 검사한다. 두 fixture, 제품, QA, 188개 행과 기존 일곱 실행 선택을 바꾸지 않는다.

## 판정

P0 0건, P1 2건이다.

1. 선택 생성기는 고정 v1 출력 경로에 `CreateNew`로 기록한다. 제안은 두 선택을 각각 실제 생성하도록 하지만, 두 생성이 서로 다른 빈 임시 작업 공간에서 이루어져야 한다고 명시하지 않는다. 같은 경로를 순차 재사용하면 첫 v1 결과가 남아 두 번째 생성이 실패한다. Edit와 Hub 각각에 대해 출력이 사전 부재한 별도 격리 경로를 쓰거나, 첫 결과를 새 선택 파일에 보존한 뒤 임시 v1이 없어졌음을 다시 확인하고 다음 생성을 수행하도록 규정해야 한다.

2. 앞선 재생성 P1을 반복하지 않으려면 결과 증거에 임시 v1의 실행 전 부재, 실제 생성기·복사 입력 지문, 작업 경로와 전체 호출 인자, 프로세스 종료 코드, 생성 v1 SHA와 새 선택 전체 구조 일치, 로그 SHA, 저장소의 기존 v1 전후 SHA를 남겨야 한다. 현재 제안은 실제 실행·구조 비교와 기존 v1 보존을 요구하지만 이 항목들을 재현 가능한 기록으로 발급하라고 명시하지 않는다. 두 실행 각각의 기계 판독 증거와 원시 로그 보존을 계약에 추가해야 한다.

이 검토에서는 설계 문서만 읽었다. 선택 생성기, 큐, Unity, 컴파일은 실행하지 않았으며 구현·실행 승인이 아니다.
