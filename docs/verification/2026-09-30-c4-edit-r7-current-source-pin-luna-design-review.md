# C4 Edit R7 현재 소스 지문 복구 설계 검토

- 검토 대상: `docs/proposals/2026-09-30-c4-edit-r7-current-source-pin-recovery-design.md`
- 검토 대상 SHA-256: `8C4F98A6E3B1711D993F8DB692A893954C6A8AE9F42D7C45DCD818B5B37C733A`
- 범위: 설계의 정적 정합성만 검토했다. 구현, 동결, 큐 실행 또는 Unity 통과를 판정하지 않는다.

## 판정

P0 0건, P1 0건이다. 이 제안은 이전 첫 실행의 실패를 제품 통과로 바꾸지 않고, 실제 실패 원인으로 확인된 두 개의 낡은 Bridge 지문만 현재 승인 원장 지문에 맞추도록 범위를 제한한다.

## 대조 결과

실제 Edit fixture는 다섯 원장 참조를 갖는다. Busy 검사와 NoOp 단일 호출 검사는 각각 Bridge의 옛 지문을 보유하며, NoOp 검사의 Owner 지문과 Busy 검사의 다른 두 Runtime 지문은 현재 승인 원장과 일치한다. 두 fixture 자기 참조는 v12를 사용한다. 일반 저장소 검사는 별도 v1 역사 지문을 사용한다. 제안은 앞의 네 참조만 v16 및 현재 Bridge 지문으로 갱신하고, 일반 저장소 역사 검사는 그대로 두도록 정확히 구분했다. 현재 Edit fixture SHA는 `16DEB90F87C0E66A6DFD8C04E9C0DB6EC91F59F0051690853B61FA5C49489B0C`, Play fixture SHA는 `F73BCC9EA0493214FC65B3005862DA5666F6EBEDD759C68CB9910D006D2C7B10`, Bridge SHA는 `52E00FE10FDEAFB8C192CF7F92B2EA428C16A202D640BEAF79C8F58E6704F32A`, Owner SHA는 `2838102F468C325E9A41C5302E753BB358179F63F0A84BEE40AFC282292C9BA7`다.

검사 의미도 보존된다. Busy 검사의 파일 잠금·Busy 예외·C1 결과 및 호출 순서 검증, NoOp 표현식, Bridge 네 토큰과 Owner 세 토큰의 정확히 한 번 검사, 실제 파일 바이트 해시 비교를 완화하지 않는다. Runtime과 부모 시험, 선택 이름·순서, 188개 행의 기대값은 변경 대상에서 제외된다. 행 v8은 Edit fixture의 `SourceFiles` 지문 한 값만 바꾸고, 선택 v6는 부모 시험과 선택 집합이 그대로여서 재사용한다.

v16 원장이 수정된 fixture의 사후 SHA를 보유하고 fixture가 그 원장을 읽는 구조는 자기 참조가 아니다. fixture에는 원장 자체의 SHA가 들어가지 않고, v16 입력 목록이 원장과 행 자료를 입력으로 포함한다. Play fixture가 기존 v12를 읽는 동작도 유지되며, v16 원장은 Play fixture의 현재 실제 SHA를 고정한다. 일반 저장소의 v1 확인은 과거 불변 지문을 계속 검사한다.

이전 첫 실행의 산출물은 XML·로그·전후 캡처·네이티브 종료 기록 등 이미 존재하는 파일로 확인된다. 따라서 새 첫 실행 stem과 여덟 출력 경로를 쓰고 기존 `result-v9`도 보존한다는 조건은 적절하다. 나머지 여덟 실행의 출력 부재를 실행 직전에 재확인하고, 하나라도 있으면 새 계획 없이 진행하지 않는 조건도 덮어쓰기를 막는다. 결과 경로 한 줄 외의 큐 도구 동작, 캡처·검증·QA 도구는 변경하지 않는 범위가 명확하다.

## 한계

새 승인, v16 원장·입력, 행 v8, 계획 및 실제 실행은 아직 이 설계 검토의 대상이 아니다. 따라서 새 지문들이 실제로 서로 결속하는지, 모든 출력이 비어 있는지, 수정 뒤 시험 결과가 어떤지는 별도 정적 동결 검토와 실행 후 증거로 판단해야 한다. 기존 139건 실행 실패는 그대로 유효하며 이 문서는 제품 동작의 결함이나 정상 동작을 판정하지 않는다.
