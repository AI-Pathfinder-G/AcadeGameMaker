# C4 공통 함수 불러오기 인자 보존 초안 검토

검토 대상: `docs/specs/work-contracts/2026-09-30-c4-library-parameter-preservation-draft.md` — SHA-256 `A0B85274AC75C7A46E5354313598727249B2474051AF22B8302C11A38BD86A8C`.

## 판정

초안 설계 검수에서 P0 0건, P1 0건이다. 기존 실행 차단 원인은 실제 호출 구조와 일치하며, 제안한 네 호출자의 인자 보존은 범위가 충분하고 불필요한 호출자까지 확대하지 않는다. 초안은 아직 Draft이며, 구현 승인·재실행·Unity 성공을 의미하지 않는다.

## 호출 범위와 충돌

`c4-verify-required-rows.ps1`의 최상위 매개변수는 `LibraryOnly`, `ExpectedPath`, `XmlPath`, `BeforePath`, `OutputPath`, `RunStem`, `RequiredRowIds`, `PlanPath`, `PlanSha256`이다. `-LibraryOnly`를 점으로 불러오는 현재 호출자는 여섯 곳이다. 실제 호출자 본문에서 매개변수 이름 충돌을 대조한 결과, Queue·Runner·VerifyRun은 각자의 `PlanPath`와 `PlanSha256`을 잃을 수 있고 Capture는 `OutputPath`를 잃을 수 있다. 초안이 지정한 네 호출자와 보존 변수는 이에 정확히 대응한다. 두 선택·행 생성기는 이 아홉 이름 중 사용하는 변수가 없으므로 수정 대상에서 제외하는 것이 맞다. 행 검증기의 일반 실행 경로도 `-LibraryOnly` 불러오기가 아니므로 범위에서 제외된다.

따라서 불러오기 전 값을 별도 변수에 보관하고 불러오기 뒤 원래 호출자 변수를 복구하는 최소 변경은 함수·실행 검증 순서를 바꾸지 않으면서 알려진 덮어쓰기를 막는다. 각 호출자에서 전후 값이 같음을 결정적으로 확인하고 변경 바깥 바이트를 보존한다는 초안의 확인 조건도 적절하다.

## 원장·계획 갱신 경계

v3 원장의 102개 파일을 유지하고 네 도구의 지문만 바꾸며, 허용 변경 근거를 21개에서 25개로 늘리는 방안은 제한 변경과 일치한다. v4 입력 목록 973개는 v3의 971개 경로를 보존하고 v4 원장 및 최종 승인 계약만 추가한다. 계획 v2는 아홉 실행의 순서·선택·행 식별자·시간·출력·잠금을 보존하고, 원장·입력 목록 및 수정된 네 도구 지문만 바꾸도록 제한되어 있다. 계획 v1과 기존 출력은 덮어쓰지 않으며 새 계획을 다시 독립 검수한 뒤 실행한다는 경계도 명확하다.

이 판단은 초안의 계약 설계에 한정된다. 네 도구의 실제 수정 바이트, 신규 v4 원장·입력 목록·계획의 지문 및 규범 적합성은 아직 검토하지 않았고, 재실행도 하지 않았다.
