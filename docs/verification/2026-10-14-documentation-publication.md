# 2026년 10월 14일 문서 게시 범위와 원문 보존

사용자의 문서 정리·산출물 병합·새 세션 프롬프트 요청에 따른 문서 전용 게시 묶음이다. 기준 원격 main은 `d2f49e4a1ed5843ae803d23c328d39f00e51d01f`다. 별도 게시 복제에서 작업하므로 원래 작업공간의 HEAD·인덱스·미게시 게임 산출물을 변경하지 않는다.

## 포함과 보존

현재 운영 모델·Approved 및 검토 단계 명세·결정·승인·실패와 검증 기록·위키 탐색 문서를 정리하고, [최신 인계](../handoffs/2026-10-14-chapter1-session-handoff.md)와 [복사용 프롬프트](../handoffs/2026-10-14-next-session-prompt.md)를 추가한다. 초안과 미완료 상태는 그대로 구분한다. 이번 작업은 게임의 일일 진척 감사가 아니다.

줄바꿈만 다른 기존 89개와 이미 원격에서 로컬 원시 링크를 게시용으로 정리한 역사 문서 12개는 재덮어쓰지 않는다. 정확 선택 경로와 원문/게시 바이트 전이는 [바이트 대조표](2026-10-14-documentation-publication-byte-map.json)에 기록한다. 이 표의 문서별 목록이 게시 선택 범위이며 스스로를 재귀 지문 대상으로 삼지 않는다.

게임 소스·자산·프로젝트 설정·실행 가능한 QA 도구·`output/` 원시·대형 원장·Base64·Library·캐시·실행 파일·로그·개인 프로필은 이번 게시 범위에서 제외한다. 로컬 원시를 삭제하거나 요약으로 대체하지 않는다. 문서 안의 구현 설명은 제품 소스 게시나 실행 권위 발급이 아니다.

## 게시본과 실행 원문

저장소의 기존 `*.md text eol=lf` 규칙에 따라 게시 복제는 LF 열람본으로 만든다. 작업공간 원문은 수정하지 않고 문서별 원문 길이·SHA256과 게시 길이·SHA256을 대조표에 남긴다. 역사 실행 핀을 게시 SHA로 치환하지 않는다. 새 실행에서 게시본을 입력으로 사용하려면 별도 정확 입력 판정이 필요하다.

게시 복제의 탐색 링크만 한정 보정한다. 미게시 원시 링크는 라벨과 원래 경로를 보존한 “로컬 보존 자료” 일반 텍스트로 표시한다. 잘못된 문서 상대경로는 의도한 대상이 유일하게 확인되는 경우에만 고친다. 코드 블록·코드 문자열·실행 인자·규범 경로·역사 SHA는 변환하지 않는다. 코드 구역 밖의 무의미한 줄끝 공백과 EOF 개행을 정리하되 Markdown의 강제 줄바꿈은 역슬래시로 보존한다. 정확 탐색·공백 치환 목록을 대조표에 남기고 LF 변환 및 해당 치환 외 차이가 없는지 확인한다.

## 검증과 수용의 범위

검사는 선택 경로·바이트 전이·상대 문서 링크·민감정보 표식·공백 오류 및 독립 문서 검토에 한정한다. 실제 REQ/AC-C1B-G3OBS-005/006/007/010/012, M1COMP-R1-002/004/006, PROC-011/012의 실행 결과와 한계는 인계와 참여 원장에 그대로 보존한다. 게시 과정에서 Unity·Play·촬영·Q0 운영·새 키·필수 9회 시험을 실행하지 않는다.

기록 관리자 준비5는 국소 검사와 제어 원문 4행 전달까지 확인했으며, 실제 descriptor·플레이·B1 FINAL·CH1 완주는 미완료다. 사용자는 플레이를 연기했고 해당 세션은 종료됐다. 원격 문서 병합을 게임 코드 게시·완주·전체 수용으로 확대하지 않는다. 별도 GitHub 위키 저장소의 게시도 이 묶음의 완료 주장에 포함하지 않는다.

실제 PR·병합 개정은 GitHub 변경 요청과 로컬 게시 영수증에서 확인한다. 이 범위 설명은 아직 발생하지 않은 병합 결과를 소급해 승인하거나 생성하지 않는다.
