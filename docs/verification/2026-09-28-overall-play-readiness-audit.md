# 전체 구현 상태와 플레이 준비도 점검

작성일: 2026-09-28. 총괄: 아스트라. 사용자 요청: 전체 구현 상태 검사와 플레이 예상 시점.

루나(`gpt-5.6-luna`)가 별도의 읽기 전용 감사로 빌드 진입점, 기능 실험장, 런타임 장면 연결 부재, C3 미구현 파일 및 기존 증거의 적용 한계를 독립 확인했다. 이 독립 감사는 새 게임 실행 시험이나 미검증 소스의 수용을 대신하지 않는다. 기간 추정은 아스트라의 판단이며 루나가 검증한 일정이 아니다.

이 문서는 읽기 전용 점검 결과와 일정 추정이며, 명세 승인이나 구현 수용 상태를 변경하지 않는다. 새 Unity 실행·빌드·수동 플레이는 수행하지 않았다. 코드·장면·프리팹·빌드 설정·검증 기록을 대조하고 기존 결과 XML 및 정적 검사 도구를 확인했다.

## 결론

이동·무게 전이·일반 적·오르단 보스·입력·카메라·프로필 저장 기반은 부분 계약별 검증 증거가 있다. 그러나 사용자가 시작해서 원정을 진행하고 성공 또는 실패 뒤 다음 행동으로 이어가는 게임은 아직 완성되지 않았다. 기능 실험 장면의 존재를 사용자용 플레이 가능 상태로 계산하지 않는다.

전체 완료율은 산정하지 않는다. 계약과 검사 수에는 기반 도구·장애 주입·독립 객체 구성이 많이 포함돼 있고, 실제 플레이 콘텐츠 분량을 같은 무게로 나타내지 못한다.

| 배포·본편 | 이전 초기 환경 빌드 존재, 본편 서사 명세는 검토 중 | 현재 게임 빌드·완주·성능 검수; 본편은 별도 콘텐츠 제작 |

## 실제 파일에서 확인한 차단점

1. `ProjectSettings/EditorBuildSettings.asset`의 활성 장면은 `Assets/Scenes/Bootstrap.unity` 하나다. 초기 장면은 카메라와 조명으로 구성되어 있다. 거점·원정·전투의 연속 실행 경로를 현재 빌드 설정이 제공하지 않는다.
2. `Assets/Scenes/MovementSandbox.unity`, `CombatEncounterSandbox.unity`, `OrdanBossEncounterSandbox.unity`는 기능 실험장이다. 오르단 프리팹은 입력 관리자와 카메라를 포함하지만, 해당 그래프와 플레이어 프리팹에는 스프라이트 렌더러가 없다. 장면을 여는 것만으로 시각적으로 플레이 가능한 게임이라고 판단하지 않는다.
3. `Builds/Windows/AcadeGameMaker.exe`의 수정 시각은 2026-08-25다. 현재 기능이 들어 있는 검수된 체험판이라는 증거가 아니다.
4. C3 확인·취소의 두 예정 파일 `ProfileNewGameConfirmationV1.cs`, `NewGameConfirmationOwnerV1.cs`는 점검 시 존재하지 않았다. C4 계약은 검토 상태이며, 그 계약 자체도 성공 후 실제 게임 입력을 활성화하지 않는다.
5. C3 조회 함수의 좁은 사용자 승인은 이미 기록돼 있다. 과거 인계서의 승인 대기를 현재 차단 원인으로 반복하지 않는다. 다만 실행 관리자 현재 지문 `1798F51244FCAFD8EE4B0D847AABBC6DA89EC8EA7138A12826CB37810264DCFB`는 직전 독립 검수 지문 `4CC23B59520FB5C4CF53111758FC6B0A4D7F622B39EABC1CA8FBA2CFE3473DA3`과 다르다. 직전 P1 발견 기록을 현재 코드 결함으로 단정하거나 현재 코드가 통과했다고 선언할 수 없다. 정확한 후속 소스 검수와 회귀가 필요하다.
6. 세령 외형은 기존 감사상 수용 조합 0/432이며, 첫 실제 미디어 패키지도 제작·게시 수용 전이다. 옷장 저장·표시 기반의 통과를 실제 인게임 의상 완료로 확대하지 않는다.

## 검증 근거와 한계

- 이번 정적 카탈로그 검사: 자체 반례 7개, 시나리오 13개, 수용기준 연결 68개 통과. `AC-PLAT-010~012`의 카탈로그 구조 범위에 대한 관찰이며 실제 게임 플레이 통과가 아니다.
- 기존 의상 표시 R15 결과 XML을 직접 읽어 실행 모드 1,142/1,142, 실패·건너뜀·판정 불가 0을 확인했다. 기존 편집 모드 800/800과 함께 `AC-CUA-009` 수용 기록이 있다. 실제 미디어·라이브 장면 검수는 범위 밖이다.
- C2/C2R 독립 수용 기록은 편집 모드 고유 613개와 실행 모드 고유 610개를 명시한다. `AC-M5D7QC2-001~010`, `AC-M5D7QC2R-001~008`은 당시 동결 소스에 대한 수용이다. 후속 수정분에 자동 재사용하지 않는다.
- 보스 입력·카메라·종료의 `AC-M5D1-001~006` 수용은 보스 실험 그래프의 계약 범위다. 데모 전체 완주 수용이 아니다.
- `REQ-SCOPE-001~004` / `AC-SCOPE-001~004`, `REQ-ROOM-001~007` / `AC-ROOM-001~006`, `REQ-CHOICE-001~007` / `AC-CHOICE-001~004`, `AC-PLAT-002`의 통합 플레이 완료를 입증하는 현재 증거는 확인하지 못했다. 검사 목록의 연결 여부와 실제 수용을 구분한다.

## 플레이 시점 추정

아래는 확정 일정이 아닌 낮은 신뢰도의 개발 규모 추정이다. 2026-09-28 이후 매일 집중 개발하고, 승인·독립 검수 흐름을 유지하며, 큰 범위 변경과 인증·도구 장애가 없다는 전제다. 기존 작업 속도를 정량 측정한 일정은 아니다.

| 목표 | 예상 개발 기간 | 조건 |
|---|---|---|
| 짧은 이동·전투 체험판 | 약 1~2주 | 한 방·한 보스, 화면 표현·체력·입력 안내·재시도·실행 파일을 우선하는 별도 승인 계약 필요 |
| 현재 승인된 약 15분 데모 | 약 4~8주 이상 | 거점, 여섯 방 풀과 런당 네 방, 실패 복귀, 두 선택 기술, 종료 장면과 통합 검수 포함 |
| 여덟 챕터 본편 | 현재 날짜 추정 불가 | 본편 명세 승인, 장별 맵·보스·서사·미술 제작량과 일정 산정부터 필요 |

짧은 체험판을 우선하려면 기존 15분 데모 기준을 몰래 축소하지 않고 별도 목표와 수용기준을 승인해야 한다. 현재 작업 순서대로 새 게임 안전장치와 전체 데모를 계속 완성하는 경우, 짧은 체험판 추정은 적용하지 않는다.
