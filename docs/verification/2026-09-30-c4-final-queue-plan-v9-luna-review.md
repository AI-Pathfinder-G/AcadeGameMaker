v8과 비교해 전역 소스·입력 지문 및 큐 도구 지문이 갱신됐다. 첫 실행은 새 stem `c4-r7-focused-edit`와 출력 경로를 쓰며, 선택 v5와 139개 이름은 유지한다. 두 번째는 선택 v4와 `c4-r2-focused-play` 새 stem·출력 경로를 쓴다. 남은 일곱 실행은 계획 객체 전체가 v8과 같다. 아홉 실행의 이름 수는 각각 139, 32, 5, 91, 149, 15, 562, 51, 610이며 stem 중복은 없다.

72개 실행 출력 경로는 모두 고유하고 현재 존재하지 않는다. 큐 결과 `artifacts/c4-final-validation-queue-result-v8.json`도 없다. 각 실행에는 원시 종료 관찰, QA 반환, 검증 결과, 행 비교를 별도 저장할 경로가 있어 R3 진단에서 남았던 QA·바깥 반환 증거 공백을 해결하는 구조다. 최대 기록 명령행 길이는 24,161자로 32,767자 한도 이하다. 모든 실행의 사례 제한은 180초, 관찰 제한은 21,600초이며, 단일 프로젝트 상호 배제 잠금과 실패 시 중단 정책이 유지된다. 행 원장은 188행 그대로이며 v9 계획의 행 원장 결속과 실제 파일 지문이 일치한다.

선택 9개 파일의 지문·이름 수·이름 배열·선택식은 계획 값과 일치하고, 각 선택의 `SourceFiles` 실제 지문도 현재 파일과 일치한다. 다만 새 focused Play 선택 v4의 Bridge 열거형 지문은 현재 소스와 일치하는 반면, 첫 focused Edit 선택 v5와 focused Hub 선택 v2의 `ParserEvidence.EnumSources`에는 Bridge의 이전 SHA `04709FA5E07A1417FF1BFF5D7829441C7C990F35B3896184C2BCC68A2CBF46BB`가 남아 있다. 현재 Bridge 실제 SHA는 `52E00FE10FDEAFB8C192CF7F92B2EA428C16A202D640BEAF79C8F58E6704F32A`다. 검증 도구의 `C4-Selection`은 모든 `SourceFiles`와 `ParserEvidence.EnumSources`에 대해 각각 실제 SHA 결속을 검사한다. 따라서 이 두 선택은 해당 검증 단계에서 거부될 것이며, 관련 실행은 현재 계획으로 시작하지 않아야 한다. 선택 파일 지문은 원장·입력에 고정되어 있으므로 승인된 범위에서 선택을 재생성하고 선택·원장·입력·계획 결속을 함께 새로 발급해야 한다. v9이나 기존 선택 파일을 직접 고치면 안 된다.
