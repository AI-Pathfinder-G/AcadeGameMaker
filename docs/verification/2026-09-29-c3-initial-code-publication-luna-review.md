## 판정과 게시 계약 전 차단사항

**P0 0건, P1 5개 차단 묶음.** 후보와 설명은 미승인·미검증 상태를 정직하게 드러내는 읽기 전용 게시 준비물이다. 다만 승인 가능한 초기 게시 계약으로 확정하기 전 아래 항목을 닫아야 한다.

1. **파일별 승인 범위:** 489개 각각에 실제 Approved 허용 목록 문맥, 기존 REQ/AC, 후속 결정, 현재 바이트 SHA, meta GUID/조립 소속을 연결한다. 300개 citation 후보도 권한으로 간주하지 말고, 189개 출처 미입증 항목은 승인 경로를 찾거나 게시 후보에서 별도 격리한다. 설정·meta·AssemblyInfo/friend 파일도 같은 기준으로 판단한다.
2. **Q0 첫 게시 전제:** 기존 시험·선택·역사를 바꾸지 않는 별도 계약으로, manifest가 검사하는 실제 Git delta와 깨끗한 최초 게시 기준의 관계를 규정한다. 시험을 수정해야 한다면 별도 승인 후속이 필요하다. 현재 문서가 이 모순을 실제 재현 또는 해결했다고 기록해서는 안 된다.
3. **누락된 도구 입력 7개:** 각 경로가 원격 기반에 이미 존재하는지, 게시에 포함할지, 승인된 재생성 절차가 있는지를 증거로 닫는다. 도구 본체 13개를 후보에 넣은 사실만으로 입력 폐쇄를 주장할 수 없다.
4. **Renderer2D GUID 7개:** 정확한 Unity/패키지 버전에서 엔진 내장·직렬화 출처와 실제 import 진단을 대조한다. 판정 전에 자산 삭제·재생성·수정은 하지 않는다.
5. **최소 설정과 기반 동결:** 10개 설정 후보의 정확 allowlist 및 파일별 기존 승인 연결을 확정하고 환경 종속 값을 검토한다. 원격 기준은 새 확인 없이 고정된 전제로 취급하지 않으며, 모든 후보 지문·줄바꿈·meta와 Q0 pin의 실제 바이트를 게시 직전에 다시 확인한다.

따라서 이 문서는 제안의 **범위 투명성 검수**이며, 완결된 게시 allowlist·깨끗한 checkout 재현·원격 상태 확인·바이트 승인·게시 승인으로 확대할 수 없다. 다음 산출물은 위 차단을 행별로 닫은 뒤 Astra가 승인 검토할 정확한 파일 목록과 재현 계약이다.
