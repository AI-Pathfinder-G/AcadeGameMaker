## 남은 작업 단계

1. **설계 경계 확정**: Sol이 단독 Driver의 정확 자기 Pilot 인계·세션 철회·증거 종류·Source 대응을 닫고 Luna 반례를 받은 뒤 Astra가 정확4파일·32사례 및 실행 범위를 판단한다. 현재 제안은 미승인이며 임의 구현 선행은 없다.
2. **플랫폼별 검사 설계 보완**: 12×두 소유종류의24와 단독8은 순수 사례 계획이다. Editor/개발 실행을 거절하는 실제 단독 양성 경로를 Editor 순수 검사만으로 증명할 수 없다. 상태 검증과 실제 비개발 Windows의 인계·소비 양성을 분리하고 실제 검사 위치·조립체·빌드 조건을 정해야 한다. 제안32의 실행 가능성과 실제 양성 관측은 아직 미검증이다.
3. **승인 범위 보정·정확 컴파일**: 새 단독 소유 경로를 승인된 파일에 구현하고 Input/Run 및 두 시험 조립체의 입력·계보를 새 Source에 결속한다. 기존 Csc2를 추가 모듈이나 Unity 컴파일 증거로 재사용하지 않는다.
4. **집중·복구·통합 검사**: 새 순수 검사→복구2→통합1의 정확 유한 승인 아래 실행한다. 기존 시간5 재사용은 직접 불변·Luna 영향 검수 조건을 따른다. I2 정책 거절의 새 관측 목적이 성립하기 전 무변경 반복하지 않는다.
5. **현재 소스 최종 빌드·동일 빌드 검증**: 필수 회귀를 확인한 새 소스로 Windows 실행파일·압축본·지문을 만든 뒤, 그 동일한 비개발 빌드에서 양분기의 소유 인계·소비·피해/종결과 기본 비활성·실패재시도 불변을 실제 검증한다. 빌드 전 동일 빌드 양성 관측을 선행으로 요구하지 않는다. r14를 최신 소스 결과물로 표시하지 않는다.
6. **독립 전달 수용**: 같은 최종 빌드의 시작·조작·실제 화면·양분기 종결·실패/복귀/재출정·저장·정상 종료를 Luna가 묶음 검수하고 Astra가 통합 판단한다. 한글 조작·저장·재시도 안내와 제한을 함께 전달한다. 사용자 중간 재생·입력·경로 확인을 새 선행으로 만들지 않는다.
7. **후속 제작**: CH1 최종 아트·동작·배경·효과·음향과 본편 상세 제작 분모를 정리하고 CH2~8의 승인된 전용 계약·소스·장면·서사 제작을 진행한다. 후속 전체 구현을 CH1 전달 선행으로 확대하지 않는다.

## 미진한 부분

- 가장 가까운 제품 병목은 단독 실행 소유 자료가 없는 현재 계속 점프 보정과 실제 보스 정책 거절이다. 국소 컴파일·시험용 합성 성공만으로 해결되지 않았다.
- 최신 제품·시험 소스와 사용자 실행파일의 세대가 다르다. 과거 자동 성공과 현재 미실행을 한 결과로 섞으면 안 된다.
- 전체 CH1 실제 창·양분기·실패 재시도의 최종 독립 수용이 없다. 자동·실제 화면·물리 입력·인간 체험 증거는 각각 따로 유지해야 한다.
- 아트는 패키지25점 단계다. 최종 인물 동작·적/보스 패턴·환경·효과·의상 실착용의 제작·수용 공백과 음향 분모 공백이 남아 있다.
- 공통47행은 오래된 보조 지표이며 최신 바이트의 완료율로 사용하기 어렵다. 전체8챕터 상세 제작량 분모와 후속 전용 구현이 부족하다.
- 준비 문서·도구 성과가 늘었지만 고정 패키지는 상위 단계의 연속 조건을 아직 채우지 못했다. 점수 유지가 작업 부재라는 뜻은 아니다.
- 사용자 보안창 자체는 제품 잔여 이슈에서 제외한다. 이번 외부 지원 전송0이며 보안·인증·권한 대리 조작을 해법에 포함하지 않는다.
