### 소스·Unity 작업 증거

10월 11~13일의 연속 체크포인트(v10~v14)는 기본 이동 관측기와 Editor 증거 창을 반복 보정했다. 최신 v14 체크포인트（`../../../output/chapter1-playable-r1/evidence/b1-final-source-checkpoint-sol61.v14.json`；로컬 보존 자료）는 제품 후보 590개를 고정하고, 직전 개정 대비 정확히 `Chapter1BasicMovementEvidenceWindow.cs` 1개 변경을 기록한다. 해당 개정에서 컴파일 실행 0, Unity 실행 0, 실제 플레이 0, GUI 조작 0, 독립 수용 0이다.

오늘 새벽의 Unity 실제 관측 원장에는 프로젝트 창과 `AcadeGameMaker/Chapter1/Basic Movement Evidence` 메뉴, `R01-A` 관측 창이 열린 기록이 있다. 관측 창의 버튼 입력은 없고 장면은 로드되지 않았으며 `SourceReady=false`, Play 0회, 캡처 0회다. 이 Unity 프로세스는 이후 STOP 경계에서 종료·핸들 폐쇄됐다고 기록됐다. 이는 초기화와 도구 창 확인이지 플레이 가능 증거가 아니다. 근거는 기본 이동 실행 원장（`../../../output/chapter1-playable-r1/evidence/b1-basic-movement-minimal-compile-work-ledger-root.v1.json`；로컬 보존 자료）의 `unityVisibleOwnedStartActualExecution4`, `unityBasicMovementWindowRead1`, `unityOwnedManager4ClosureAndOutputRisk1` 항목이다.

원장은 TTY 행/줄바꿈의 전송 동일성을 확인하지 못해 정리 후 종료했고, 기존 실행을 반복하지 않도록 기록한다. 그 뒤 도구 메모리 컴파일(Add-Type)은 성공했지만 Unity 프로젝트 소스의 컴파일 성공으로 볼 수 없다. 10월 14일 승인된 최신 M1 호환 부록은 정해진 입력으로 가시 초기화를 한 번 더 관측하도록 허가했으나, 이 감사 시각까지 새 시작 실행 결과는 원장에 없다. 계약은 [M1 제한 개발 호환 부록](../../specs/work-contracts/2026-10-08-m1-bounded-development-compatibility.md)이다.

오디오·영상 파일은 현재 자산 폴더에 존재하지만 확인한 파일의 최근 수정 시각은 9월 8일 이전이다. 이번 관측에서 새 제작 또는 Unity 장면에 연결된 수용 증거는 발견되지 않아 챕터 아트 패키지 점수를 올리지 않았다.

## 현재 작업, 병목 및 다음 전달물

- 실제 주력은 CH1 실제 플레이 자체가 아니라 기본 이동 관측기를 Unity 작업 흐름에 넣기 위한 M1 실행·관측 경로를 마무리하는 단계다. 코드 수정은 있으나 제품 동작의 변화는 아직 독립 검수되지 않았다.
- 병목은 도구/실행 경로의 반복 호환 문제다. 원장의 실패 이력에는 Add-Type 호환 문제, Unity 입력 연결의 즉시 EOF, IPC 초기화 오류, TTY 줄바꿈/출력 동일성 문제가 순차적으로 기록돼 있다. 이 때문에 여러 번의 실행 준비·호환 부록·관측 수집이 생겼지만, 그 기간에 실제 CH1 플레이는 시작되지 않았다.
- 다음 전달물은 현재 승인 범위의 새 초기화 단회 결과를 받아 Unity 프로젝트가 안정적으로 준비되는지 확인하는 것이다. 성공해도 이후에는 방별 기본 이동, 독립 수용, 묶음 검사, 실제 시작·조작·결과·재시도, 현재 소스 빌드가 남는다. 계약에 없는 버튼 입력·Play·새 실행 반복을 이번 감사가 승인하지 않는다.
- 과정 개선은 도구 상태 확인과 게임 진척을 분리해서 보고하고, 동일 전송/초기화 실패를 다시 만나면 큰 실행을 재개하기 전에 새 실패의 원시 증거와 달라진 원인을 먼저 확정하는 것이다. 승인된 기능 묶음 안의 충돌 없는 제품 설계·아트 연결 작업은 실행 경로 대기와 구별해 이어가야 한다.
