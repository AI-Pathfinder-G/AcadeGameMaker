# C4 legacy 행 출력 분기 R2 후속 검토

검토 대상은 `docs/specs/work-contracts/2026-09-29-c4-legacy-row-output-amendment.md` SHA-256 `A66C6EF7B5368FBD7B1995328268E2601FA10B14E8D90F3515C219B60568FD80`이다. 이전 검토는 초안 SHA `9F0D047312A3194941FC2317092190E3AA2B667573ED99A12F4C33CEB57A840C`를 대상으로 했다.

R2는 240 전체 이름 배열과 Matrix91/Remaining149 각각의 원본 순서를 별도로 보존하고, 두 분할의 이름 집합이 서로소이며 합집합이 전체240과 정확히 같은 조건을 명시했다. 부분 배열의 이어붙인 순서가 전체 배열과 같아야 한다고 요구하지 않고, 계획의 Runs 실행 순서를 별도로 고정한다고 적었다. 이는 원본 전체/부분 선택에서 확인된 순서가 서로 일치하지 않는 사실을 반영한다. 따라서 이전 분기 초안에 대한 배열 순서 우려는 닫혔다. 예상 legacy 원장과 validator의 SHA 및 `OutputPaths.RequiredRowComparison` 단일 슬롯·legacy writer 조건은 R1에서 확인한 것과 동일하다.

그러나 이전 검토의 규범 연결 P1은 남아 있다. Approved QA R2에서 `RequiredRowComparison` 및 행 비교 결과를 C4 형식으로 정의했는데, R2 초안은 Matrix91에 동일 경로로 legacy JSON을 기록하는 예외를 추가하면서 QA R2 조항의 승인된 한정 개정 또는 명시적 보완 관계를 아직 규정하지 않았다. 그 연결을 문서상 닫기 전에는 두 소유 규격을 함께 적용할 때 결과 형식이 모호하다.

판정: 이번 수정으로 배열 분할·순서 P1은 폐쇄 가능하며, legacy 출력의 규범 스키마 연결 P1은 미해결이다. P0 0, P1 1. 이 검토는 정적 텍스트 대조이며 구현, 도구 호출, C4 실행 또는 수용을 확인하지 않는다. 소스·QA·Unity·Git을 수정하거나 실행하지 않았다.

## 정확 지문 후속 폐쇄 검토

최신 초안 SHA-256 `5E80F4B0513F07624A3B28C8E960A2D23DB9226474D31C086D170BA477E89062`를 추가 대조했다. 초안은 Approved 전환 시 QA R2의 `RequiredRowComparison` 형식 및 verify-run 적용 규칙을 Matrix91에 한해서 개정하고, 그 분기만 이 문서의 legacy 형식을 우선 적용한다고 명시한다. 다른 실행과 새 C4 행에는 QA R2를 그대로 적용하며 Draft 상태에서는 현재 QA R2를 대체하지 않는다는 점도 고정한다. 따라서 앞서 남긴 규범 연결 P1은 이 정확 지문에서 폐쇄 가능하다. R1의 377원장과 validator SHA는 재조회 결과 각각 `D1B9CBDA4AF477B5C10FC14893F0C58B2BAE676A38E15987C87B7D918658C9C6`, `7BB2CC75B09979E77DE883EB495DCBE29780337861D7F37883F9EFB732CE27E2`로 유지된다.

최신 지문에서 배열도 별도로 재확인했다. 전체 240과 Matrix91/Remaining149 각 배열의 자기 원본 순서를 보존하고 서로소 집합의 합집합만 전체와 같게 요구하므로 부분 배열 연결 순서 불일치도 정확히 처리한다. 이에 따라 해당 R2 설계 검수의 최종 정적 판정은 P0 0, P1 0이다. 이는 Draft의 승인이나 분기 구현·실행 완료를 의미하지 않는다. 원문 검토 기록은 보존하며 이 절만 후속 판정으로 추가했다.
