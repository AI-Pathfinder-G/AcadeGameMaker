상태: 테라의 키 없는 준비 증거를 원시 자료에서 재발급했다. 루나의 독립 파일 검수와 아스트라의 한정 수용은 별도 단계다. 적용 요구사항은 `REQ-PLAT-061/062/068/069/070`, 이번 정밀도·결속 검증 기준은 `AC-PLAT-059/060/066/067/068`이다. 승인 보정 계약 `docs/specs/work-contracts/2026-10-03-q0-evidence-int64-precision-correction.md`의 SHA는 `5787810A884ED916BDD2ED2DDFE2814A5B88656AD67D45F3B6E473028D6C07F2`이다.

## 결과와 원시 결속

새 파일은 검사한 메모리 후보와 바이트가 동일하게 각각 한 번 생성되었다.

유니티 v2는 1~4차 영수증을 각각 원문 파일에서 직접 다시 읽어 원시 SHA와 Base64를 결속했다. 큰 정수 일곱 개는 1차 `639265460748965343` 두 곳, 2차 `639265467445018083` 두 곳, 3차 `639265542226848562` 한 곳, 4차 `639265547678170929` 두 곳이다. 각 영수증의 `UnityStartTicks`와 원문 `UnityStartUtc`를 일치 확인했다. 3차는 제한 권한 환경에서 패키지 관리자 IPC 연결 실패로 종료 1·지원 메서드 미관측이었고, 4차는 현재 C# 바이트를 정상 권한에서 실행하여 종료 0·파이프 피어 결속·공개벡터 4개·공유 순번 집합 1..4 및 최종 4·보호 501개 전후 불변이었다. 1차와 2차는 이전 C# 바이트의 역사로만 남긴다. 성공한 4차도 XML을 생성하지 않았고 아홉 운영 선택의 실행 결과는 아니다.

채널·유니티·준비 후보의 모든 중첩 JSON 숫자 토큰 각각 17·77·603개를 엄격 UTF-8, 중복키, 정수 문법, Int64 범위와 십진 원문 왕복으로 검사했다. 원문 수집기와 내장 객체, 네 원문 영수증과 내장 객체의 숫자 경로·값을 전수 비교하여 차이 0이었다. 주 조정자와 루나는 파일 생성 전 읽기 전용 메모리 채널에서 세 후보의 실제 원시 바이트·SHA 및 큰 정수와 준비 결속을 별도로 검사했다. 보유 서버는 세 파일 발급 뒤 정확 소유 종료를 관측했다. 시험이나 유니티 실행을 새로 반복하지 않았다.

준비 v2의 `PrePublicSourceRows` 570개는 현재 준비 복제의 원시 길이·SHA와 모두 일치했고 누락·중복·불일치가 0이었다. 주 조정자가 4차 유니티 전후 570개를 실제 읽어 길이·SHA 변경 0이라고 보고한 시각은 준비 문서에서 **주 조정자 보고 증언**으로 구분했다. 별도 원시 전후 파일이나 아스트라 직접 시행으로 소급하지 않았다. 공개 검증기의 네 리터럴은 모두 `UNISSUED`다. 준비 v2가 위 채널·유니티 v2의 발급 원시 SHA를 결속한다. 향후 계획의 `CurrentPreparationEvidence`는 정확 두 역할, `Preparation`→`preparation-v2.json` 및 `NegativeTests`→`channel-tests-v2.json`을 사용해야 한다.

## 실패 역사와 남은 범위

JavaScript 숫자 변환이 채널 원문 ticks `639265539138890254`를 `639265539138890200`으로 바꾸고 유니티 일곱 중첩 ticks를 반올림한 첫 공통 파일 네 개는 수정하지 않았다. 채널 v1 SHA `D6510D6FC966FAAA10720DA6F461AD474F6EB201D89B7D288D6AFF78C753DD3C`, 유니티 v1 `84DBCAD74D63EBFB357C37879389F025CE13E7C02DEBB324817381A9C764C333`, 준비 v1 `5EFEA79F4E89652429CD24F1FDA42203D1D1DF5426DEE95323F4A4E6A16BD618`, 테라 보고 v1 `58B9EAE569EBD4131077FA55516672B92733B52086CDE60C1597B0CF595C423D`는 `FailPrecisionSources`로 보존한다. 첫 보고의 P0/P1=0 주장은 정밀도 결함 발견 전의 자체 주장으로만 남는다. 이번 보정의 자료 정합성은 검사했지만 독립 수용 전까지 P1의 최종 폐쇄를 자인하지 않는다.

기존 키 없는 채널 71건, 합성 호스트 6건·상위 사망 1건, 합성 Git 571 추적 파일 관문 5건, QA 편집기 소유 기능 회귀 104건은 각각 증거에 결속한 당시 범위다. QA 104건은 성공 운영 표준출력의 단일 JSON이나 진단 표준오류 분리를 검증하지 않았다. 실제 서명된 계획·인증된 외부 권위·현재 HEAD/트리·실행 소비·아홉 선택의 XML/로그/종료·188/377행은 아직 관측되지 않았다. `OperationalKeyCreated`, `OperationalAuthorityUsed`, `WholeAccepted`, `PublicationApproved`는 모두 거짓이다. 공개키 치환 후에만 최종 현재 소스·입력·선택·행 원장과 `source-freeze`를 생성할 수 있다. 이 보고는 테라 구현의 독립 수용을 대신하지 않는다.
