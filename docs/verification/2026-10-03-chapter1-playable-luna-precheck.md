# Chapter 1 실제 플레이 사전검토

- 검토자: Luna (`gpt-6-luna`)
- 기준일: 2026-10-03
- 상태: 독립 사전검토. 제품 계약 승인, 구현 수용, 실제 플레이 검증이 아니다.
- 목적: 승인된 게임 규범과 검토 중인 전체 서사 규범을 분리하고, Chapter 1을 처음부터 끝까지 플레이할 제품 계약에 필요한 범위와 검증 경계를 제시한다.

## 판정 요약

Chapter 1 완주는 단일 오르단 보스전, 로컬 첫 연결 구간, 또는 VD-00 수직 데모 완료로 대체할 수 없다. 캐논은 유담·오르단의 갈등과 첫 인간성 선택, 세령의 추적자 첫 등장 및 아인을 찾으려는 협력을 고정하지만, 현재 전체 서사 계약 NAR-00은 Review이고 Chapter 1의 정확한 필수 사건 목록·종료 이벤트·선택 결과 저장 경계는 제품 수준으로 확정되지 않았다. 구현 전에 Astra가 Chapter 1 시작/필수 진행/두 선택 경로/실패 후 복구/종료 상태를 테스트 가능한 계약으로 고정하고, Terra가 실제 씬·입력·에셋·저장 의존을 조사해야 한다.

다음 검토는 위 항목을 계약 초안에서 확인한다. 본 문서는 승인된 동작을 새로 만들거나 구현을 허가하지 않는다.

## Chapter 1 완주 계약에 필요한 후보 요소

아래는 새 계약에서 명시해야 할 검사 항목이다. 완료 조건의 최종 내용은 Astra의 승인 계약이 정하며, 이 표 자체는 제품 규범이 아니다.

1. **진입과 시작 상태:** 새 실행에서 Chapter 1의 지정 시작점과 조작 가능한 장면에 도달하고, 필요한 안내·플레이어·충돌 세계·HUD·입력이 실제 생산 경로로 초기화된다. 정확한 시작 씬과 상태 소유자는 실제 의존 조사로 고정한다.
2. **필수 진행 연결:** 계약이 지정한 Chapter 1의 도입, 이동/탐색, 필수 대화·사건, 전투 및 다음 구간이 끊김 없이 연결되고, 필수 목표·진행 표시가 플레이어에게 판독 가능하다. 제안서의 상세 시놉시스를 승인된 사건 목록처럼 사용하지 않는다.
3. **오르단 갈등과 플레이:** 캐논상 오르단의 ‘질서’ 명분과 유담의 주체성 갈등이 전달되고, 보스전이 플레이어 입력에 반응한다. 기존 보스 그래프를 재사용하는 경우 VD-03의 피해·공격·패턴 계약과 관련 AC를 보존한다. 보스 1회 승리만으로 챕터 완료를 주장하지 않는다.
4. **유담의 두 선택:** 선택지가 각각 의미 있는 완주 경로이며, 추출/연대의 차이가 승인된 결과·기술·후속 상태로 추적된다. VD-06을 재사용하면 유담의 동의 범위, 양 선택 경로, 기술 획득·봉쇄선 및 수직 데모에서 정의된 세령 등장 순서를 지킨다. Chapter 1의 추가 결말 상태는 별도 승인 없이 추정하지 않는다.
5. **실패·재시도·상태 보존:** 사망/실패 지점과 허용된 재시도 방식, 임시 상태 초기화, 선택·영구 진행의 보존 범위를 명시한다. 두 분기 각각의 완료 가능성, 실패 후 재시도, 중복 이벤트·건너뛴 단계·선택 초기화가 없는지 확인한다. 기존 VD-05의 런 단위 규칙은 재사용 범위에서 유지하되, 챕터 영속성은 새 계약으로 확정한다.
6. **세령과 Chapter 1 종료:** 세령은 보상이나 자동 면책 장치가 아니라 캐논에 정한 추적자/협력자 역할로 등장한다. 아인을 찾으려는 목표와 약속은 실제 전달된 대화·행동으로 확인한다. Chapter 1 종료 이벤트, 명확한 완료 표시, 다음 장 진입 자격 또는 저장 상태를 계약에서 지정해야 한다. Chapter 2 플레이를 CH1 완료의 자동 선행조건으로 추가하지 않는다.
7. **표현과 접근성:** 승인된 아트만 사용하고, 플레이어·적·위험·전이 대상·선택 UI를 구분할 수 있어야 한다. VD-07/08을 쓰는 영역에서는 입력 모드, 상태 피드백, 대비·실루엣·레이아웃과 승인된 에셋/라이선스를 확인한다. 검수되지 않은 시안이나 임시 도형을 완성 외형으로 부르지 않는다.
8. **실행 가능한 인계:** 정확한 소스·씬·설정이 포함된 현재 빌드 지문, 실행 안내, 오류 로그, 분기·실패별 증거를 남긴다. 실제 키보드/마우스 입력으로 처음부터 CH1 종료까지 플레이한 독립 증거가 있어야 한다.

## 누락·과장 위험

- **범위 축소:** 단일 오르단 보스/첫 이동 구간/LPS 성공·실패·재시도는 기반 단계일 뿐이다. 전략 문서도 이후 CH1 전달에 도입·원정·유담 선택·기술·봉쇄선·세령·종료를 적고 있다.
- **데모 결과를 챕터 종료로 오인:** VD-00의 `DemoCompleted` 또는 수직 데모 성공 후 세령 장면을 CH1 완료로 재사용하면, 실제 챕터 진행과 종료가 검증되지 않는다.
- **분기 하나만 검증:** 연대 선택만 성공하거나 추출 경로만 완주하는 경우, 유효한 두 선택 경로라는 VD-06/NAR-00 기대를 충족하지 못한다.
- **선택의 표면화:** 선택 UI만 나타나고 당사자 동의, 결과, 저장된 상태, 후속 장면이 바뀌지 않으면 선택·주체성 계약을 입증하지 않는다.
- **서사 범위 과잉 확정:** 제안서의 Chapter 1 세부 비트나 NAR-00 Review의 미결정된 혼합 경로·저장 규칙·관계 상태를 승인된 사실로 가져오지 않는다.
- **시각·기술 데모를 실제 플레이로 대체:** 자동 완주, 포커스 테스트, `ForTests`, 피해 주입은 장치 입력 플레이의 증거가 아니다. 반대로 도구 종류만으로 플레이 검증이 불가능하다고 결론 내릴 수도 없다.
- **옛 감사 수치의 현재화:** 감사03의 날짜 기준 결과는 현재 실행 상태가 아니다. Terra의 새 영향 조사로 실제 파일·씬·의존과 빌드 가능 여부를 확인한다.

## 검증 설계와 증거

### 실제 플레이

검수 대상은 원본 Unity 편집기 창이 아니라 정확한 빌드에서 생성된 새 실행 파일 창이어야 한다. Root가 확인한 컴퓨터 사용 경로는 창 목록 조회까지 성공했으나, 아직 새 창 선택·활성화·입력·게임 실행은 없었다. 따라서 이는 검증 수단의 가용성 확인일 뿐 AC 통과가 아니다. 실제 검수 배정 시 해당 도구 안내를 다시 읽고, 새 실행 창의 상태를 관측한 다음 한 번의 입력을 수행하고 화면을 갱신하는 순서로 진행한다. 입력 조작·화면·게임 이벤트를 연결해 기록하고, 처음 실행부터 두 선택 경로, 실패/재시도, 종료 표시까지 필요한 범위를 증명한다.

연속 또는 시각이 연결되는 화면 기록, 정확한 빌드·소스 지문, 입력 순서, 화면 결과, 예외/로그, 선택·프로필 전후 상태를 함께 보존한다. 각 장면을 건너뛰지 않았음을 확인할 수 있는 이벤트/상태 증거를 화면 기록과 결속한다. 자동화 검사는 재현 가능한 회귀의 보조 증거이며, 사람의 실제 입력과 반응성 확인을 대체하지 않는다.

### 기존 AC 회귀

새 계약은 변경 그래프에 따라 필수 회귀를 고정해야 한다. 특히 재사용되는 영역의 기존 추적성은 적어도 다음을 검토한다.

| 영향 경계 | 승인된 기준 예시 | CH1 검수 시 확인 |
|---|---|---|
| 이동·대시·조준·카메라 | VD-01 `REQ-MOV-001..010`, `AC-MOV-001..006`; VD-08 `REQ-ART-011`, `AC-ART-008` | 입력 경계·틱 결정성·화면 판독이 현재 씬/빌드에서 유지되는지 |
| 무게 전이·대상 소유 | VD-02 `REQ-WT-001..008`, `AC-WT-001..006` | 선택 대상·사거리/시야·단일 활성 대상·정리 및 결과 피드백 |
| 일반 적·오르단 전투 | VD-03 `REQ-COM-001..006`, `AC-COM-001..004` | 실제 공격/피격/보스 전환, 기존 수치·패턴 경계 |
| 방·런·실패 상태 | VD-04 `REQ-ROOM-001..007`, `AC-ROOM-001..006`; VD-05 `REQ-RUN-001..006`, `AC-RUN-001..004` | 사용되는 방/전환만 검사하고 사망·재시도 후 오래된 상태·콜백이 없는지 |
| 선택·서사 후속 | VD-06 `REQ-CHOICE-001..007`, `AC-CHOICE-001..004`; NAR-00 `REQ-NAR-002..006`, `AC-NAR-002..005` | 각 선택의 유효 완주·당사자 주체성·세령 순서·상태 반영 |
| 입력·UI·표현·빌드 | VD-07 `REQ-UX-001..014`, `AC-UX-001..013`; VD-08 `REQ-ART-001..015`, `AC-ART-001..012`; VD-09/10 플랫폼·검증 AC | 실제 사용 입력맵, 한글·상태 피드백·권리·씬 설정·현재 소스 빌드와 검사 결과 |

표는 모든 AC를 자동으로 CH1 적용한다고 선언하지 않는다. Terra의 영향표가 사용·변경 경로를 특정하고, 해당 기존 필수 검사를 유지하거나 “해당 없음” 근거를 남겨야 한다. VD-10의 성공/실패 경로, 결정성·프로필 회복 및 초회 플레이어 측정 기준은 수직 데모에 대해 승인되어 있으므로, CH1 제품 계약에서 재사용 범위와 별도 CH1 종료/분기/완주 증거를 구분한다.

## 계약 초안 사전검토 체크리스트

- 정확한 CH1 시작·완료 이벤트와 필수 구간이 승인 캐논 및 VD-06의 첫 등장 계약을 보존하는가?
- 완주를 단일 전투나 데모 종료로 축소하지 않고, chapter state와 완료 증거가 명시되어 있는가?
- 추출/연대 양쪽의 플레이 가능 경로, 후속 상태, 실패·재시도·저장 규칙이 명시되어 있는가?
- 제안서·Review 문서에서 가져온 새 서사 결정이 승인 사실과 구분되어 있는가?
- 실제 씬·입력·저장·미디어·패키지 의존과 소유자가 읽기 전용 조사로 확인되었는가?

- 이 사전검토는 제품 코드를 복제·수정하거나 Unity/빌드/실제 플레이를 실행하지 않았다. §10.1 세 원장과 보충 원장의 입력 지문은 확인했지만 제품 API 전체의 실행 호환성, Unity 가져오기 성공, 테스트 발견 수, 실제 사용자 입력 성공은 아직 검증하지 않았다. Astra의 제한된 단계 승인 뒤 소스 사전 대조, 유한 가져오기·컴파일, 선택된 필수/집중 회귀와 독립 플레이가 각각 별도 관문이다. CH1 완주와 단일 오르단 전투/첫 로컬 구간도 계속 구별한다.
