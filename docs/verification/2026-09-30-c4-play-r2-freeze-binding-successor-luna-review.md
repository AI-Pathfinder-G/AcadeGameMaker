# C4 Play R2 동결 후속 결속안 독립 설계 검토

검토 대상 제안 SHA-256 `4C9A0901B2D6CA9B9F4F30B2DD68FE57E215271910538A5F2AE7BE7EE7D4EC0F`와 현재 승인 계약 `docs/specs/work-contracts/2026-09-30-c4-play-r2-current-source-pin-amendment.md` SHA-256 `0DA1251B97D1A2E763B3A878110077C5FB5EB3E43565DA72C99A9D949D72EF1B`를 대조했다. 이 검토는 설계 단계이며 코드·원장·실행 결과를 수정하지 않았다.

제안은 v3 선택 파일의 Bridge `ParserEvidence.EnumSources`가 구 SHA를 가진 문제를 정확히 다룬다. `C4-Selection` 검증기가 `ParserEvidence.EnumSources` 각 파일에 실제 입력 스냅샷 결속 검사를 적용하므로, v3을 현행 Bridge가 반영된 실행에서 그대로 사용하면 불일치로 거부된다. v4를 기존 제한 선택 도구로 재생성하고 v3과 전체 구조를 비교하여 Bridge SHA 한 필드만 달라지는지 확인하며, 32개 이름·순서·선택식·부모 지문 등 나머지를 동일하게 요구하는 보정은 범위가 적절하다.

기존 승인 계약을 새 승인으로 바꾸지 않고, 선택 v3·원장 v12·입력 v12를 보존한다. 새 source manifest v13은 Edit fixture의 낡은 `ChangeAuthority`만 바로잡고, 선택 v4·역사 원장 v12·새 설계 제안·이 독립 검토·후속 Approved 계약을 각각 별도 Evidence로 결속한다. input v13도 이전 경로·사유를 보존하면서 동일 세 문서와 선택 v4·manifest v13을 직접 입력으로 추가하도록 명시한다. 새 실행 계획은 v13 원장/입력과 v4 선택의 실제 SHA를 사용한다. Runtime, 부모, 제품 동작, QA 규칙, 188개 행을 수정하지 않는다.

## 판정

P0 0건, P1 0건이다. 앞선 두 결속 문제를 닫는 설계가 구체화되었고, 기존 R2 승인의 범위를 몰래 확대하지 않는다. 단, 선택 생성기는 출력 파일을 `CreateNew` 방식으로 v1 경로에 기록한다. 따라서 구현·승인 실행 지시에서는 임시 작업 공간을 저장소와 분리하고, 그 안의 고정 v1 출력 경로가 실행 전에 존재하지 않음을 확인해야 한다. 경로가 이미 있으면 생성은 실패해야 하며 기존 저장소의 역사 v1 파일은 건드리지 않는다. 이는 현 제안의 범위 차단 결함은 아니지만 안전한 실행의 필수 전제다.

아직 후속 Approved 계약, v4, v13 원장·입력·계획은 발급되지 않았고 Unity 실행도 없다. 따라서 이 결과는 설계 검토일 뿐 구현 승인, 실행 통과 또는 전체 C4 수용이 아니다.
