## staged 구성과 링크

staged 경로 34개를 확인했다. 모두 `docs/` 아래 Markdown 문서이며 코드, 자산, 설정, 메타, QA 도구, 원시 실행 자료 경로는 staged 목록에 없다. staged 문서의 상대 Markdown 링크는 staged 경로 또는 기존 `HEAD` 경로에서 모두 해석됐다. 끊어진 링크는 0개다.

작업 트리에는 staged 밖의 수정·미추적 산출물이 남아 있다. 따라서 게시 작업은 확인한 34개 staged 경로에 한정해야 하며, 전체 미추적 파일을 일괄 추가하면 안 된다. 이는 현재 staged 묶음의 결함은 아니다.

## 게시 바이트 지도

`docs/verification/2026-10-01-c3-c4-final-publication-byte-map.md`는 11개 문서의 차이를 열거한다. 표의 모든 행을 main 작업공간 원본 및 staged blob으로 다시 해시했다. 11/11행에서 로컬 원본 SHA와 staged 게시 SHA가 각각 표와 일치했다.

차이는 설명대로 제한된다. 6개 문서는 게시하지 않는 로컬 원시 자료 링크를 경로 식별 표기로 바꿨고, 5개는 줄바꿈 정규화뿐이다. 나머지 23개 staged 문서는 main 작업공간 파일과 바이트가 같다. 문서 본문 diff에서도 기록된 경로 표기 대체 외에 요구·판정 내용을 바꾼 차이는 발견되지 않았다.

## 수용 문구와 근거 한계

공동 최종 수용은 v19 소스와 v15 실행에 한정하고, 아홉 실행의 1,654건을 중복 포함 실행 건수로 표시한다. 188개 C4 행, 377개 C3 내부 행, 실행 종료값과 입력 동일성도 별도로 기술한다. 실행 도구 원본의 `WholeAccepted=false`를 그대로 보존한다고 명시한다.

`AC-M5D7QC3-007/008`은 이전 독립 검수에서 규범 상태가 `Open / Not Verified`였음을 숨기지 않는다. 공동 최종 수용문은 현재 실행 증거를 근거로 두 기준을 명시적으로 닫으며, 이것이 과거 검토 결과나 실행 도구 원본을 소급 변경한 것은 아니라고 구분한다. 이는 Astra의 명시적 최종 판정으로 표기되어 있고, 게시 검수자가 대신 수용 상태를 바꾸지 않는다.

문서 게시와 코드 게시도 분리되어 있다. 501개 후보의 게시 허용 목록은 비어 있고, 428개 출처 공백, 기존 10개 변경 사슬의 14개 미폐쇄 전이, 원격 대조·깨끗한 복제 검증의 미완료가 제한사항으로 남아 있다. 새 12개 파일 및 기존 변경 파일에 대한 제한 수용은 바이트·분류 근거의 제한된 범위로 서술되고 게시 허가로 확대되지 않는다. 최종 수용문과 색인은 원시 로그·XML·실행 도구를 게시하지 않는다고 명시한다.
