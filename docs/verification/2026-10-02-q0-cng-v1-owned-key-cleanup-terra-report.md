## 실제 관측

PowerShell `7.6.5`, .NET `10.0.11`에서 제공자 `Microsoft Software Key Storage Provider`와 정확한 빈 문자열 이름 하나만 열었다. 공개 매개변수의 RSA 3072비트 형태를 확인하고 계산한 지문이 V1 기록의 `9C0F6B568E14B7CA407657E5BE0A38F68F0CCF520A4C79ED4E2CB0BEAF15543A`와 일치했다. 개인키는 조회하거나 내보내지 않았다.

제한 환경의 첫 실행은 동일한 대상·지문 일치 후 삭제 호출에서 접근 거부 `0x80070005`로 끝났다. 계약이 허용한 권한 경로로 **한 번** 다시 실행해 동일한 이름·제공자·공개 지문을 재확인한 뒤 `CngKey.Delete`가 성공했다. 즉시 같은 정확 이름을 다시 열었을 때 키 세트 없음 `0x80090016`을 관측했다. 프로세스의 관리자 역할 검사값은 `False`였다. 이는 **해당 이름과 제공자 조회에서** 삭제 후 미존재를 뜻하며 다른 키의 상태를 말하지 않는다. 모든 키나 파일을 열거하지 않았고 다른 이름·키는 삭제하지 않았다.

최종 도구 SHA-256은 `A95EF4A48D30121FE93034EA68F15EADAC00CBFCD6D783C808E963B518A744CF`, 결과 JSON SHA-256은 `AFD1763FD867B701A17452B1CB5BA30E6AFF40576AC1833B04F5D67C63366742`이다. 실제 최종 결과와 오류코드는 `artifacts/c4-q0-cng-v1-owned-key-cleanup-v1.json`에 있다.

이 정리는 합성 V1 시험 키의 정확 대상 확인·삭제에만 해당한다. 실사용 권위 발급, 외부 루트 P1 수용, 전체 의존성·게시, 루나 독립 검수는 수행하지 않았고 자기 수용도 하지 않았다.
