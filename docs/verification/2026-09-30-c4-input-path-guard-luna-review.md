# C4 동결 입력 경로 검사 보정 초안 독립 검토

- 검토 대상: `docs/specs/work-contracts/2026-09-30-c4-input-path-guard-draft.md`
- 정확 SHA-256: `B3E723CAF11E18AF4AF1F6A2A81D5A33817D61DB63AA3B3638E6B5B4D6F8C9C4`
- 대조 기준: Approved C4 r4, QA r2, 동결 보정 승인, 입력 정렬 보정 승인, 현재 v2 원장·입력 목록 및 fixture/tool 경로 참조.
- 판정: P0 0, P1 0. 초안 상태이며 실제 도구 수정·v3 발급·실행 승인이 아니다.

경로 검사 결함은 재현 가능한 정적 결손이다. 현재 `C4-Relative`는 ASCII 문자만 허용하고, 입력 목록 v2에는 이에 맞지 않는 한글 BGM 이름 6개와 내부 공백이 있는 TMP 설정 파일 2개가 있다. 모두 선행 884개에서 보존된 실제 경로이므로 삭제·개명 없이 허용 범위를 최소 확장한다는 초안의 방향은 적절하다.

제안된 허용 범위는 문자·결합 부호·십진 숫자·기존 ASCII 구두점과 내부 공백으로 제한하고, 구성요소의 빈 값·`.`·`..`·맨 앞/뒤 공백·끝 마침표, 절대경로·역슬래시·콜론·Windows 금지 문자·제어문자를 거부한다. 전체 문자열 끝을 엄격히 결속해 마지막 줄바꿈이나 널 문자가 붙은 경로도 통과시키지 않으며, 기존 작업 루트 내부 실경로 검사를 유지한다. 이 조건은 현재 8개 경로를 수용하면서 상대경로 탈출과 출력·재귀 입력 차단을 보존한다. capture의 정렬·사유·전체 입력 재열거 로직을 건드리지 않는 단일 함수 범위도 맞다.

v3 원장은 v2의 102개 파일·순서를 유지하고 verifier 도구의 실제 SHA 하나만 갱신하며, `AllowedChanges`에 그 도구를 REQ-M5D7QC4-007 및 AC-M5D7QC4-009/010의 경로 검사 근거로 추가한다. 이전 20개 경로 권한을 보존해 21개로 만드는 설계는 제한적이다. fixture가 읽는 소스 원장 v1의 C1/C2 바이트는 변경되지 않고 fixture는 그 도구의 v1 행을 권한 증거로 쓰지 않는다. 실행 도구는 v3을 권위 원장으로 삼고 v2를 역사 입력으로 유지한다.

입력 목록 v3는 기존 969개 경로·사유를 보존하고 새 v3 원장과 최종 Approved 계약을 추가해 971개로 만든다. fixture가 직접 읽는 source manifest v1도 기존 목록에서 계속 포함되고, 목록 v1/v2 자체·자기 경로·계획·실행 출력은 빠진다. 새 도구·원장·계약은 승인된 case-sensitive 순서와 경로별 사유에 포함해야 한다. 이 갱신은 정렬 보정 승인 및 동결 보정 승인과 양립한다.

후속 실물 검수에서는 실제 도구 차이가 `C4-Relative` 한 함수인지, 969개 기존 유효 경로와 새 두 경로가 통과하는지, 안전 거절 표본이 계속 거절되는지, v3 원장이 승인 경로 한 건만 추가하고 102개 바인딩 중 도구 SHA 하나만 바꾸는지 확인해야 한다. 입력 v3의 971개 경로·사유·정렬 및 capture 검사 결과도 별도 대조가 필요하다. 이 검토에서는 소스·도구·원장 변경이나 Unity·컴파일·queue 실행을 하지 않았다.
