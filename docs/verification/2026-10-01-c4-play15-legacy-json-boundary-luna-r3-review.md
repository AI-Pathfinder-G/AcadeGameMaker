# Play15 선행 진단 JSON 경계 설계 최종 재검수

검수 대상 제안: `docs/proposals/2026-10-01-c4-play15-legacy-json-boundary-design.md`, SHA-256 `6E33C4E112ADC228D7EF01F7CB4222956CEC5E960D054E88276F422331BBCA84`. 이전 검토 기록은 [최초 검토](2026-10-01-c4-play15-legacy-json-boundary-luna-review.md)와 [r2 검토](2026-10-01-c4-play15-legacy-json-boundary-luna-r2-review.md)에 보존했다.

초기 실패의 원인은 C4 행 표시명이 아니라 Play15의 두 선행 시험이 출력하는 C5 JSON을 C4 행으로 오인한 것이다. 새 제안은 범위를 고정 Play15 선택과 정확한 두 전체 NUnit 이름, 시험 소스 지문, 빈 `RequiredRowIds`로 제한한다. 각 `test-case`가 정확히 하나이고 두 부모 결과가 모두 `Passed`여야 하며, 실제로 테스트의 마지막 재무장 단언은 진단 출력 뒤에 있다. 제안은 다섯 JSON 필드와 값, 사례 인자와 `id` 대응, 각각 한 번만 출력되는 조건 및 JSON 중복 키 거부를 요구한다. 따라서 출력만으로 실패한 부모를 성공 증거로 오인하지 않는다.

예외 JSON은 C4 `Rows`와 계획·도달·통과 집계에 들어가지 않는다. 그 밖의 모든 `{"id":` 줄은 기존 엄격 C4 파싱을 거쳐야 하므로 예상 밖 C4 행은 `UnexpectedIds`, 잘못된 행은 `InvalidIds`로 계속 실패한다. 두 C5 진단을 일반 허용하거나 `schemaVersion` 없는 객체를 폭넓게 무시하지 않는다. 제안된 회귀는 누락·변조·교환·중복 출력·중복 JSON 키·잘못된 부모 귀속·부모 실패·중복 `test-case`를 거부하며, 기존 zero-row와 non-zero 행 검사를 유지한다.

이전 P1이었던 큐 결과 경로 충돌도 정정됐다. 제안은 검증기 변경과 함께 queue 결과 경로 상수만 v12에서 새 v13 경로로 바꾸고, 두 도구의 새 SHA를 새 manifest와 입력 목록에 묶도록 제한한다. 기존 v12 결과 및 기존 XML·선택·188행 원장·제품 소스는 보존하고, 새 아홉 실행 계획과 미사용 출력 경로를 다시 발급하도록 한다. 이는 현재 queue 도구가 이미 존재하는 v12 결과 경로만 허용하는 조건에 맞다.

P0 0건, P1 0건. 설계상 이전 지적은 닫혔다. 다만 이 자료는 여전히 제안 단계이며 실제 도구 구현·회귀·독립 구현 검수 전이다. Unity 실행과 전체 수용 판정은 하지 않았다.
