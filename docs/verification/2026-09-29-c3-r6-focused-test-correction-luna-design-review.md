# R6 집중 시험 보정 설계 독립 검토

검토 대상은 제안 지문 `DE6A88E4041114A4116720ED8639F3C17EA0C6D5AF27A4DE586863722DDEDE43`이다. 설계 정적 판정은 P0 0건, P1 0건이다. 이는 설계의 제한된 품질 검토이며 구현 승인, 실제 실행, 현재 R6 실패 수용 또는 제품 결함 부재 판정이 아니다.

## 추적과 수정된 원시 결과 해석

Approved C3에는 REQ-M5D7QC3-001부터 -007까지만 있다. 명세의 추적은 REQ-001→AC-001, REQ-002→AC-002/004, REQ-004→AC-004/007, REQ-005→AC-005/006, REQ-007→AC-009/010이다. REQ-006은 AC-007/008의 C1 Begin 전 실행 폐쇄 요구다. AC-009와 AC-010은 승인 기준이지 REQ 항목이 아니다. 첫 제안의 헤더가 존재하지 않는 REQ-009/010을 인용한 점은 r2에서 REQ-001/002/004/005/007과 관련 AC로 정정됐다. 실제 안에도 REQ-006의 실행 폐쇄 보정안을 포함하지 않고 AC-006 프레임 격리 시험만 다룬다. 검토한 r2는 r1에서 이 추적 헤더만 바꾼 버전이다.

기존 실행의 원시 집계도 대조했다. decision-row-comparison은 377 planned, 377 행 내부 passed 관측, 0 failed 관측을 기록하지만 `MatchedRows=0`, `EvidenceMatched=false`다. XML에서 이를 출력한 AC002 및 AC004 세 NUnit 상위 케이스는 각각 180,000ms 제한시간 초과로 `Failed`다. 행 출력은 존재하지만 실패한 상위 케이스에 속하므로 승인된 테스트 증거 377행으로 승격되지 않는다. 이는 수정된 실행검토 r3의 문구와 일치하며, 새로운 설계 제안이 현재 3개 실행 실패 묶음(P1)을 닫지 않는다는 전제를 확인한다.

## 보정 범위와 보존 조건

- 고정 분할 산술은 정확하다. AC002 173행을 8행씩 21개와 마지막 5행으로 나누면 22개 시험이다. AC004는 역할별 68행을 3행씩 22개와 마지막 2행으로 나누어 역할당 23개, 총 69개 시험이다. 네 기존 행렬 케이스는 91개로 바뀌어 총 선택은 EditMode 241개, PlayMode 15개가 될 수 있으나 실제 선택 원장·선언된 NUnit 이름 재계산 전에는 확정 숫자로 취급하지 않는다.
- 377개 행의 ID, 원래 역할·순서·범위·예상 결과, 실제 권한 흐름, before/after 파일 검사, 세대 및 원본 참조 검사는 유지한다. AC002의 기존 cohort·epoch 공유 의미와 AC004의 행별 실제 fixture 격리도 유지한다. 새 verifier가 각 행을 정확한 NUnit full name의 실제 XML 결과에 결속하고 그 상위 case가 `Passed`인 경우에만 행을 수용해야 한다. 계획행, 행 내부의 `passed` 표식, 실패 case 출력은 독립적인 NUnit 통과를 대체하지 않는다.
- 180초 NUnit 제한을 유지하고 비용 자료를 보장치로 표현하지 않는다. 개별 선택 실행은 실패 단위를 확인하는 진단일 뿐이다. 한 케이스가 여전히 제한을 넘으면 그 실패를 보존하고, 승인된 377행 전체를 더 작고 매핑 가능한 NUnit 단위로 나누는 변경을 별도 검토해야 한다. 제한을 올리거나 느린 행을 제거하는 해결은 이 설계에 없다.
- 정상 `OnDisable` 시험을 실제 PlayMode 생명주기로 옮기는 안은 직접 콜백 호출이나 `ExecuteAlways`를 금한다. 실제 `Behaviour.enabled=false` 이후 콜백·Owner/handoff 종료·늦은 intake 비변경을 관찰해야 한다. AC006의 빈 released 입력 갱신은 successor 이전에 발생하고, successor 뒤 첫 실제 Submit 프레임의 폐기 검증과 후속 새 실제 선택을 보존한다. 가짜 프레임, 억제 상태 대입, Submit assertion 완화로 핵심 기준을 우회하지 않는다.
- 예상행 생성기·선택 생성기·비교기의 시험 이름 및 행별 매핑 갱신은 수용 판정기를 바꾸는 구현이다. 제안에도 별도 제한 승인이 전제돼 있고, 이 설계 검수는 그 승인을 대신하지 않는다. 기존 회귀 이름·기준 행렬·입력·설정 및 runtime, friend, asmdef, 자산, Q0 조건의 불변은 명시된 범위와 일치한다.

따라서 r2 설계는 기존 실제 결과의 실패 결속을 존중하고 승인 기준을 약화하지 않는 제한 보정안이다. 다음 단계에서도 정확 승인, 새 소스 지문, 91개 이름 생성 검증, Edit/Play 실행, 377행 전부의 실제 Passed-case 대응, 독립 재검수와 아스트라 수용이 각각 필요하다. C3 전체 AC-007/008 또는 C4에 대한 결론은 이 제안에서 도출하지 않는다.
