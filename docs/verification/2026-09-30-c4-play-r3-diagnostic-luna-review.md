검토 대상 Play XML `artifacts/c4-play-r3-diagnostic.xml`의 SHA-256은 `80A145D3C0553935B1256A937CE621D26D5C370F656E3A7288505777CB338F36`, Unity 로그 `artifacts/c4-play-r3-diagnostic.log`는 `9E000EA9AE0245B66F458E9B57D3C9516C169E311F535C2D3274D7D5477559D1`이다. before/after 캡처의 SHA-256은 각각 `B7DA329E85A283F01112F53704CCDEA0F52B159B8C10787DE72998FDB096CE0F` 및 `A649289A2A369A6FD14A4702B3742FC2690AE6A098868EF4CC73F0CCC167004B`이다. 선택 v4는 `032376266E3217B859BDC9F01A98385AD275E25DF0443865196BE7782F97DF13`, 소스 원장 v13은 `E4D55B1923547F9347E0A1DB61355007B7608EA1BC240D0F7EA503CAADBD530D`, 입력 목록 v13은 `9C4C09B574779DE53E6E5CA48F942AF73BAA04E14253B36F2F8F6EE71849538D`, 행 원장 v7은 `E637FC829F1316327866CF0F13305F56A23258341FE0FA4BE80367F853B93C4D`이다.

XML은 총 32건, 통과 32건, 실패·건너뜀·미결정 각 0건을 기록한다. XML의 테스트 이름은 선택 v4의 32개 이름과 중복·누락·초과 없이 일치한다. NUnit XML의 나열 순서는 선택 파일의 명시 순서와 다르지만, 선택 파일 자체는 앞서 검증한 이름과 순서를 유지한다. XML 최상위 결과는 `Passed`이다. Unity 로그에는 “Test run completed. Exiting with code 0”이 남아 있어 실제 Unity 프로세스의 종료 코드 0을 확인했다.

before/after 캡처는 각각 1,029개 항목을 담는다. 두 파일 전체 SHA는 캡처 시각 등의 차이로 서로 다르지만, 경로·파일 SHA 쌍을 항목별로 비교한 차이는 0건이다. 원장 v13의 142개 현재 파일 지문도 모두 실물과 일치한다. 선택 v4의 현재 열거형 소스 지문은 Bridge, 디스크, 메모리 구현의 실제 지문과 맞고, 행 원장 v7은 188개 행을 유지한다.

## 판정

P0 0건, P1 1건이다. 별도 QA 도구 반환 및 바깥 실행기의 반환 JSON이 현재 산출물에 없어 외부 QA 반환 코드를 독립 확인할 수 없다. Unity 로그의 native 종료 코드 0과 XML의 32/32 통과는 확인했지만, 이를 외부 QA 반환 검증으로 확대하지 않는다. 별도 반환 증거가 없으므로 기록상 한계로 남긴다.

이 실행은 선택 v4에 한정된 비수용 진단이다. 최종 9회 큐, 필수 회귀 전체, 또는 C4 전체 수용을 입증하지 않는다. 원본 XML·로그·캡처를 수정하지 않았고 Unity·컴파일·큐를 실행하지 않았다.
