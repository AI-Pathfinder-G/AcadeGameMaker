## 판정

게시 문서 범위에서 P0 0건, P1 0건이다. PR #4 게시 범위는 문서 전용으로 확인되며 아티팩트, 게임 코드, QA 실행 파일·결과, 자산·설정은 포함되지 않는다. 이 검수는 문서 게시 품질만 다루며 v15 전체 PlayMode 610개나 C3·C4 공동 최종 수용의 근거가 아니다.

## 검증 근거

- 게시 대상 병합 커밋 `84f7d2e96530eee1047069f089bb03b7364ad84b`를 원격 `main`에서 읽기 전용으로 조회했다. 부모는 `4d864484f75939dcf9c93c055d296613cf1ba1dd`와 게시 작업 커밋 `5f017d3084987018234fa32cb4eb9426ae0bcb1b`이며, 첫 부모와의 차이는 95개 경로 전부 `docs/` 아래였다. `artifacts/`, `qa/`, 게임 코드·자산·설정 경로는 0개이고, 작업 커밋과 병합 커밋 사이의 차이도 0개였다. 따라서 PR #4 병합 커밋의 게시 범위를 직접 확인했다.
- 현재 체크아웃에서 `git diff-tree --check HEAD`는 공백·줄바꿈 오류를 보고하지 않았다. 게시 바이트 대응표 [`2026-10-01-c3-c4-publication-byte-map.md`](2026-10-01-c3-c4-publication-byte-map.md)는 문서 94개와 바이트 차이 29행을 기록한다. 대응표의 SHA-256은 `8F1573FD73D4954D136AD9A842E3E0973800EF397FAE46E491E6CF163244D0CD`이며, 29행의 게시본 SHA는 게시 전 스테이징 블롭과 재대조되어 불일치 0건이었다.
- 게시 변경 95개 문서의 실제 상대 마크다운 링크를 읽기 전용으로 확인한 결과 해석되지 않는 링크는 0개였다. 역사 문서 링크가 게시 파일로 존재하지 않는 경우에는 게시본에서 원본 경로·SHA와 게시 주석으로 식별하도록 대응표에 기록되어 있다.
- 동결 입력의 [`c4-frozen-source-manifest-v19.json`](../../artifacts/c4-frozen-source-manifest-v19.json)은 SHA-256 `980443316BFB2DC008B611FF948259200C3913C1B3C7F8C5DE6CE62D1511B595`, 소스 193개다. [`c4-frozen-input-paths-v19.json`](../../artifacts/c4-frozen-input-paths-v19.json)은 SHA-256 `274F49B6E0D77C51636FA866DC1EB87321DF64B5AEFB4B8189D8B2DE4DC71F1C`, 입력 1084개다. 새 검수 문서 경로는 두 매니페스트에 없으며, 게시 범위 밖이다.
- 게시 상태 색인 [`2026-10-01-c3-c4-publication-evidence-index.md`](2026-10-01-c3-c4-publication-evidence-index.md)와 위키의 `Implementation-Status`, `Publishing-Status`는 문서 게시와 실행·수용을 구분한다. 현재 기록은 C4를 검토 중으로 유지하고, 마지막 PlayMode 610개와 전체 공동 수용을 미완료로 둔다. PR #4와 위키 게시 완료는 문서 탐색·상태 게시이며 제품 동작 또는 시험 수용을 뜻하지 않는다.

## 범위 제한

v19의 193개 소스와 1084개 입력은 게시 대상이 아니라 검증 기준의 식별자다. 원시 XML·로그·JSON·실행 스크립트, 게임 코드, QA 도구, 자산과 설정은 이 문서 게시 검수에서 수용하지 않았다. 역사적 원본 SHA와 Git 게시본 SHA는 줄바꿈 정규화에 따라 다를 수 있으므로 대응표의 두 지문을 혼용하지 않는다.

이 기록은 `AC-M5D7QC3-009/010` 및 `AC-M5D7QC4-009/010`의 문서 게시 추적만 남긴다. C3 전체 구현·검증, v15 전체 PlayMode 610개, C4 공동 최종 수용은 별도 실행과 독립 검수 및 Astra 판정이 필요하다.
