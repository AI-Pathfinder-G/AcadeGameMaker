P0 0건, P1 0건. 초안은 제한 수용의 의미를 현재 바이트 수용이나 게시 승인으로 넓히지 않으며, 489 후보·61 근거·428 공백을 유지한다. C4 v19의 Assets 33개와 후보 원장의 교차는 독립 재계산 결과 후보 내 21개(지문 변경 10, 동일 11), 후보 밖 신규 12개로 초안과 일치한다. 이 수치는 후속 원장 발급 때 다시 계산한다는 조건도 적절하다.

## 근거와 경계

- 바이트 근거 R2는 489 후보 중 61개에 직접 경로·지문 근거가 있고 428개에는 직접 근거가 없다고 기록한다. 권한 색인의 428개는 이 공백과 같고, 제한 수용 문서는 60개 정확 바이트 경로와 R6 제한 정적 1개, 나머지 428개 및 게시 차단을 그대로 유지한다. 색인의 Approved 경로 22개와 유일 파일명 4개를 현행 SHA 승인으로 세지 않는 초안의 구분도 근거와 맞다.
- 초안의 추적 범위 `REQ-M5D7QC3-007`, `REQ-M5D7QC4-007`, `AC-M5D7QC3-009/010`, `AC-M5D7QC4-009/010`은 게시·재현 준비의 관련 기준이다. 파일별로 실제 승인 문서의 정확 경로·줄·상태와 적용 REQ/AC를 기록하게 하고, C3 기존 요구 `001..007` 밖의 ID를 만들지 않도록 한 제한은 적절하다. 선행 수용의 `REQ-M5D7QC3-001..007`, `AC-M5D7QC3-001..006/009/010` 및 전체 수용이 아닌 범위와도 충돌하지 않는다.
- C4의 변경 10개와 신규 12개를 기존 역사 수용이나 부모·동명 파일·폴더·meta 권한으로 자동 승격하지 않는다. 17 실행 자산과 10 설정, 미해석 Renderer2D GUID 7개, 잔여 공백 분류와 기존 도구 입력 7개의 별도 처리는 승인 경계 및 바이트 자료의 미해결 항목을 드러내며, 해석 전 무영향·결손·빌드 성공으로 결론 내리지 않는다.
- 파일별 독립 원장, 루나의 독립 검수, 아스트라의 별도 파일별 허용 목록, 게시 직전 원격/지문 재확인, 승인 목록만 든 깨끗한 복제의 Unity/import/조립/GUID/시험 검증은 제한 수용 기록이 주지 않은 권한을 보완 게이트로 둔다. Q0 기존 Git 차이 조건의 재현을 선결 사실로 주장하지 않으며, 클린 복제 성공도 미리 선언하지 않는다.
- 기존 문서 137개 게시와 위키 갱신의 승인·영수증은 코드 게시 허가가 아니다. C3 AC007/008 미수용, C4 Review, v15의 전체 결과 미확정, 코드·자산·설정 게시 불승인이라는 상태를 유지한다.
