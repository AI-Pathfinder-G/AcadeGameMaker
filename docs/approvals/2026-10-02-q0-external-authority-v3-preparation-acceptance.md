# Q0 v3 키 없는 준비 수용과 첫 발급 시작 조건

2026-10-02 실제 `gpt-6-astra`가 `REQ-PLAT-068/069/070`, `AC-PLAT-066/067/068`의 v3 키 없는 준비 범위를 한정 수용한다. [정수·정리 보정 계약](../specs/work-contracts/2026-10-02-q0-strict-numeric-and-process-cleanup.md) SHA `55DAED7944E63010D6F278E8316BC8BC1EB99C51D7BAD12CCEC35C9380F7C84D`의 두 P1은 아래 실제 수동 관문을 포함하는 한정 범위에서 폐쇄한다. 운영 외부 권위·현재 계획 발급·전체 회귀·게시가 완료됐다는 판정은 아니다. 이 판단 시 실제 운영키는0개이며 본 검토는 키를 생성하지 않았다.

수용하는 정확 초안은 `output/q0-external-authority-evidence-r1/preparation-v3-draft.json` SHA `685CE7EA4E6B486E542CDBFD40F389AABA3E946E89B47010F68646E07FC54AE3`와 `negative-tests-v3-draft.json` SHA `5A9B6CAEB1815256BF8809D567A18150A589237A39E3F170CEF12D4C170615BE`다. 두 SHA를 현재 파일에서 재계산해 일치 확인했다. 루나 `gpt-6-luna`가 실제 독립45/45, 현재20지문 일치, 지정3변경/17불변, 원시숫자29토큰·8의미군, 입력5·정리4·전용 호스트의 자발/시작 후 예외/시간초과 종료를 확인하여 추가 P0/P1 없음으로 전달했다. 이는 루나의 실제 검수이며 아스트라가 재실행했다고 주장하지 않는다. 루나 원문 보고는 `docs/verification/2026-10-02-q0-external-authority-luna-review-v3.md`에 검수한 두 SHA와 실제 재현·한계를 남겨 최종 증거에 결속한다.

## 수동 승인 경계의 명시

현재 `Assert-Q0V3Preparation`은 키 생성 전에 엄격 숫자·정확 필드·20소스·결과/운영 미생성 상태를 검사한다. 45사례 각각과 모든 관측 관계의 전체 의미 검사는 서명 뒤 `Confirm`의 `Assert-Q0PreparationEvidence`에서 수행한다. 코드 자체가 키 생성 전에 그 전체 관계를 검사한다고 주장하지 않는다.

이 분리는 주 조정자의 **운영 시작 직전 독립 검수된 정확 최종 두 SHA와 현재20소스 SHA 대조**가 전체 의미 승인 경계라는 조건에서 현재 계약을 충족한다. 임의 새 `PASS` 파일을 간이검사만 통과시켜 키를 생성하는 경로는 승인하지 않는다. 비교 기대SHA는 파일 자신의 선언이나 호출자가 임의 제출한 값이 아니라 위 루나 검수와 아스트라 수용의 정확 값이다. 주 조정자는 실제 읽은 지문·판정시각·루나 보고SHA·현재20개의 행별 일치를 발급 증거에 남긴다. 이 범위에서 추가 소스 변경이나 새 증거 버전은 필요하지 않다.

## 동일 바이트 최종 발급과 운영 첫 키

1. 루나 원문 보고를 완성하고 정확 검수 두SHA와 수동 관문 해석이 일치하는지 확인한다. 주 조정자는 최종 초안 바이트와20개 현재 소스 지문을 다시 대조한다. 불일치면 이 수용으로 진행하지 않는다.
2. 승인된 두 초안의 원시 바이트를 각각 `output/q0-external-authority-evidence-r1/preparation-v3.json`, `negative-tests-v3.json`에 `CreateNew`로 한 번 복사한다. 재직렬화·상태 수정 없이 각 최종SHA=위 초안SHA와 바이트 차이0을 확인한다. 기존 파일이 있으면 덮어쓰지 않는다. 초안도 이후 동결한다. v1/v2 실패 이력은 불변이다.
3. 주 조정자는 운영 전용 호스트를 시작하기 **직전** 최종 두 파일·20소스·issuer 원본SHA·준비 검수 보고를 다시 읽어 정확 일치를 확인한다. 이 실제 단계가 빠지면 키 생성 조건을 충족하지 못한다. 작업 중 해당 파일을 수정하는 담당이 없어야 하며 대조와 실행 사이 변경이 관측되면 중단한다.
4. 위 단계 및 원래 계약의 저장소/경로/인증·기한/출력 관문이 충족되면 [원래 발급 계약](../specs/work-contracts/2026-10-02-q0-external-authority-issuance.md) SHA `451998AB32068DF1879E76B0A4CEC2ACB13619CDE7D48F25CB1E0E25A88AADEC`이 허용한 **첫 운영키 한 개**와 문서 두 개·계획 한 건의 발급을 시작할 수 있다. 새 인간 승인이나 별도 준비 계약은 요구하지 않는다. 공개키 지정 자리 대입과19개 동일/검증기 전이 확인, 단명45분·한 번 결속/서명·중첩 정리·전용 호스트 실제 종료 조건은 모두 유지한다.
5. 서명 뒤 전체 의미 관문이 거절하면 발급 성공을 기록하지 않는다. 이미 생긴 공개 권위/서명/오류를 실패 이력으로 보존하고 중첩 정리와 호스트 종료를 확인한다. 두 번째 키·재서명을 자동 시도하지 않는다. 원격 가지 보호 상세 조회의403은 행정 조회 범위 제한으로 보존하되 일반 인증 실패나 병합 성공의 증거로 확대하지 않는다. 실제 병합·불변 권위 조회는 실행 중 별도 확인한다.

이 문서는 준비 수용·조건부 시작 허용이다. 최종 파일 발급·키 생성·원격 병합·실제 서명 완료를 미리 주장하지 않는다. 미실행 계획의 `ExecutionAuthorized=false`, 원래 원격 정확 두 문서 범위, 게임/QA 코드 게시 미승인과 후속 실행 계약의 별도 관문을 유지한다.
