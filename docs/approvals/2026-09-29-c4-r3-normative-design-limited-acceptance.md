# C4 r3 규범 설계의 제한 수용

2026-09-29, 아스트라, 실제 `gpt-6-astra`. 이 기록은 `REQ-M5D7QC4-001..007` 및 `AC-M5D7QC4-001..010`에 대한 후속 계약의 기술 선택만 확정한다. C4는 Review이며, C3 마지막 필수 실행610과 선행 단계의 독립 수용이 완료되기 전 구현을 허용하지 않는다.

대상은 [r3 초안](../proposals/2026-09-29-c4-implementation-contract-ready-r3-draft.md), SHA `F4A6BA518DC75960784AEBC53F77DB0B9107DAA03472D35042BC1D6F9DB75F73`이다. [루나 독립 설계 검수](../verification/2026-09-29-c4-implementation-r3-draft-luna-review.md), SHA `8D1B5B70771F5A9DF2296740976D1A819D081A2193FAC820F3EB82608E501FA5`, 설계 텍스트 기준 P0/P1=0을 확인했다. 이전 세 P1의 원본과 실패·검토 이력은 보존하며 현재 설계 대안의 충분성만 수용한다.

## 정확 규범 선택

- AC007: 실제 C1 준비 결과의 전체 검증과 양측 가드 결속 후, C2 호출 직전 한 번의 시험 정지만 선택한다. 준비10초·작업자 보유20초·정리 합류10초 상한과 사례180초를 유지한다. 실제 임시 루트의 다른 작업자 lease로 C2 Busy를, 별도 실제 unsafe lock 경로로 C2 ManualRepair를 확인한다. 가짜 결과·대체 실행·시간 초과의 성공 재분류는 금지한다. 정상 3인자 실행은 고정 무동작 control만 사용한다.
- AC003: 실제 Begin이 반환한 readonly struct의 복사본에 대한 단일 outcome/state 음성 시험과, 동일 공유 순수 validator의 성공이 모든 실제 proof 전달·C2 분기를 지배한다는 최종 소스 증거의 조합을 채택한다. 이것은 실행 중 저장값 손상 시험이 아니다. 실제 nested proof의 단일 `_root=null` 및 실제 C2 반환 객체의 단일 `_outcome=default` 손상은 각각 별도 AC005/007 실행 증거로 검증한다. 기존 getter의 검증을 우회하지 않고, 정상 proof 참조 취득 뒤 음성 observer 및 재검증 순서를 따른다.
- AC001/008: 실행은 실제 발급 스레드 문맥에 한정한다. 실제 원장과 독립 발급 사건의 관리 참조로 신뢰 스레드를 확증하는 검사가 먼저다. 지원하지 않는 스레드 또는 신뢰 anchor를 확증할 수 없는 호출은 무소비·무변경·Unity/native/C1/C2 0회의 문맥 거절이다. 이를 payload 전체 검증 완료, 정상 권한 또는 종료 정리 완료라고 기록하지 않는다. 원래 스레드만 전체 불변식·단일 필드 손상·pair/root/generation을 검증하며, 등록 원본 projection 손상은 영구 fault 사건을 native Disable 전에 기록하고 양측 terminal로 처리한다. 소비 이후의 모든 불확실·예외 경계는 기존 양측 영구 종료 규칙을 유지한다. 이미 소비·종료된 요청의 늦은 호출은 관리 이력으로 비변경 거절한다.

원본의 clean pre-entry 무소비 규칙과 reflection corruption의 선택적 containment에 대한 위 문맥 해석을 기술 규범으로 선택한다. 단일 trusted anchor 손상은 실행 불가를 보장하며 원래 세션 전체의 native 종료를 수행했다고 주장하지 않는다. 새로운 정상 발급기·복구·모든 private 필드 동시 손상 보장은 추가하지 않는다. 계획한 Thread 참조 필드는 현재 소스의 구현 사실이 아니다.

guard는 해당 옛 세션의 메뉴·알림·저장 권한과 메모리·입력 생산을 차단한다. 독립 Profile 저장과 외부 파일 쓰기는 기존 lease 및 실제 durable barrier의 경계로 구분한다. worker에서 기존 Unity 종료 함수를 호출하거나 모든 독립 writer에 새로운 관리 latch를 확장하는 r2 대안은 채택하지 않는다. 실제 held Submit의 기존 canceled 사건만 재진입 실행 증거로 삼고 사건이 없었던 구간은 구조 증거로 분리한다.

## 구현 승인 전 조건

정확 C4 계약 개정에 위 선택과 r3의 파일·API·Q0/Q-A/Q-B 보정 범위를 옮긴 뒤 별도 승인해야 한다. 이 기록은 기존 Review 계약의 상태나 소스를 바꾸지 않는다. C3 선행 gate, C2의 현재 경계 동결과 독립 수용, 정확 감사 보정과 실제 구현 허용 목록을 생략하지 않는다.

구현 후에는 신규 source/meta 동결, 정식 NUnit 이름·예상 수·checkpoint 도달 및 음성 행의 별도 원장, 실제 native/QA/외부 종료와 전후 입력 지문을 요구한다. 기존 240/15/562/51/610 선택 이름과 사례180초를 보존한다. 새 C4 소스에 R11의 고정14·입력884 큐 또는 과거 통과 결과를 재사용하지 않는다. 루나의 새 소스·실행 독립 검수와 아스트라 통합 수용 전 C3 AC007/008이나 C4 전체를 Verified로 기록하지 않는다.

현재 수용은 규범 설계에 한정되며, 실제 구현·실행 연결·전체 C3 수용·게임 코드 최초 게시 승인은 없다.
