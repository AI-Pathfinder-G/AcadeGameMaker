# C3 하위 확인 요청 경계 구현 설계 승인

아스트라는 2026-09-29에 Approved C3의 하위 경계 구체화를 승인한다. 대상은 [솔 반대 설계](../proposals/2026-09-29-c3-lower-confirmed-request-boundary-review.md) SHA-256 `EAA6CBE69CACC2BCA91515296768FC6E0C76F3C2BDCF604AF661D77A70A3218D`이며 [루나 독립 설계 검수](../verification/2026-09-29-c3-lower-confirmed-request-boundary-luna-review.md) P0=0/P1=0을 확인했다.

REQ-M5D7QC3-001/002/004/006/007의 기존 허용 목록 안에서 `ProfileNewGameConfirmationV1.cs`와 새 lower 집중 시험·메타만 구현한다. 실제 내부 발급 capture, 정확한 adapter/router/root와 opaque owner/epoch 참조, 전체 세 leaf identity 비교, 한 번의 요청 발급, 불투명 커밋 예약·완료·종료 경계를 구현한다. lower 커밋만으로 상위 권한 폐쇄나 Q-B 출처를 증명했다고 주장하지 않는다.

상위 소유자는 실제 Q-B 발급·확인 CAS와 같은 owner/epoch/generation을 검증하고 모든 결정·재시도·재무장·입력 상호작용을 폐쇄한 후에만 동일 예약을 완료해야 한다. 이 결합은 이후 실제 owner 시험으로 검증한다. 현재 lower 시험은 actual capture·identity 비교·불투명 요청·중복 및 외부 값 거절 경계에 한정하며 전체 C3 권한 검증의 양성 증거가 아니다.

기존 C3L 수용 원문·지문·원장은 선행 증거로 보존한다. Adapter/Profile 관찰·기존 시험·조립 방향은 변경하지 않는다. 새 identity 추출 경계, ExecutorConsumed, C1 Begin, C2 및 실행 보고 발급은 Review C4의 범위이므로 현재 추가하지 않는다. 코드 수용이 아니라 구현 설계 승인이고 실제 실행·독립 검수·아스트라 통합은 남아 있다.

## 독립 구현 검수 후 보정 승인

아스트라는 [하위 구현 독립 정적 검수](../verification/2026-09-29-c3-lower-confirmed-request-runtime-luna-review.md)의 P1 두 건을 확인하고 같은 허용 파일 안의 보정을 승인한다. 예약 CAS 전 현재 실제 capture·전체 projection·인증된 root를 재검증하고, 인증된 요청의 예약 이후 실패는 종료 상태로 보내 원래 예약 재시도를 차단한다. 인증 전 외부 소유자 불일치는 원래 요청 권한을 소모하지 않는다. 이 구별과 반사 손상·복제·세 leaf 불일치를 실제 집중 시험으로 증명해야 한다.

기존 내부 `IdentityFor`는 저장소 호출이 없음을 확인했다. C4 승인 전 직접 identity 추출 경계를 남기지 않도록 해당 미사용 메서드를 제거한다. 이는 새로운 실행 연결 권한을 승인하는 변경이 아니다. 독립 검수와 실제 실행 전에는 보정 구현을 수용하지 않는다.

## GPT-6 재개 후 남은 결함 보정

사용자 지시와 ADR-0037에 따라 테라 구현 역할은 별도 `gpt-6-sol`, 루나 독립 검수는 `gpt-6-luna`로 수행한다. 아스트라는 [최신 독립 검수](../verification/2026-09-29-c3-lower-gpt6-luna-review.md)의 P1 두 건을 확인하고 같은 하위 허용 파일의 보정을 승인한다.

확인 요청 witness는 실제 mint에 사용한 원본 capture-result 및 그 비공개 발급 witness를 참조로 보존하고, 재관찰 값의 동일성이 아니라 원래 발급 연결의 동일성을 예약·완료 전에 확인해야 한다. 같은 cohort/root의 다른 실제 capture로 한 필드를 바꾸어도 요청에 들어간 원래 identity가 교체될 수 없어야 한다. caller에게 원본 증명이나 registry를 노출하지 않는다.

외부 cohort/token/generation의 인증 전 거절은 원래 요청을 소모하지 않는다. 정확한 실제 요청의 인증이 끝난 뒤 예약 직전 검사 실패는 아직 예약 CAS가 일어나지 않았더라도 `Issued` 또는 `CommitReserved`를 `Closed`로 종료하고 원상복구 후 재시도를 금지한다. 이미 종료·완료된 역사 상태를 되돌리지 않는다. 필요한 복제·발급 witness·세 리프 투영·root·외부 문맥 음성 시험을 실제 행으로 추가하고, 새 정확 소스로 집중 실행·독립 검수를 수행한다. 이는 상위 Q-B 출처나 C3 전체·C4 승인으로 확대하지 않는다.

## 단일 소비 필드 복원 방지 설계 승인

아스트라는 [단일 CAS 무결성 보정안](../proposals/2026-09-29-c3-lower-single-field-cas-integrity.md) SHA-256 `D23ED6F90FE58198A4C5778133083463CA4715BB72CF87DD377C3CDC1A6C6754`와 [루나 독립 설계 검수](../verification/2026-09-29-c3-lower-cas-integrity-luna-design-review.md)의 P0=0/P1=0을 확인했다. `REQ-M5D7QC3-001/006`, `AC-M5D7QC3-001/008`의 하위 부분 증거를 위해 같은 런타임·시험 두 파일의 제한 구현을 승인한다.

실제 witness 참조에 결속된 비공개 생애 기록과 불변 사건을 정수 소비 상태와 함께 검증한다. 정상 중복·동시 호출의 패자는 승자의 유효 권한을 닫지 않으며, 인증 전 외부 문맥 거절도 비소모다. 실제 사건과 정수 불일치 또는 승자 경로 실패만 인증 후 종료한다. 완료·종료 이력은 되돌리지 않는다. 예외 경로의 이력 저장은 미리 보유한 참조를 대입하는 방식으로 추가 할당 없이 처리하고, 사전 생성 종료 사건에 아직 존재하지 않는 예약 쌍을 제조하지 않는다. 실제 등록된 쌍과 이전 사건은 보존된 종료 이력으로 증명한다. 구현자는 이 순서와 중간 등록 실패 시험을 구체화해야 한다.

공개 시험용 발급기·장애 주입 API·등록부 노출, C4 실행·보고·identity 추출은 금지한다. 새 정확 소스의 실제 집중 실행과 독립 구현 검수 전에는 수용하지 않는다.

## 실제 시험 조립 컴파일 후 두 줄 접근 보정

테라가 기존 Unity 응답 파일의 참조·정의를 사용한 별도 C# 컴파일에서 하위 시험 지문 `F5EFF1F9414F1DFC6BC3ECBB4A2B66592AEC61416DADD2902A59F695C699C4D3`의 `ProfileResetConfirmationCaptureV1` 직접 참조가 이 시험 조립의 내부 접근 권한 밖이라 실패했다고 보고했다. 아스트라는 해당 복제 음성 시험 두 줄에서 객체를 `object`로 받고 기존 정상 검증 메서드 호출 도우미로 검증하는 최소 보정을 승인한다. 조립·friend·런타임·반례 의미·정상 권한 발급 방식은 바꾸지 않는다. 원래 컴파일 실패·정확 명령·응답 파일·실제 종료를 보존하고 새 시험 지문에서 재컴파일 및 독립 검수해야 한다. 기존 정적 검수는 이전 지문의 이력이며 새 시험 실행 또는 수용 증거가 아니다.
