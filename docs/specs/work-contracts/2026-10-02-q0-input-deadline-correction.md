## 실패 역사와 차단

주 조정자와 루나가 .NET10의 `Console.In.ReadLineAsync`가 `SyncTextReader`에서 동기 대기할 수 있어 반환된 작업의 `Wait`만으로 입력 기한을 보장하지 못함을 확인했다. 열린 표준입력에 데이터가 오지 않는 경우 원래45분 입력 기한과 정리 진입을 입증하지 못하므로 운영 시작 차단 P1이다. 이전 준비 보고의 성공 표기는 수용 근거로 철회한다. 이는 과거 합성 다른 사례까지 무효라는 뜻이나 실제 운영키 사고라는 뜻이 아니다.

다음 최초 파일은 현재 재계산한 원시 SHA와 함께 실패 이전 관측 이력으로 불변 보존한다. 삭제·덮어쓰기·동일 이름 재생성·문구 소급 정정은 금지한다.

- `output/q0-external-authority-evidence-r1/preparation.json`: `1E96EA32DD1A08AED2A4F737F15864AE200928BBE0689FE953DC9C278E0D9AEA`
- `output/q0-external-authority-evidence-r1/negative-tests.json`: `2B74D4B051CA0AE1CE5629D51D00098E683A8E9357BE84B049A5AB61C3D07A24`
- `docs/verification/2026-10-02-q0-external-authority-terra-report.md`: `70275187A9D9C3B4DA845259622FE789A61B2C0EAC0C11B6418074E097CCB555`

본 계약 작성 때 현재 진행자에서 이미 `Console.OpenStandardInput`을 사용하는 보정 중 소스가 관측됐다. 이를 과거 최초 증거의 실행 소스나 독립 수용 소스로 소급하지 않는다. 테라는 최초 기록 지문·보정 시작 현재 지문·최종 지문을 단계별로 구별하고 기존 문서/소스 이력의 불일치를 숨기지 않는다.

## 정확 보정과 새 출력

테라 `gpt-6-sol`은 원래 허용된 `output/q0-external-authority-r1/qa/tools/Invoke-Q0ExternalAuthorityIssuance.ps1`과 `output/q0-external-authority-r1/qa/tools/Test-Q0ExternalAuthorityIssuance.ps1` 두 소스만 이번 문제에 맞게 보정한다. 단독 검증기·스키마·helper·네 C#·다른 파일의 의미 변경은 이 보정으로 허용하지 않는다. 최종 실제 현재 소스 집합20개와 필드별 원시 SHA를 다시 열거하고 변경은 이 두 파일뿐임을 확인한다. 실제 집합이20과 다르면 숫자를 맞추지 말고 정확 차이·원인을 보고한다.

입력은 `Console.OpenStandardInput`의 원시 스트림과 별도의 비동기 reader를 사용한다. `Console.In`의 동기 래퍼에 다시 의존하지 않는다. 읽기 시작 자체가 기한 검사 스레드를 막지 않는지 실제로 확인한다. 한 번에 하나의 읽기만 허용하고, 시간초과 뒤 남은 읽기가 다음 단계를 소비하거나 재사용되도록 두지 않는다. 만료·EOF·잘못된 UTF-8/형식은 서로 구별해 실패시키며 `finally`에서 reader/stream 및 열린 발급 세션을 닫고 소유 프로세스를 종료한다. 운영45분 단조 기한을 늘리거나 EOF를 성공 단계로 처리하지 않는다.

새 허용 출력은 정확 `output/q0-external-authority-evidence-r1/preparation-v2.json`, `output/q0-external-authority-evidence-r1/negative-tests-v2.json`, `docs/verification/2026-10-02-q0-external-authority-terra-report-v2.md`다. 부재 확인 후 새 파일로 한 번 생성한다. 기존 두 JSON/보고를 지우고 새로 만드는 방법은 승인하지 않는다. 실패 시험의 표준출력·표준오류·시각/종료/소스 지문은 새 두 JSON 안에 보존한다. 임시 실행 프로세스는 메모리/파이프로 제어하며 승인 밖 새 시험 파일을 늘리지 않는다.

## 실제 시험과 독립 관문

`AC-PLAT-067`: 별도 실제 자식 프로세스의 표준입력을 **열린 채로 유지하고 아무 데이터도 보내지 않는** 짧은 제한 시험을 수행한다. EOF를 보내거나 부모가 먼저 파이프를 닫아 시간초과처럼 보이게 하지 않는다. 예를 들어 내부200밀리초 기한·외부5초 관찰 한도를 쓰고 실제 단조 경과시간, 시간초과 사유, 정리 진입, 자식 종료를 기록한다. 관찰 한도까지 자식이 종료하지 않으면 실패이며, 정확 소유한 자식만 종료한 사실을 기록한다. 부모 강제 종료를 정상 기한·정리 성공으로 계산하지 않는다.

별도 EOF 사례, 기한 안 정상 공개 한 줄 수신, 잘못된 단계/입력 거절 및 읽기 뒤 추가 호출 금지를 확인한다. 공개 입력 수신 성공은 운영 인증 성공이 아니다. `finally` 출력 문자열 하나만으로 세션/reader 폐기를 입증하지 않는다. 정리 코드 경로와 폐기 후 접근 거절·관측 가능한 정리 상태를 대조하고 실제 확인한 범위만 쓴다. 이 단계에서는 운영키를 생성하지 않으며 기존 허용 합성 시험과 키 없는 입력/정리 검증만 수행한다. 합성 정리로 실제 운영키의 폐기를 수행했다고 주장하지 않는다.

`AC-PLAT-068`: 전체 기존 합성 회귀와 새 입력 경계, 정확20개 최종 소스/현재 바이트 결속, 최초 세 증거 불변 및 원문534·LF534·LF505·기존 issuer/core 불변을 확인한다. 새 JSON은 `SupersedesPreparationEvidence`에 최초 경로/지문과 이번 P1을 기록하되 과거 파일을 삭제하지 않는다. 준비 성공은 새 결과가 실제 충족한 부분만 표시하고 전체/게시/루나 수용 플래그는 거짓이다.

루나 `gpt-6-luna`가 이 보정의 정확 두 소스와 v2 결과를 독립 확인하고 열린 입력 기한을 실제 별도 프로세스에서 재현한 뒤 아스트라가 P1 폐쇄와 운영 시작 조건을 판단한다. 그 전에는 운영키 생성·권위 발급을 시작하지 않는다. 후속 `source-freeze.json`과 실제 계획은 **v2 준비/음성 결과·최종20소스 지문**에 결속하고 최초 성공 표기를 선택하지 않는다. 최종 동결 뒤 의미 변경이 필요하면 원래 발급 계약의 폐기/재준비 규칙을 따른다.
