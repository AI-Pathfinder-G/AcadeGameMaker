## 실제 공백과 한정 소스

원본 QA 도구의 `Invoke-OwnedEditorWait` 안 `Launch`가 `Start-Process -PassThru`로 실제 Unity를 시작한다. 큐 부모가 외부 프로세스 목록을 뒤늦게 관찰하는 것만으로 이 시작 사건과 자식의 첫 인증 요청 사이에 엄격한 선후 장벽이 있었다고 증명할 수 없다. 원본불변 감시만으로 공백이 닫혔다고 수용하지 않는다.

기존 허용 준비 복제 `output/q0-trusted-child-r1`에 **`qa/tools/Invoke-UnityQa.Canonical.ps1` 한 개**를 원본 바이트에서 파생하는 후속 도구로 추가 허용한다. 변경은 시작 전 승인 슬롯 요청, 실제 시작/편집기 부착 뒤 등록, 부모 응답 장벽, 종료·오류 등록에 한정한다. 기존 환경/경로/소유 편집기 확인·인자 인코딩·단일 시작·실제 종료/결과 판정·경합 차단은 보존한다. 원본 도구는 편집하지 않는다. 기존 허용 큐/선택 실행자·lease 모듈·자체시험만 후속 도구 경로/지문과 등록 인터페이스에 맞게 연결할 수 있다. 다른 새 소스/조립/메타는 추가하지 않는다.

후속 도구를 현재 소스/입력 원장의 명시된 새 역할로 넣고, 출발 원본SHA·후속SHA·최소 차이와 전체 직접 읽기 입력을 기록한다. 기존20개는 외부 발급 준비의 집합이며 후속 실행 소스가21개 또는 다른 수가 됐다는 이유로 원본20 기록을 수정하지 않는다. 준비 복사·구현은 현재 입력 원장의 루나/아스트라 관문 충족 뒤 시작한다.

## 시작·등록·인증의 실제 순서

1. 이미 등록된 QA 자식이 정확 계획SHA·InvocationId·Stem·역할·실행파일/인자 결속으로 부모에 단일 시작 슬롯을 요청한다. 부모는 해당 QA의 실제 연결 PID·보유 핸들·UTC 생성 전체 ticks·실제 부모 계보를 검증하고 한 슬롯만 승인한다. 슬롯은 프로세스 실재의 증거나 Unity 권위가 아니다.
2. QA는 그 슬롯으로 정확 한 번 시작하고 반환된 프로세스 핸들을 즉시 유지한다. 실제 PID·`StartTime.ToUniversalTime().Ticks`·경로·부모 관계를 부모에 등록한다. 부모는 전달 문자열만 신뢰하지 않고 자신이 연 살아 있는 OS 프로세스 핸들에서 PID·전체 ticks·실행 경로·실제 QA 부모/계보를 독립 확인한다. PID만 일치하거나 초 단위 시각/잘린 ticks만 일치하면 실패다. 시각 포맷은 전체 ticks 정수와 왕복 UTC 형식을 모두 보존한다.
3. 반환된 시작자와 실제 편집기 프로세스가 다르면 실제 편집기 부착 단계에서도 같은 등록을 수행한다. 중간 시작자 핸들과 생성시각/계보를 보존하여 둘을 연결한다. 사망·권한 제한·계보 미확정으로 직접 소유를 입증하지 못하면 실패하며 명령행 유사성만으로 대신하지 않는다. 관련 핸들은 판정과 정리가 끝날 때까지 유지한다.
4. 부모의 실제 등록 완료 응답 뒤에만 해당 Unity/역할/Stem 요청에 도전값·권위 요약을 발급한다. QA도 등록 완료 장벽을 넘기 전에는 시작 성공이나 정상 관측 상태로 진행하지 않는다. 초기 Unity 인증 요청이 먼저 도착하면 **신뢰되지 않은 대기 요청**으로 유한 기한 안에서만 보관하고 등록 뒤 실제 연결 프로세스 신원을 다시 확인한다. 등록 전에 권위·성공 영수증·도전값을 발급하지 않는다. 등록 실패/기한초과는 요청 거절과 소유 프로세스 정리로 끝난다.

기존 계약의 “연결 전에 등록”은 이 보완에서 **인증 교환 및 권위 전달 전에 실제 등록 완료**로 정확히 한정한다. 파이프의 물리적 연결 자체가 먼저 성립할 수 있다는 사실을 숨기지 않는다. 물리적 연결·채널명·시작 슬롯만으로 권위를 부여하지 않으며, 인증 교환 이전 등록 장벽의 요구는 완화하지 않는다. 실제 미등록 프로세스가 권위를 받았다면 실패다.

## 키 없는 검증과 실패 처리

기존 `c4-canonical-trusted-child-selftest.ps1`과 허용된 채널 증거 안에서 시작 슬롯 중복·등록 전 요청·잘못된 PID/전체 ticks/부모·슬롯 재사용·등록 응답 지연/손실·빠른 자식 종료·부모 사망을 실제 별도 프로세스로 검증한다. 일찍 도착한 요청이 등록 전 성공하지 않음, 등록 뒤 같은 실제 자식만 한 번 통과함, 미정은 실패로 끝남을 계측한다. 초 단위 생성시각과 전체 ticks가 충돌하는 사례를 거절한다. 실제 핸들을 보유한 부모/QA/Unity 연결의 정상 사례도 격리 컴파일/채널 관문에서 확인한다.

종료는 정확 소유 핸들·생성 ticks를 확인한 자식만 대상으로 한다. 다른 편집기를 전체 종료하지 않는다. 외부 강제 종료를 자발 종료나 관리 `Dispose` 성공으로 기록하지 않는다. 등록 사건·요청 도착·승인 전달·종료 관측의 순서와 시간은 기존 `channel-tests.json`, `unity-compile.json` 및 테라/루나 보고에 넣고 임의 추가 증거 경로를 만들지 않는다.

루나가 실제 등록 장벽·음성·후속 QA의 기존 판정 보존·지문을 독립 검수하고 아스트라가 준비 범위로 수용한다. 실제 아홉 선택·새 권위 발급은 기존 실행 계약의 나머지 관문을 유지한다. 이번 보완은 인증 도구 실패나 첫 발급 실패 세대를 정상 권위로 승격하지 않는다.
