## 1. 목적과 현재 허용

REQ-M1R3ER-001. 목적은 import 이전에 `globalThis.performance`와 그 `now` 참조가 실제 노출되는지, 가능한 실제 시계값이 어떤지, `nodeRepl.write`의 작은 단일 영수증이 실제 전체 도구 반환봉투에 어떻게 나타나는지를 한 번 관측하는 방안을 설계하는 것이다. 영속 상태·합성 버퍼·모듈 import 없이 확인할 좁은 경로다.

현재는 이 Draft 한 파일 신규 작성1회·동일범위 문구 보정최대1회만 허용된다. 코드 후보 작성·평가·Node 호출·합성 청크 전달·파일 API·자식 프로세스·기존 상태 조회·reset·다른 파일 수정은0이다. 이 문서는 후속 구현이나 실행 권위가 아니다. SourceReady=false·accepted=false를 유지하며 본편 1챕터 완주·콘텐츠 진척으로 계산하지 않는다.

직접 판독한 `2026-10-16-m1-r3-nonpty-memory-capability-probe.md` §9 Approved의 REQ/AC-M1R3NC-009~010은 초기 진입 단조시계 및 실제 반환구조의 근거 부재에서 중단하도록 한다. Sol은 그 조건에 따라 네 후보를 작성하지 않고 반환했다. 해당 준비의 최초 판독/준비1묶음 사용·후보작성0·보정0과 기존 소진 이력을 보존한다. 이번 새 문서 예산으로 이전 준비/보정 예산을 복원하지 않는다. 그 네 후보와 기존 계약은 수정하지 않는다.

## 2. 두 정확 충돌의 한정 예외 제안

REQ-M1R3ER-002. 기존 fresh-run §11.1/12 및 framed 계약의 Node 금지, 능력 확인 계약 §9의 실행 예외 미발급과 충돌한다. 후속 승인에서 제안하는 예외는 아래 정확 후보로 `mcp__node_repl__js`를 최대1회 호출하여 두 표준 참조·시계값·영수증 반환을 관측하는 것뿐이다. 기존 전역 목록/상태/권위/수신기·원문·프로젝트 경로·도구 문맥의 다른 속성을 읽지 않는다.

능력 확인 계약 §9는 Root와 Node의 최초 진입 단조시계로 import 및 호출 사이 지연을 포함한30초를 요구한다. 아직 그 API 노출 근거가 없으므로 이번 사전관측 단계만 그 최초 단조시계·30초 증명을 선행시키지 않는 예외를 제안한다. 노출 여부를 확인하기 위해 미확인 시계를 이미 쓸 수 있다고 가정하지 않는다. import 뒤 원점을 잡거나 `Date.now`·UTC 벽시계를 단조시계로 대신하지 않는다.

이 예외의 시간 제약은 정확 도구 인수 `timeout_ms=5000`인 단일 호출뿐이다. 이 수치는 도구가 평가/큐/통신 전체를 실제5초 안에 강제 종료한다는 보장이 아니다. 최초 Root 단조시계·Node 단조시계에 의한 총경과30초 증거는 이 단계에서 미입증으로 명시한다. 이 단계의 단회 예외를3079바이트 시험이나53청크 전송으로 승계하지 않는다. 후속 전체 능력 확인은 Root와 Node 두 최초 시계의 구체 근거를 별도로 닫아야 한다.

## 3. 관측 대상과 효과 상한

REQ-M1R3ER-003. 실제 도구 설명은 `code` 문자열·선택 `timeout_ms`/`title`, `nodeRepl.write(value)`, 최상위 await/동적 import와 영속 바인딩을 명시한다. 해당 설명은 `globalThis.performance`나 write 결과의 정확 반환 배치를 보장하지 않으므로 이번에는 그 관측 자체만 제안한다. 관리 문맥의 물리 격리·런타임/호스트·프로세스 수·권한을 확인하지 않는다.

후속 코드 후보의 효과는 다음으로 제한한다. 외부에 영속되는 최상위 바인딩/속성/상태를 생성하지 않는 한정 지역 범위에서 `globalThis.performance`의 실제 종류를 확인한다. null/부재이면 그 사실을 기록한다. 사용 가능한 값이면 그 `now` 참조의 종류를 확인하고 함수인 경우 동일 수신자에 대해 최대2회 순차 호출한다. 원본 메서드·객체를 변경하거나 다른 시계로 대체하지 않는다. getter·메서드 접근/호출에서 오류가 발생하면 고정 오류분류만 기록하고 다른 속성을 더 탐색하지 않는다. 접근 자체의 외부 부작용 부재를 일반적으로 입증했다고 주장하지 않는다.

실제 유한 숫자가 반환되면 두 값과 비음수/비감소 여부를 영수증에 담는다. 같은 값은 정밀도 한계상 허용되는 관측이며 단조시계 부재로 단정하지 않는다. NaN/무한/숫자 아님은 구별한 고정 분류와 null 값으로 기록하고 JSON 변환으로 유효 숫자인 것처럼 바꾸지 않는다. 메서드 종류가 함수라는 사실만으로 정상 값 반환을 주장하지 않는다. import·타이머·sleep·루프 대기·파일/네트워크·프로세스 조회·random·합성 청크는0이다.

마지막에 고정 스키마의 작은 영수증 문자열1개를 `nodeRepl.write`로 최대1회 반환하는 후보를 제안한다. 시계 부재/오류도 같은 영수증 안에 분류하되 출력 재시도0이다. 출력 호출 자체가 실패하면 추가 console/write 없이 실제 도구 오류 원문을 반환받은 사실만 남긴다. 관리 커널/프로세스 종료를 요청하지 않는다.

## 4. 영수증·호출핀과 전체 반환 원문

REQ-M1R3ER-004. 영수증의 후속 고정 필드는 schema·새 nonce·performance 종류·now 종류·관측분류·숫자값0/1 또는 null·유한/비음수/비감소 판정 또는 미관측·accepted=false·끝표식이다. 허용 종류/분류/필드순서·숫자 표현을 정적 후보에서 고정한다. 실제 시계값은 변동 관측이므로 전체 영수증의 사전 고정 SHA를 발급하지 않는다. 대신 정적 스키마/허용 필드의 정확핀과 실제 반환 영수증 UTF8 길이/SHA를 분리한다. 기대값을 넣어 관측을 대신하지 않는다.

후속 code 원문은 UTF16/UTF8 각각4096 이하, 최종 도구 인수 JSON은 UTF8 8192 이하, 영수증은 UTF8 1024 이하를 제안한다. 수치는 이 좁은 관측의 설계 상한이며 실제 도구 보장/실측 길이가 아니다. 코드 원문·구조화 인수·새 nonce/attemptKey/authorityId·title·timeout_ms=5000·정확 호출문·각 길이/SHA는 별도 후보 작성 승인 뒤 고정한다. 현재 실제 후보 코드/식별자/호출핀은 미발급이다. 셸 명령행·파일 경유·후속 자동 분기0이다.

Root는 새 attemptKey의 실제 부재를 확인하고 호출 직전 정확 새 권위 소비를 먼저 기록하는 절차를 후속 후보에 고정한다. Node에는 지속 상태를 만들지 않는다. 실제 도구 반환을 받으면 텍스트 블록 선택/JSON 파싱/성공 판정 전에 전체 CallToolResult를 원래 반환 형태로 Root 메모리에 먼저 보존한다. content 전체·structuredContent·메타·오류 여부·예상 밖 블록을 포함하며 편의상 선택한 한 텍스트만 남기지 않는다. 구조화 원문과 도구가 제공한 실제 텍스트를 구별한다. 제공되지 않은 전송망의 원시 바이트를 보존했다고 주장하지 않는다.

Root는 원래 결과 참조를 유지하고 직렬화 가능한 실제 전체 결과만 별도 UTF8 표현/핀으로 결속한다. 직렬화/메모리 보존 자체가 실패하면 첫 실패와 그 사실을 기록하며 복구된 봉투를 꾸미지 않는다. 메모리 보존용 새 키/최초 상태/예외 경계는 후속 정적 제어 후보에서 결속해야 한다. 추가 보존 호출/디스크 기록 권위는 없다. 기존 도구 대화 기록과 Root 메모리에 실제 남은 증거 범위를 구분한다.

전체 반환의 예상 내용/블록 위치는 이번 관측 전에 고정 가정하지 않는다. 원문 선보존 뒤 실제 반환 content 배열의 모든 블록·종류·문자열·오류/절단 표식을 읽기 전용으로 대조한다. 명확한 단일 영수증과 그 전후의 실제 봉투 표현이 확인될 때만 후속 파서 규칙의 근거로 제안한다. 서로 다른 배치/추가 내용/응답 절단이면 관측 사실을 그대로 남기며 일반 텍스트 제거 규칙으로 성공 처리하지 않는다. 실제 선택/단일성 규칙은 사후 독립 판독/Astra 수용 뒤 후속 별도 범위에서 정한다. 이 단계는 모르는 반환구조를 이미 알고 있는 것으로 취급하여 실행 전에 차단하는 재귀 선행을 만들지 않는다.

Root 원문 보존의 제안 상한은 전체 도구 반환의 JSON 표현65536 UTF8바이트다. 이는 능력 확인 계약의4096 원응답 상한을 늘려 그 시험을 재개하는 조치가 아니라 봉투 자체를 처음 관측하는 이번 단계만의 별도 제안이다. 실제 원문이 상한을 넘으면 자르거나 부분만 저장하지 않고 관측초과/보존한계를 실패로 보고한다. 반환 원문 참조가 유지되는 동안 그 사실을 보존하며 디스크/추가 도구/다른 저장 경로로 우회하지 않는다. 메타나 상위 서비스가 자체 절단한 부분은 복구하지 않는다.

## 5. 단회·첫 실패·미완료

REQ-M1R3ER-005. 실제 실행을 후속 승인한다면 도구 호출최대1회·write최대1회·now최대2회·timeout_ms5000이다. 빈 상태조회·추가 호출·재전송·다른 커널·모듈 import·재시작·reset·kill·속성 삭제0이다. 실패 여부와 무관하게 최초 호출 착수 시 새 단회 권위가 소비된다. 남은 예산을 재시도 권위로 해석하지 않는다.

가능한 결과를 구분한다. 정상 작은 영수증이 돌아오면 실제 참조/값/반환 배치의 해당 표본만 관측한다. performance/now 부재·잘못된 값·접근오류도 정상적으로 보고된 부정/불확정 관측일 수 있으며 후속3079바이트 시험의 시계 관문은 닫히지 않는다. 도구 오류·timeout·응답유실·절단·메모리 선보존 실패는 첫 실패다. 실제 평가 완료/중단/관리 커널 종료는 확인한 내용만 적고, 무응답을 호출 미실행이나 프로세스 종료로 추정하지 않는다.

실제 응답이 없다면 없음/도구 오류 원문과 호출 착수·소비 사실만 기록한다. 응답 원문을 나중에 화면/기대 영수증으로 재구성하지 않는다. 늦은 평가가 남아 있을 가능성도 추가조회 없이 미완료/미관측으로 반환한다. 보존한 원문/첫 오류를 삭제하지 않는다. 이 시험은 영속 상태가 없으므로 커널 쪽 실패 잠금을 따로 기록했다고 주장하지 않는다. Root의 실제 보존 상태가 유일한 시도 원장 역할이며 프로젝트 원장 파일에 쓰지 않는다.

## 6. 관측 한계·선행·추적

REQ-M1R3ER-006. 성공해도 입증 범위는 해당 호출의 global performance/now 종류·가능한 두 실제 값·한 영수증의 실제 반환봉투뿐이다. 성능시계의 모든 미래 구간 단조성·물리 프로세스 동일성·Root 최초 단조시계·관리 서비스 timeout 취소·영속성·모듈·파일/호스트/권한·합성3079/실제154371 운송은 미입증이다.

다음 선행은 Luna의 이 문서 독립 설계판독/Astra 한정 호환 승인, 별도 코드 후보 작성의 정확 경로·예산, 실제 코드/인수/스키마핀·새 식별자·Root 원시 선보존 절차의 정적 독립 검수, Astra의 정확 사전관측1회 권위다. 현재 코드·식별자·권위와 실제 관측은 전부 미발급/미실시다. 실제 관측 뒤에도 Luna의 전체 반환 독립 판독과 Astra 수용을 거쳐 후속 시계/파서 근거로 사용할지 따로 판단한다. 막힌 네 후보 작성 재개나 기존 예산 복원을 자동 승인하지 않는다.
