## 정확 필드와 검증

`CurrentPreparationEvidence`는 필수 필드이며 정확 두 행의 배열이다. 각 행은 `Role`, `Path`, `Sha256`만 허용한다. 역할은 각각 `Preparation`와 `NegativeTests`, 경로는 정규화 절대 경로의 `output/q0-external-authority-evidence-r1/preparation-v2.json`과 `output/q0-external-authority-evidence-r1/negative-tests-v2.json`이다. 작업공간 기준 절대 루트는 기존 승인된 신뢰 호출이 고정한다. 상대 경로·다른 루트·v1 경로·중복/누락/미지 역할·링크 이탈·미지 필드와 비정규SHA는 거절한다. SHA는 대문자64자리이며 실제 원시 파일 SHA와 일치해야 한다. 호출자가 임의 외부 파일 두 개를 선택할 수 없다.

스키마는 위 형식과 정확 역할·경로 규칙만 규정하고 미래 v2 결과 SHA를 상수로 넣지 않는다. 검증기는 실제 두 파일을 읽어 원시SHA, 엄격 형식·준비/음성 역할·실제 결과·소스 집합/지문을 대조한다. 임의 `Passed=true`만 보고 성공하지 않는다. 최종 계획의 원시 SHA가 기존 서명 payload에 들어가므로 이 필드의 두 실제 결과 SHA도 서명에 결속된다. `CurrentInputRows`의 기존 빈값을 v2 결속의 대용으로 사용하지 않는다.

v2 준비 원장의20개 소스는 **키 없는 준비 최종 바이트**다. 실제 키의 공개값 고정 후 검증기 바이트만 바뀌는 원래 허용 전이는 별개로 보존한다. 최종 계획 `CurrentSourceRows`는 공개값 고정 뒤 현재20개를 가리킨다. 검증기는 나머지19개의 실제SHA가 v2와 같음을 대조하고, 검증기 한 개는 지정된 공개 modulus/exponent·지문·키 세대 자리의 대입만 허용한다. 준비 검증기의 해당 자리 원문과 고정 규칙을 v2에 기록하고, 현재 검증기를 그 정확 준비 자리 값으로 되돌린 원시 바이트 SHA가 v2 검증기 SHA와 같음을 확인한다. 임의 코드/공백/다른 상수를 바꾼 검증기는 이 허용 전이로 통과시키지 않는다. 현재 공개값은 실제 고정 키·세대와도 일치해야 한다. `source-freeze.json`은 이 전후 지문·대입 차이를 별도로 기록한다. 준비SHA와 공개값 고정 후SHA가 같다고 꾸미지 않는다.

## 비순환 작성 순서

1. 네 허용 소스의 의미 구현과 합성 시험을 완성한다. 단독 검증기/스키마/진행자에 미래 v2 SHA·계획SHA·자기SHA를 하드코딩하지 않는다.
2. 최종 키 없는20개 소스를 열거·해시한다. 기존 기한 보정의 실제 열린 입력 무응답/EOF/성공·정리와 기존 합성 회귀를 수행하고 최종 소스 지문에 결속한다. 추가 시험은 정확 두 역할/경로 정상, 누락/중복/경로교체/v1선택/원시 한 바이트 변조/소스 불일치/공개 자리 밖 변경 거절이다. 합성 결과는 메모리 입력 또는 기존 허용 시험 경로 안에서만 다루며 운영 경로의 v2 파일을 시험마다 생성·삭제하지 않는다.
3. 아직 부재인 정확 `preparation-v2.json`, `negative-tests-v2.json`을 최종20소스 SHA로 새로 발급한다. 두 파일은 자신의SHA·서로의 미래SHA를 내부에 요구하지 않는다. 둘의 관계는 같은 준비 식별자·정확20소스 지문으로 연결하고 실제 파일SHA는 다음 단계가 계산한다. 기존 허용 `docs/verification/2026-10-02-q0-external-authority-terra-report-v2.md`에 실제 결과와 두 파일SHA를 기록한다.
4. 루나가 최종 소스·실제 입력 기한 및 v2 바이트/결속을 독립 검수하고 아스트라가 준비 P1을 폐쇄해야 운영키 생성을 시작한다. 운영 계획은 그 뒤 실제 존재하는 v2 두 파일SHA를 읽어 `CurrentPreparationEvidence`에 넣는다. 운영키 공개값 대입 후 최종20소스와 허용 대입 전이를 재확인하고 source-freeze와 계획을 발급한다.
5. 서명 직전 두 증거·20소스·고정 검증기 지문을 다시 읽어 동일함을 확인한다. 실제 서명 검증에서도 같은 두 증거를 재대조한다. 나중에 두 증거가 바뀌거나 없어지면 계획 검증은 실패한다. 소스 수정이 다시 필요하면 이미 생성된 v2를 덮어쓰지 않고 정확 후속 경로를 아스트라가 별도 판단한다.

`AC-PLAT-066/068`은 누락된 결속을 실제 필수 필드·실제 파일/소스/서명 검사로 닫았는지 확인하며, `AC-PLAT-067`은 소스→v2증거→계획→서명의 비순환 순서를 확인한다. 이 계약은 실제 키/원격/서명을 지금 실행한 증거가 아니다. 기존 원격 정확 두 문서·가지와 미실행 계획의 `ExecutionAuthorized=false`를 유지한다. 이 추가 계약/증거를 원격 허용 집합에 자동 추가하지 않는다.
