## 4. Root 벽시계와 도구 timeout의 한정 제안

REQ-M1R3CE-004. Root의 Date.now 최초값은 새 권위 소비/의도 저장과 첫 도구 호출보다 앞에서 채취한다. 이후 각 호출의 의도 기록 전·직접 호출 직전·반환 원응답 선보존 직후·후속 호출 판단 전에 값을 기록한다. 응답을 받으면 원래 반환 참조 확보와 전체 메모리 선보존을 먼저 하며, 시계 관측/검사 실패가 원시 보존을 생략하게 하지 않는다. 호출 사이 사용자/서비스/제어 양보 지연도 이 벽시계 차이에 나타나는 범위에서 포함한다. UTC 도구를 추가 호출하여 시간을 보충하지 않는다.

값이 유한한 안전 정수·비음수가 아니거나 직전 관측보다 작거나 최초값보다 작으면 첫 실패다. 최초값과 차이가30000 이상이면 다음 호출/작업0이다. 양의 시계 점프도 연장하지 않고 상한 도달 시 실패시킨다. 관측 사이 시계가 변했다가 돌아오는 경우·벽시계가 느리게 가는 경우는 이 검사로 배제할 수 없다. 벽시계가 계속 증가했다는 표본을 단조시계 보장으로 표시하지 않는다.

도구 호출은 기존과 같은 초기화1·청크0/1 각1·완료1, 최대4회다. timeout_ms는 초기화10000·청크0/1 각5000·완료5000으로 제안한다. 합계25000밀리초로 기존15000/5000/5000/5000의30000보다5000 작다. 이5000은 관측/호출 간 처리 여지를 둔 설계 차이이며 실제 서비스 여유나 지연 실측이 아니다. 도구 timeout의 강제 중단/전체 실제 반환시간 의미는 미확정이다.

각 호출 전 Root 벽시계상 남은 시간이 해당 고정 timeout 이상이어야 호출한다. 부족하면 timeout을 임의 줄이거나 예산을 늘리지 않고 첫 실패/미완료로 끝낸다. 네 timeout 값은 후속 정확 후보/인수핀에 고정한다. Node 남은 시간과 Root의 남은 벽시계 시간을 서로 같은 원점처럼 비교하지 않는다. 두 쪽 각각의 허용 조건을 모두 통과해야 한다.

호출 뒤 벽시계가 마감을 넘었더라도 반환 원응답의 선보존은 해야 한다. 이 한정 증거 보존 외 후속 청크·성공 승격·추가조회는0이다. 원문 보존 후 마감 실패를 고정하며 이를 마감 내 호출 성공으로 소급하지 않는다. 실패/타임아웃 뒤 서비스가 뒤늦게 평가할 가능성을 제거했다고 주장하지 않는다.

## 5. 실제 표본에 근거한 반환봉투 검사

REQ-M1R3CE-005. 각 호출의 전체 CallToolResult 원문을 Root 메모리에 먼저 보존한 뒤 구조/길이/영수증을 검사한다. 기존 합성 시험의 원응답4096 UTF8바이트·영수증2048·Root 합계16384 상한을 유지한다. 사전관측의65536 한정 예외를 가져와 늘리지 않는다. 실제 원문이 초과하면 자르거나 일부를 정상 영수증으로 승격하지 않고 실패와 보존 한계를 보고한다. 원래 반환 객체 참조·가능한 전체 JSON 표현/실제 텍스트의 지문을 분리한다.

후속 합성 후보에서 수용할 봉투는 own enumerable 최상위 키 집합이 content,isError 두 개뿐인 JSON 객체, isError가 명시적 false, content가 길이1 배열인 경우로 한정한다. 유일 블록의 키 집합은 type,text뿐이고 type은 text, text는 문자열이어야 한다. 다른 블록/structuredContent/_meta/누락/알 수 없는 키·배열·오류 true·오류/절단 표식·서비스 예외는 첫 실패다. 사전관측 표본의 실제 삽입순서 content,isError와 type,text는 역사 원문핀에 그대로 보존한다. 향후 객체 키의 삽입순서 자체는 성공의 의미 조건으로 삼지 않고 정확 키 집합/타입/단일성을 검사한다. 봉투를 재정렬한 표현으로 사전관측 원문핀을 다시 주장하지 않는다.

text 내부 영수증은 새 합성 nonce·고정 schema·호출번호/단계·정확 수신량/청크·prefix/최종핀·실제 시계 관측·accepted=false·고정 끝표식을 모두 갖춰야 한다. 키/순서/타입·숫자 범위·허용 분류는 후속 정적 후보에서 고정한다. 실제 시계 숫자를 포함하므로 전체 영수증의 사전 고정 SHA와 정적 스키마핀을 혼동하지 않는다. 고정 규칙으로 파싱 후 재직렬화한 문자열과 실제 text가 완전일치하도록 설계해, 중복 키·임의 공백/앞뒤 텍스트·다른 숫자 표현·추가 JSON을 허용하지 않는다. 파싱 실패/부분 영수증/다른 nonce/순번·길이·핀 불일치이면 후속 호출0이다.
