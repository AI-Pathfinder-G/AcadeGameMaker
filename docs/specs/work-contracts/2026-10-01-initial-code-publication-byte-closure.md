## 입력과 판정 단위

입력은 원본 `artifacts/c3-initial-code-publication-candidate-files.json` 489경로, `artifacts/c3-initial-code-publication-byte-evidence-r2.json`의 직접 근거61·공백428, `artifacts/c3-initial-publication-gap-authority-index.json`의 문서 권한 분류, 최종 C4 동결 소스 원장·입력 목록, 실제 Approved 계약·독립 검수와 게시 직전 확인한 원격 기본 가지다. 기존 원장·실패 증거·승인 문서의 바이트를 다시 쓰지 않는다. 현재 C4 v19 원장의 Assets 33파일은 초기 후보와 21개가 겹치며 그중 10개는 초기 지문에서 달라졌고 12개는 후보 밖 신규 source/meta다. 이 숫자는 후속 최종 동결에서 재계산하고 불일치하면 승인 검토를 멈춘다.

각 후보와 신규 파일을 **정확한 한 경로**로 판정한다. 행에는 현재 SHA-256, 후보·과거 수용 SHA, 파일 종류, 조립·직접/전이 참조, meta GUID와 GUID 참조처, 실제 Approved 허용 파일·줄·상태·REQ/AC, 독립 검수의 정확 파일 지문, 원격 기본 가지의 존재/바이트, 포함·제외 판정과 사유를 기록한다. 문서의 파일명 언급, 폴더/조립 허용, 부모 파일의 승인, 같은 이름의 다른 파일, source의 승인으로 meta를 승격하지 않는다. 상태는 `현재 바이트 직접 입증`, `정확 변경 승인 필요`, `문서 출처만 확인`, `출처 미입증`, `게시 제외`를 분리한다. `현재 바이트 직접 입증`도 게시 승인과 다르며 승인 전 `PublicationApproved=false`다.

2. `ProjectSettings` 10파일과 직접 근거 공백인 실행 자산 17파일을 파일별 승인값·패키지 버전·씬/프리팹/입력 자산의 GUID 전이로 닫는다. `Renderer2D`의 미해석 GUID 7개는 엔진/패키지 제공 자료 가능성을 포함해 실제 import 진단으로 출처를 판정한다. 해석 전에는 결손·무영향·빌드 성공으로 단정하거나 설정 전체를 포함하지 않는다.
