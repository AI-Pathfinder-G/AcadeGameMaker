## Purpose and boundary

M5D7M is the bounded desktop startup owner that captures the Unity profile root and UTC once, reserves the existing `InputRouter` against legacy fallback, calls M5D7L once, transfers the prepared disabled `GameInputActions` into that router exactly once, and initializes the already-authored M5B5 graph in `UIOnly`. After successful initialization it publishes one immutable hub-entry-ready handoff receipt and zero or one typed notification payload.

This slice does not create or load a hub scene, prove that a hub exists, find objects, establish UI hierarchy/focus/menu ownership, relax the M5B5 graph, render UI, localize prose, log, retry persistence, save again, inspect devices, enter gameplay mode, or mutate profile/run/narrative state. “Hub-entry-ready” means only a validated `UIOnly` router handoff receipt with a current in-memory profile. A later authored-scene/UI contract performs actual entry and consumes that receipt. If a hub scene cannot supply the complete existing Movement/Transfer/Combat/Camera graph required by M5B5, this unit stops; it does not invent a lighter router.

## Router reservation and ownership lifecycle

`InputRouter` receives additive internal launch seams backed by one private closed state machine:

`Unreserved → Reserved(owner) → Adopted(owner, actions) → InitializedPendingPublication(owner) → Initialized`

`Reserved`, `Adopted`, or `InitializedPendingPublication` may instead become terminal `Failed`. The state binds the exact `(owner, actions)` pair where applicable. Unknown/default/reflection-corrupted states, illegal field matrices, a null owner/actions, a foreign owner, duplicate transition, late reservation, enabled candidate, or state/field mismatch throws before mutation.

The adapter retains `[DefaultExecutionOrder(-220)]` and the existing router remains `-210`, but correctness never depends on relative `Awake` order. Unity completes every active cohort `Awake` before any `Start`; within that cohort either component may awaken first. Router `Awake` only records private `_awakeEntered` proof and validates the closed field matrix. It allocates no actions, registers no callbacks, initializes no graph, and enables no map. Reservation/adoption is legal either before or after router `Awake`, but only before router `Start`, default action allocation, callback registration, or any initialization. Reservation remains mandatory before preparation: a failed prepared launch must suppress later legacy fallback.

Router `Start` validates before mutation, records `_startEntered` once, and uses an explicit switch over every defined state. `Unreserved` calls one private `EnsureLegacyActionsAndCallbacks`, then performs the existing legacy `Initialize`. `Reserved` at `Start` is an abandoned preparation and becomes terminal `Failed` with exact prepared fault stage `Closed`, without allocation or fallback. `Adopted`, `InitializedPendingPublication`, `Initialized`, and `Failed` allocate nothing and perform no fallback; an `Adopted` router reaching `Start` before adapter `Start` remains inert rather than failing, so the adapter may complete prepared initialization afterward. `InitializeForTests` requires router `Awake` to have entered, and on `Unreserved` uses the same ensure helper before initialization; it rejects before `Awake` and remains forbidden for every prepared state. `InitializePreparedHub(owner)` is the sole legal `Adopted → InitializedPendingPublication` transition; it requires router `Awake` to have entered, validates the exact active/enabled owner/actions and pristine callback/map state, registers callbacks on the exact adopted wrapper, performs the existing M5B5 initialization in `UIOnly`, and closes on failure. `ConfirmPreparedHubPublication(owner)` alone performs the prechecked non-allocating `InitializedPendingPublication → Initialized` assignment. `FailPreparedHubLaunch(owner)` accepts the exact owner in every prepublication state including `InitializedPendingPublication`, sets the router faulted, and closes initialized maps/actions.

`EnsureLegacyActionsAndCallbacks` is callable only in pristine `Unreserved`; it creates the legacy wrapper and registers callbacks exactly once. The existing authoring configuration seams (`ConfigureForAuthoring` and `ConfigureTerminalTeardownForAuthoring`) may operate after router `Awake` only while the router remains healthy `Unreserved`, unstarted, uninitialized, action-free, and callback-free. They remain forbidden after `Start`, reservation, allocation, callback registration, initialization, failure, or disposal. `InitializeForTests` is not a configuration seam: after `Awake`, a healthy uninitialized `Unreserved` router uses the shared legacy initialization path, while an already validly initialized healthy legacy router validates and returns without allocation, callback registration, map transition, or other mutation. It remains forbidden in every prepared, faulted, or disposed state.

One private pure central validator owns the complete stable state-field matrix and runs at entry and committed exit of `Awake`, `Start`, reservation, adoption, prepared initialization, publication confirmation, prepared failure, test initialization/configuration, update/test-step, and teardown seams. It rejects undefined state/fault-stage values and every mismatched owner, actions, callbacks, closed, initialized, faulted, disposed, awake/start, mode, or map combination. Stable rows are: pristine or initialized/faulted legacy `Unreserved` with no prepared owner; pre-Start `Reserved` with owner and no actions; disabled adopted `Adopted` with exact owner/actions and no callbacks; exact `UIOnly`/UI-enabled `InitializedPendingPublication` with owner/actions and both callbacks; historical live/faulted/disabled/destroyed `Initialized` whose later M5B5 mode may differ from the receipt snapshot; and terminal `Failed` with non-null owner, faulted true, no actions/callbacks/maps, closed true, and a defined non-None prepared fault stage. Before router `Awake`, initialization, callbacks, and `Start` are impossible. `_startEntered` implies `_awakeEntered`; partial callback registration is observable only inside its guarded try/catch.

Invariant failure uses one best-effort cleanup wrapper that preserves and propagates the original invariant exception. A corrupt `_actionsClosed` flag never prevents cleanup when actions or callback flags remain: the exact held object is disabled, callbacks are removed best-effort, disposed once, nulled, and both flags cleared. Unknown/corrupt enum or owner evidence is not normalized or invented. Legacy callback-allocation failure stays ownerless `Unreserved` under the existing M5B5 fault path; it must not create an ownerless prepared `Failed` row.

Adoption is an explicit all-or-nothing ownership boundary. It validates the disabled wrapper before mutation. Before successful `AdoptPreparedHubActions(owner, actions)`, the caller owns the candidate. On success the router is the sole owner. A rejected adoption leaves ownership with the caller. The allowed router change adds private ownership/callback flags and one idempotent `CloseActionsOnce`: best-effort disable, remove each registered callback set at most once, dispose the exact wrapper at most once, null it, and mark it closed while preserving an already-propagating exception over cleanup exceptions. Legacy disable→destroy and prepared failure→disable→destroy use this same closure without duplicate unsubscribe/dispose. Adapter cleanup never disposes router-owned actions.

The adapter records a local `reservationAcquired` proof. Only the exact owner that acquired reservation may call `FailPreparedHubLaunch(owner)`; a foreign/duplicate reservation failure performs zero preparation, take, adoption, or closure against the legitimate owner. If its own failure occurs before adoption, it disposes the token/candidate exactly once and fails its reservation in `finally`. If failure occurs after adoption but before a successful receipt, it tells the exact router owner to enter `Failed`; the router closes its adopted actions exactly once. Adapter `OnDisable`/`OnDestroy` before receipt and router `OnDisable`/`OnDestroy` while `Reserved`, `Adopted`, or `InitializedPendingPublication` perform the exact owner-bound abort: enter `Failed`, disable both maps, close the exact actions/callback ownership once, and leave no receipt or notification. After receipt, disabling/destroying only the adapter never tears down the initialized router. A failed adapter instance never retries. Router legacy startup remains behavior-compatible when no reservation occurs.

## Adapter API and exact sequence

New internal `DesktopProfileLaunchAdapterV1 : MonoBehaviour`, explicitly serialized to one `InputRouter`, exposes:

```csharp
internal DesktopProfileLaunchReceiptV1? CurrentReceipt { get; }
internal bool TryTakeNotification(out ProfileLaunchNotificationV1 notification);
internal InputRouter BoundRouter { get; }
```

It uses fresh instance-scoped environment and preparation ports. Production environment reads only `Application.persistentDataPath` and `DateTimeOffset.UtcNow`; production preparation delegates only to `ProfileLaunchPreparationCoordinatorV1.Prepare`. There is no static mutable service locator or test hook.

Exact lifecycle:

1. `Awake` validates one exact active/enabled router in the same lifecycle cohort, pristine pre-`Start` state, and authored `InputMode.UIOnly`; calls `ReservePreparedHubLaunch(this)` and records local ownership before any preparation authority. Router `Awake` may already have entered, but router `Start`, default allocation, callback registration, and initialization must not have entered.
2. Perform literal port order `Reserve → GetPersistentDataPath → GetUtcNow → Prepare`. Capture each environment value once, validate the fully qualified non-root path and zero-offset UTC before Prepare, and pass both exact values to M5D7L once.
3. Validate the returned token and `HubEntryAllowed`; defensively copy its immutable evidence/document into a pending receipt projection.
4. Call `TakeActions()` once. Adopt that exact disabled object through the reservation owner. Dispose the transferred token without touching the adopted object.
5. Router `Awake` records lifecycle entry only. Router `Start`, regardless of whether it occurs before or after adapter `Start`, performs no allocation or fallback while any prepared state is present.
6. Adapter `Start` calls `InitializePreparedHub(this)` once. The router registers callbacks on the exact adopted collection, delegates the existing M5B5 initialization/preflight, enters `InitializedPendingPublication`, and returns an immutable internal `PreparedHubInitializationProofV1` containing only the bound owner identity for immediate comparison, `InputMode.UIOnly`, `GameplayEnabled=false`, `UiEnabled=true`, callbacks-registered evidence, and initialized-pending-publication evidence. It exposes no actions reference. The proof validates its closed field matrix from every getter. The adapter validates the returned owner against itself and snapshots only mode/map facts into the receipt.
7. Only after exact router/UI/map evidence succeeds, construct and fully validate the receipt and optional notification in locals. Call `ConfirmPreparedHubPublication(this)` after all fallible staging and validation; this performs only the prechecked non-allocating pending→initialized state assignment. Commit the optional notification by non-throwing assignment, then assign `CurrentReceipt` last. No call, validation, Unity read, or other fallible operation follows receipt publication. Router `Start` later performs no second initialization.

Every preparation, reservation, adoption, callback registration, initialization, proof, receipt, notification, or prepublication-confirmation exception yields no receipt and no notification, closes ownership exactly once, leaves both maps disabled, suppresses legacy fallback, and propagates. Typed M5D7L preservation/save failure is not an exception: its verified in-memory token still reaches `UIOnly` with `PersistencePending=true`.

## Receipt and notification model

`DesktopProfileLaunchReceiptV1` is an immutable, fail-validating projection containing exact M5D7L source/source revision/final revision/final document/recovery reasons; exact initial binding outcome/failure/disposition and final binding outcome/failure/disposition; preservation states, `MayPersist`, stopped role and derived `AnyPreservationAttempted`; save kind/persistence outcome and stage/stored states/committed revision/pending evidence; plus snapshot `InputMode.UIOnly`, `GameplayEnabled=false`, `UiEnabled=true`. `AnyPreservationAttempted` is true exactly when any role state is `Preserved`, `SourceMissing`, `FailedBeforeMove`, or `MoveOutcomeUncertain`; `NotAttempted` and `NotRequired` are not attempts. The receipt contains no live router reference; adapter `BoundRouter` provides non-historical authoring identity. It retains no path, clock, mutable actions, exception, callback, UI object, scene, or prose. Every getter revalidates all cross-field relations against a defensively independent final document and closed evidence, never against later live map state.

`ProfileLaunchNotificationKindV1` is closed:

- `RecoveryCompleted`
- `RecoveryArtifactPreservationFailed`
- `PersistenceDeferred`

`ProfileLaunchNotificationV1` is immutable and fail-validating; every getter calls `Validate`. It stores the exact typed source/recovery, initial/final binding, preservation, and persistence correlation evidence sufficient for a later presentation owner. Its kind must equal the priority function of that stored evidence. Default/unknown kind, missing or mismatched correlation fields, or an impossible row rejects. It contains no filesystem path, exception text, timestamp, localized prose, or action reference.

The notification is constructed only from the same already-validated local receipt projection. Field equality is exact for Source, SourceRevision, FinalRevision, FinalRecoveryReasons, every initial/final binding outcome/failure/disposition, every preservation state/MayPersist/stopped role/attempted flag, SaveKind, PersistenceOutcome/Stage, all stored states, CommittedRevision, and PersistencePending. Its validator re-derives the notification kind from those fields and the receipt validator uses the same closed correlation routine. Reflection mutation of each correlation field must fail; a notification cannot be paired with a different otherwise-valid receipt.

At most one notification is synthesized with strict priority:

1. `PersistenceDeferred` when `PersistencePending=true`.
2. otherwise `RecoveryArtifactPreservationFailed` when preservation `MayPersist=false`, including direct-current/no-save preservation failure.
3. otherwise `RecoveryCompleted` when source is not Primary, recovery reasons are nonzero, initial binding outcome is `RecoveryRequired`, or `AnyPreservationAttempted=true`.
4. otherwise no notification.

`TryTakeNotification` returns only a prevalidated pending typed payload exactly once; subsequent calls return false and a default output. Absence always returns false with the same default output. Notification consumption never mutates the receipt, profile, router, scene, or persistence state.

## Test seams and deterministic proof

Tests configure an inactive object before any `Awake` with fresh instance environment/preparation ports; production uses stateless wrappers. Tests never write to real `Application.persistentDataPath`. An isolated root and fixed UTC are forwarded to real M5D7L integration. Ports record exact calls and object identity, not just counts.

Narrow deterministic fault injection may use closed internal enums and instance-only setters for the prepared-launch callback-registration boundaries and adapter post-initialization proof/receipt/notification staging boundaries. No arbitrary callback, delegate, static mutable hook, production behavior switch, or external fault API is allowed. Each injected stage throws one fixed test exception at the exact production check point and is covered by cleanup/original-exception assertions.

Exact closure attempts may be observed only through private reflection-read diagnostics in `InputRouter`: last closed actions identity and integer counts for action dispose, Gameplay unsubscribe, and UI unsubscribe attempts. Each field is assigned/incremented immediately before the corresponding real best-effort operation, has no getter, delegate, branch, reset, service locator, or production behavior effect, and exists solely to prove REQ-M5D7M-003 exact-once cleanup.

Adapter outcome rows construct no handwritten `PreparedProfileLaunchV1`. A deterministic preparation port calls the real M5D7L coordinator overload once with scripted lower profile/actions ports, producing legal clean-current, default-bootstrap, previous-promotion, metadata-decode-repair, binding-decode-repair, binding-apply-repair, preservation-denied, save-failed-before-commit, and save-commit-uncertain tokens. Default/current/previous/decode-repair smoke rows additionally use isolated real filesystem roots; OS permissions/locks are never used to synthesize failures. Instance ports record exact root/UTC/Prepare and M5D7L Create/apply/discard operations with their values and candidate identities. Reservation is observed as already acquired at the first environment read. Take/adopt are proved by the retained token reference, rejected re-Take, unchanged post-transfer M5D7L disposer count, and the router holding the exact final candidate identity. Because transferred-token `Dispose()` is intentionally behavior-free and exposes no observation seam, its lexical occurrence after successful adoption is proved by static source inspection; router-owned final closure is proved independently by the approved private reflection-only attempt counters. Notification priority separately covers persistence+preservation+recovery overlap, clean-current preservation failure, successful recovery, and clean-current absence.

A valid M5D7L token always has `HubEntryAllowed=true`; therefore no valid “denied token” can be produced within this sealed API. The adapter must retain its defensive check, while tests cover preparation throw, null, and reflection-malformed token; valid denied-token execution is recorded N/A rather than fabricated. “Reused action” means same-router duplicate adoption, retake after transfer, or the discarded first candidate in binding-apply recovery; cross-router global ownership is not claimed because no global registry exists. “Same lifecycle cohort” means both exact serialized components are enabled and active-in-hierarchy before router `Start`; it does not add common-parent, scene, or topology identity authority.

The focused PlayMode matrix must cover legacy router behavior, every legal/illegal reservation field transition and reflection corruption, preparation failure before and after router `Awake`, exact adopted identity through callbacks/maps/disposal, M5D7L default/current/previous/decode-repair/apply-repair/typed preservation/save outcomes, notification correlation/priority and one-shot consumption, and lifecycle failures at reservation/preparation/take/adoption/callback-registration/initialize. Combined evidence must prove the exact `Reserve → root → UTC → Prepare → Take → Adopt → transferred-token Dispose` sequence. Instance ports record root/UTC/Prepare and M5D7L candidate operations; the first environment read asserts that the exact router is already Reserved. Runtime state and identity assertions prove successful one-shot Take and adoption of the exact final candidate, rejected re-Take, and zero candidate disposal by the M5D7L disposer after transfer. Static inspection proves the behavior-free transferred-token Dispose remains lexically after adoption. Approved router reflection-only counters prove exact final unsubscribe/dispose attempts and identity. No single port is required to observe operations outside its authority. Single-field reflection rows must cover every stable state's owner/actions/callback/closed/initialized/faulted/fault-stage/awake/start correlations, pending mode/maps, an unknown state in `Awake`, and an unknown state injected after `Awake` before `Start`; each rejects and closes without fallback or receipt. Four real lifecycle permutations—same GameObject router-added-first, same GameObject adapter-added-first, separate objects router-created-first, and separate objects adapter-created-first—must all converge successfully. It also proves router `Awake` alone remains action-free; legacy `Start` and post-`Awake` `InitializeForTests` allocate/register once while pre-`Awake` `InitializeForTests` rejects without allocation; `Reserved` at `Start` fails closed; router `Start` before adapter `Start` in `Adopted` remains inert and later prepared initialization succeeds; adapter-first initialization makes later router `Start` a no-op; reservation after legacy `Start`/default allocation or test initialization rejects; preparation failure after router `Awake` stays terminal without fallback; callback fault cleanup is exact; every prepublication disable/destroy row including `InitializedPendingPublication` closes without receipt or fallback; competing adapters do not corrupt the winner; and notification overlap priority is complete. Bounded asynchronous/lifecycle waits must assert completion.

## Requirements

- **REQ-M5D7M-001:** capture one exact desktop profile root and zero-offset UTC and forward them to one M5D7L preparation.
- **REQ-M5D7M-002:** reserve the router before preparation and before legacy `Start`/default allocation so every failed prepared launch suppresses legacy default-action fallback independent of relative `Awake` order.
- **REQ-M5D7M-003:** transfer one exact disabled prepared actions collection into the reserved router with a closed, exact-once ownership lifecycle.
- **REQ-M5D7M-004:** initialize only the existing valid authored M5B5 graph in exact `UIOnly`, enabling only UI and publishing no gameplay input.
- **REQ-M5D7M-005:** publish a fail-validating immutable hub-entry-ready receipt only after successful adoption/router initialization and prepublication confirmation while preserving every typed M5D7L evidence field.
- **REQ-M5D7M-006:** expose zero or one typed launch notification under the fixed priority and exact-once consumption rule.
- **REQ-M5D7M-007:** allow typed preservation/save failure to reach a safe UI-only receipt without retry, fallback save, or data-loss claims.
- **REQ-M5D7M-008:** fail closed on every protocol/programmer/lifecycle exception with exact cleanup, no receipt/notification, no enabled map, and no retry.
- **REQ-M5D7M-009:** preserve M5B5 legacy behavior and add no scene lookup/load, hub topology, UI rendering/prose, logging, device, gameplay, save, profile transform, run, narrative, network, or RNG authority.
