## CH1 첫 연결 단계의 전달물

아래6요소는 CH1의 기반 검증 단계다. 최종 사용자 전달은 CH1 계약의 도입·원정·양분기·봉쇄선·세령·종료까지 포함한다. 단일 전투로 최종 목표를 대체하지 않는다.

1. 실행 파일 시작부터 조작 가능한 한 장면에 진입하는 경로.
2. 플레이어·적·지형을 구별하는 승인된 표현과 조작 안내.
3. 기존 이동·점프·대시·무게 전이·기본 공격을 연결한 한 이동/전투 구간.
4. 체력·피격·성공/실패 결과를 실제 화면에서 확인하는 표시.
5. 성공과 실패 뒤 같은 구간을 새 상태로 재시도하는 경로.
6. 정확 소스/장면이 들어간 빌드, 실행 방법, 루나의 독립 실행·실제 플레이 증거.

미수용 시안·합성 외형을 최종 아트로 승격하지 않는다. 식별용 임시 표현이 필요하면 한정 체험 계약에서 용도·표시·권리·별도 종료 조건을 명시 승인받으며 캐논 외형 완료율에 합산하지 않는다. 실제 기존 미디어를 쓸 수 있으면 이를 우선한다.

전체 데모의 방6·런4·선택·기술2·12~18분·성공/실패 AC는 유지한다. 본편8챕터/진보스·옷장432조합은 첫 체험에 실제로 필요한 기본 패키지 이상을 자동 선행으로 묶지 않는다. 세령의 첫 등장/기본 의상 수용은 전체 데모 단계의 해당 기준에 따른다.

## 개선 요구사항

### 본 개발을 이어가는 운영 원칙 — 2026-10-08 사용자 지시

사용자가 본 개발을 최대한 탄력적으로 진행하도록 프로세스 점검·변경을 지시했다. 아래는 앞으로 적용할 절차이며 과거 실패·동결 계약·이미 소비된 실행 권한을 소급 변경하지 않는다. 프로젝트 승인과 실제 도구/운영체제 권한은 별개다.

1. **한 기능 묶음, 한 승인 계획:** 아스트라는 사용자 행동·허용 쓰기 경로와 단일 소유·인터페이스/저장 경계·영향 REQ/AC·검사/예산·재실행/정지 조건을 한 계획에 정한다. 솔은 이 범위 안의 구현·내부 리팩터링·국소 오류 수정·검사 준비를 연속 수행한다. 요구 행동·권한·지속 데이터·공유 계약을 바꾸지 않는 보정마다 새 계약/승인 문서를 발급하지 않는다. 참조 추가/가시성 변경 등이 실제 인터페이스나 접근권을 늘리는 경우는 작은 줄 수라도 경계 변경으로 분류한다.
2. **로컬 개발 실행도 묶어서 계획:** 앞으로의 로컬 묶음에는 필요한 컴파일·집중 검사·국소 보정 후 재확인을 처음부터 유한 실행 예산 안에 포함한다. 정상 개발 실행까지 모두 단회로 지정하여 실패마다 새 권한 문서를 만드는 관행은 기본값으로 삼지 않는다. 솔이 실행할 작업과 Root 전용 작업, 도구 심사·환경·실제 동의가 필요한 경계를 명시한다. 기존 단회 계약/Root 전용/미발급 실행은 그대로 지키며, 그 범위의 탄력 운영 호환 부록을 한 번 승인한 뒤에만 새 계획으로 이동한다. 이번 절 자체는 새 native/Unity/GUI 실행 권한이 아니다.
3. **실패는 경로를 좁혀 고친다:** 첫 실패의 원시 결과를 보존하고 영향받는 입력/컴파일/행동만 최소 재현·수정·재확인한다. 같은 원인 두 번이면 큰 검사를 멈추고 원인을 먼저 확인한다. 이는 모든 본 개발의 중단이나 작은 원인 분석의 중단이 아니다. 필수 회귀는 기능 묶음의 안정된 최종 바이트에서 수행하고 중간 보정마다 전체를 다시 돌리지 않는다. 변경된 입력/소비자에 필요한 증거만 무효화하며 영향 없는 수용을 일괄 취소하지 않는다.
4. **문서는 작업 원장 하나로:** 묶음별 기존 원장에 변경·실패·새 입력 지문·REQ/AC·결과를 추가한다. 원시 결과는 도구가 기록하고 독립 검수용 최종 제출에서 적용성을 결속한다. 보조 보고/승인 문서의 지문이 바뀌었다는 이유만으로 제품 소스나 시험을 다시 실행하지 않는다. 새 실행이 실제 소비하는 소스/자산/설정/도구/계획/권위만 결속하고, 검수 문서가 새 검수 문서를 끝없이 요구하는 재귀 의존을 만들지 않는다. 기존 정확 핀 계약을 임의로 줄이지 않으며 필요한 호환은 해당 묶음에서 한 번 닫는다.
5. **막힌 작업만 대기:** 앱 동의·환경/도구 심사·게시 권한 때문에 실제 플레이가 막혀도 그 경로와 충돌 없는 기승인 콘텐츠/소스 구현·후속 설계·장면 준비는 이어간다. 공유 파일은 단일 쓰기 소유, 아직 없는 API의 소비자는 준비 사본과 제품 통합을 구분한다. 의존을 제거했다고 주장하거나 가짜 입력/완주 증거로 대신하지 않는다. 도구 동의·스킬의 실제 제한을 우회하지 않는다. 새 도구 개발이 필요하면 막는 제품 행동과 가장 작은 수단·종료 조건부터 고정하며 게임 개발 전체를 검증 도구 개발로 치환하지 않는다.

독립 검수는 M1/M2/M3 제출 시점에 모으고 지적은 같은 목록에서 영향 범위만 보정한다. 루나의 전반 재검수는 새 변경/실패/미해결 영향이 있을 때만 확대한다. 아스트라의 통합 승인은 최종 묶음의 제출물과 실제 증거에 결속한다. 승인 없는 기능/새 저장 권한·캐논 변경·키/서명·Q0 인간 승인·세대·기존9회·원격 게시와 정식 도구 심사/앱 동의는 면제하지 않는다. 진척 감사는 일일08시와 별도 사용자 요청만 유지한다.

실제 아스트라는 사용자 개선 지시·문서 직접 검토·루나의 중대 결함 없음 판정 및 보정을 근거로 Review→Approved, ADR-0039 proposed→accepted 전환과 감사03의 근거 수용을 허용했다. 다음 주력은 P0-LOCAL 의존 조사와 한정 제품 계약 설계다. 검토 시점 전략 지문은 `F36A2CA639E413B467E81F6D1632EEDC7FD0CA247B942311F7F256348413CACE`였고 상태/승인 기록 추가 후 지문과 구별한다. 기존 Q0 인간 승인·새 세대·키·서명·공개문서 게시/병합·9회 실행 권한은 그대로 별도다.
