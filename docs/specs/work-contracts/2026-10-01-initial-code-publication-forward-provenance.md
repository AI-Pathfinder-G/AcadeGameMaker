## 새 기준의 정확한 집합과 시점

새 출처 기준의 **후보 집합**은 위 501파일 원장 `Files[]`의 정확 고유 경로 501개 및 각 `CurrentSha256`다. 이는 원래 후보489와 C4 신규12의 합집합이다. 경로의 대소문자·구분자·확장자·meta 짝을 보존하며 폴더, 비슷한 이름, 조립 전체를 묵시적으로 추가하지 않는다. 기준 후보는 C4 v19 source manifest SHA-256 `980443316BFB2DC008B611FF948259200C3913C1B3C7F8C5DE6CE62D1511B595`와 input list SHA-256 `274F49B6E0D77C51636FA866DC1EB87321DF64B5AEFB4B8189D8B2DE4DC71F1C`에 결속한다. v19가 포함하지 않은 후보도 501원장 행의 정확 SHA를 기준으로 삼는다. 501행은 현재 게시 허용 목록이 아니며 모두 `PublicationApproved=false`다.

계약 승인 뒤 실제 조사 시작·종료 UTC 시각, 501원장·v19 문서 SHA, 각 경로의 조사 전·후 실물 SHA를 **새 기준 스냅샷**으로 기록한다. 501개 경로·SHA 중 하나라도 선행 원장의 값과 다르거나 누락·중복되거나 조사 전후 값이 달라지면 기준 발급을 멈추고 아스트라에 보고한다. 기준 시각 구간은 앞으로의 검증 기준이며 과거 구현 시점으로 소급하지 않는다. 조사 도중 바이트가 달라져도 새 값을 조용히 대체하지 않는다. 필요한 경우 별도 승인된 기준 개정과 새 지문 원장을 요구한다. 모든 행은 원본 후보 SHA, 새 기준 SHA, v19 적용 여부, 파일 종류, 향후 조사 결과를 분리해 보존한다.

역사 자료는 별도 축이다. 원래 489 후보의 직접 근거61·공백428, 현재 동일 지문60, C4 기존 변경10의 관측 전이14와 열린 간격14/14, `ChainClosed=0/10`을 원문 상태로 연결한다. 원래 후보 바이트와 14개 전이 구현 바이트가 없다는 사실을 새 기준이 지우지 않는다. 새 기준의 파일별 검증이 성공하더라도 과거 승인 범위에 바이트를 소급 귀속하거나 과거 사슬을 `Closed`로 표기하지 않는다. C4 신규12는 원래 489 후보가 아니었다는 출처를 유지한다.

## 읽기 전용 파일별 독립 출처 조사

각 행은 `Path`, 원장·실물 `Sha256`, 새 기준 시각, 원래 후보/역사 사슬 상태, 파일 종류, 소유 조립·정확 `asmdef` 참조, 짝 meta/GUID 소유와 참조처, 자산·프리팹·장면 의존, 사용 패키지·설정 값, Approved 정확 경로·변경 범위·문서 SHA·줄·REQ/AC, 현 바이트의 독립 검수 근거, 원격 기본 가지의 조회 시점·커밋·존재·바이트, `ForwardEvidenceState`, `InclusionCandidate`, `ExclusionReason`, `PublicationApproved=false`를 기록한다. 문서의 파일명 언급, 기능 수용, 같은 조립의 다른 파일, 이전 SHA 승인 또는 시험 통과만으로 현재 파일 바이트의 출처를 승인하지 않는다. 확인 불가 값은 `미입증`으로 남기고 통과값으로 채우지 않는다.

먼저 기존 변경10은 새 현재 바이트 자체의 Approved 요구 적합성과 독립 검증을 수행한다. 과거 14간격의 부족은 유지한다. 신규 C4 source/test6 및 meta6은 최초 생성 경로·정확 허용 방식·현재 SHA·GUID/짝 source/조립을 따로 검증한다. meta6의 [현재 바이트 제한 수용](../../approvals/2026-10-01-c4-meta6-exact-byte-evidence-limited-acceptance.md)은 실제 경로·SHA 검수 근거로 사용하되 전체 이전→현재 사슬이나 게시 수용으로 확장하지 않는다. C4와 겹치는 나머지 동일 지문 파일, C3 도구2, 원래 직접 근거61도 원본 역사 지문과 새 현 바이트 검증의 차이를 유지한다.

원래 428공백은 실행 자산17, 최소 설정10, 조립파일154, 파일 meta190, 폴더 meta36, QA 도구·선택 원장13, Q0 직접 읽기 문서4, 실제 선택 외부 작업자2, 감사 선행 원문1, 패키지·바이트 기반1로 분리한다. 이것은 **역사 공백의 분류**다. 새 501후보 전체의 파일 종류는 실행 자산20, 설정10, 조립파일188와 신규 C4 소스6, 파일 meta208·폴더 meta40·신규 C4 meta6, 패키지·바이트 기반3, QA 도구·선택 원장13, Q0 문서4, 외부 작업자2, 감사 원문1이다. 특히 meta248과 신규 meta6, 패키지 관련2와 별도 바이트 기반1을 빠뜨리거나 C4 source manifest193으로 501 조사를 축소하지 않는다. 각 경로를 새 기준에서 실제 내용·사용처·Approved 범위·독립 현 지문 검수로 닫거나 명시적으로 제외한다. `Renderer2D`의 미해석 GUID는 엔진/패키지 출처일 가능성과 실제 미해석 상태를 구분한다. 미해석을 결손·무영향·빌드 성공으로 단정하지 않는다. `Packages`와 잠금 자료의 실제 버전, `ProjectSettings`의 정확 값과 자산/조립 참조, `asmdef`·친구 조립·패키지 의존이 501 안에서 닫히는지도 검사한다. 누락 의존은 자동으로 501에 추가하지 않고 별도 범위 결정 후보로 보고한다.

원격 기본 가지는 선행 원장의 옛 스냅샷을 재사용하지 않고 읽기 전용으로 새 조회 시점·정확 커밋/트리·각 후보의 blob 식별자와 실제 SHA-256·존재 여부를 기록한다. 이 조회는 원격 수정이나 게시가 아니며, 실제 게시 직전에 다시 확인해야 한다. 현재 원격과 다른 동일 경로는 정확 바이트 차이와 소유·병합 충돌을 파일별 판정하고, 덮어쓰기 승인으로 간주하지 않는다. 원격 조회가 허용되지 않거나 실패하면 `미조회`로 남겨 파일별 승인과 게시 게이트를 멈춘다.
