# Q0 실행 권위의 전용 발급 제어 도구

상태: **Approved** — 2026-10-03 실제 `gpt-6-astra`의 한정 구현 승인. `REQ-PLAT-068/069/070`, `AC-PLAT-066/067/068`의 발급 수명·인증·서명 경계를 구현한다. 원계약4F9와 불변 issuer 핵심 SHA `0F6937BD52732C49E979C8F8A3F897C81733DD21028BE6EEB194AC0B381D012A`를 유지한다. 코드 구현 승인과 운영키 시작을 구별한다.

## 정확 추가 범위

- `qa/tools/Invoke-Q0TrustedChildIssuer.ps1` — root의 외부 전용 제어 도구.
- `qa/tools/Test-Q0TrustedChildIssuer.ps1` — 키 없는 모의·수명 검수 도구.

기존570 준비/실행 입력에 포함하지 않고 별도 제어 소스 지문으로 결속한다. 원격 허용 두문서·제품/QA 코드 게시 범위를 늘리지 않는다. 원래 Git·핵심 모듈·570 소스·이미 발급된 준비v2/기존 보고는 변경하지 않는다. 테라가 구현하고 루나가 별도 검수하며 아스트라가 실제 두 도구SHA와 근거를 수용한 뒤에만 운영 시작을 판단한다. 기존 준비v2의 한정 수용은 이 신규 도구 완료를 기다리는 관문으로 바꾸지 않는다.

## 소유 세션과 단계

하나의 전용 pwsh 프로세스를 정상 권한의 실제 소유 `tty=true` 도구 세션으로 유지한다. 임의 공개 파이프/다중 호출자 인터페이스를 만들지 않는다. root가 동일 세션에 공개 단계만 전달한다. 원시 stdin 비동기 읽기·UTF-8/중복키/정확필드·16384바이트 상한·유한기한을 적용한다. Console.In.ReadLineAsync라는 이름만으로 비동기 기한을 보장한다고 주장하지 않는다. 장치 에코와 프로토콜 응답을 혼동하지 않는다. 첫 입력 전30초,한 요청의 첫 바이트 수신부터 읽기/처리30초 상한과 키 생성부터 전체45분 단조기한을 적용한다. 요청 사이의 대기는 남은 전체45분 안에서 허용하되 새 요청마다 전체기한을 재시작하지 않는다.

운영 시작 전 정확 이 도구/핵심SHA·준비 수용·도구 세션 소유·실제 호출 인자를 대조한다. 공개키 자리 외 코드·준비 경로/원격 승인 범위가 미완성이면 키 생성 전에 실패한다. 실제 CNG null 이름·RSA3072·내보내기 금지·정수45분은 불변 핵심 제한 호출을 사용한다. 실제 세션ID/개인키/토큰/환경값은 응답·디스크·인자로 내보내지 않는다. 공개키/지문/새 epoch만 공개한다. 기존 실패 세대·451 고정 진행자를 위장 재사용하지 않는다.

상태는 Unbound→Bound→Signed→Closed다. 공개정보 읽기는 같은 현재 세대만 반환하며 키를 재생성하지 않는다. Bind 전에 동일 프로세스에서 고정 gh 실행파일의 실제 인증 GET으로 저장소ID1344230225·불변 병합commit·정확 권위 blob 원문·계약4F9·실행 verifier 지문·공개12필드/현재 epoch/fingerprint를 확인한다. 실제 API exit/응답을 검사하고 임의 Authenticated 표시·사용자 제공SHA·실패 응답을 인증으로 인정하지 않는다. 토큰을 추출하거나 출력하지 않는다. 원격 쓰기는 이 도구에 넣지 않는다.

원격 경로는 `docs/specs/work-contracts/2026-10-02-q0-trusted-child-execution.md`, `docs/approvals/2026-10-02-q0-execution-public-authority-r1.json` 두문서뿐이다. 서명자가 직접 읽은 권위 원시SHA를 같은 핵심 세션에 한 번 Bind한다. 이후 정확 원문 계획SHA/nonce·기존 payload·계약/권위·최종 source/Git/준비v2 결속을 검토한 한 번 Sign만 허용한다. 응답 전송 손실도 두 번째 서명의 근거가 아니다. Sign 직후 키를 닫고 전용 프로세스가 종료하며 성공을 위한 재발급 루프를 만들지 않는다.

실제 아스트라가 unsigned 최종 계획 원시SHA/nonce를 먼저 검토한 뒤 한 번 서명한다. 기존 승인 레코드의 정확10필드는 SchemaVersion/ContractSha256/AuthoritySha256/PlanSha256/Context/Nonce/SignatureBase64/SignerRole/ApprovedAtUtc/PlanPath다. ApprovedAtUtc는 기존 핵심이 허용하는 초 단위 `yyyy-MM-ddTHH:mm:ssZ`이고 계획의 같은 값과 정확 일치해야 한다. 프로세스 StartTicks/StartUtc의 전체 정밀도와 이 승인 시각 형식을 혼동하지 않는다. 프로토콜 SignerRole='Astra'는 실제 root 시스템의 서명 실행을 gpt-6-astra 실행으로 소급하는 근거가 아니다. 실제 아스트라의 기술 검토, root의 시스템 호출, 루나의 서명 후 독립 검수, 실제 아스트라의 Authorize 개시 판단을 각각 기록한다.

장수명 큐는 별도의 기존 소유 장수명 세션에서 시작·감시한다. signer의 생성 자식이나 signer 생존에 의존하는 큐를 만들지 않는다. signer는 실제 Ready의 PID/전체ticks/UTC/경로·sourcebindings·InvocationId/LeasePipeName·실제 부모를 OS에서 대조하여 읽기 핸들을 보유한다. 사후 읽기 핸들을 직접 생성 반환 핸들이라고 부르지 않는다. 그 정확 신원을 계획에 서명한다. 서명 전 계획 기술검토와 서명 후 루나 최종검수/실제 아스트라 Authorize 승인을 구별하며, 이 도구가 아홉 큐를 개시하지 않는다.

## 실패·정리·관측

EOF/Abort/소유 세션 사망·잘못된 형식/순번·기한초과·원격 불일치·중복Bind/Sign은 그 세대의 실패와 종료다. 핵심 CloseSession의 Dispose 예외를 고려하여 중첩 finally로 입력/읽기핸들/모듈 정리를 각각 시도하고, 전용 signer 프로세스 실제 종료를 외부 소유자가 확인한다. 키 객체의 관리 Dispose 성공은 관측 범위에서만 주장한다. 프로세스 종료가 CNG 핸들 해제의 필수 마지막 경계이며 멈춘 signer는 정확 소유 핸들/전체ticks/경로를 재확인한 그 프로세스만 중단할 수 있다. 키 재생성·세션 재활성화·같은 계획 재서명은 금지한다.

root의 키 없는 실제 TTY probe(PID37400/전체ticks639265572817887453, 공개 KEYLESS_CLOSE 수신/exit0)는 보고된 기본 입출력 근거다. 전체45분·인증·서명·정리 검수의 대체물이 아니다. 프로토콜의 정확 명령/필드·표준출력 응답·중단/에코 처리와 소스SHA를 구현 보고에 명시하여 검수 대상이 흔들리지 않게 한다.

## 키 없는 시험과 수용

시험은 실제 CNG/비밀키/SignHash/원격 쓰기를 호출하지 않는 모의 어댑터로 제한한다. 모의 성공을 운영 권위로 만드는 caller boolean이나 일반 입력의 시험 어댑터 삽입 경로는 금지한다. 운영 경로는 고정 핵심/gh/프로세스 API를 사용하고, 키 없는 모드가 그 실행에 도달하지 않음을 별도 부정 시험으로 확인한다. 제어자의 실제 TTY/열린 무입력/EOF/Abort·정상종료·읽기 오류·소유세션 사망·기한, JSON/숫자 정밀도·명령 순서, 인증 GET 실패/다른 저장소·commit·계약·원시SHA·키/epoch, 다른 큐 ticks/경로·죽은 큐, 중복Bind/Sign, Sign후 응답손실, Close예외와 최종 프로세스 종료를 검증한다.

기대/실제 관측·모의 호출 횟수·실제 프로세스 신원/종료·소스 전후SHA·실패를 기록한다. 정수는 PowerShell/.NET Int64 원문 경계로 보존하고 JavaScript Number 재직렬화를 금지한다. 증거 후보는 메모리에서 완성·root/Luna 검수한 뒤 동일 바이트를 허용 JSON에 CreateNew한다. 실패 결과를 덮거나 임의 v2를 만들지 않는다. 두 새 소스는 검수 전 수정 가능하지만 최종 운영 대상은 아스트라가 수용한 정확SHA만이다.

도구 검수 보고/아스트라 한정 판정은 기존 인계문서에 경로/지문/실제 역할을 기록할 수 있다. 새 보고 파일을 자동 추가하지 않는다. 최종 코드와 키 없는 증거의 독립 검수·아스트라 판정 전 운영키는0으로 유지한다. 이 계약 자체로 준비570·공개4자리·실행복제·원격·아홉 실행을 성공 수용하지 않는다.
