# ADR-0039: 실제 플레이 통합 우선과 반복 복구 범위 제한

- 상태: accepted — 2026-10-03 실제 아스트라 `gpt-6-astra`의 절차 한정 승인. 실제 루나 `gpt-6-luna`의 독립 검토와 보정을 반영했다. 미래 제품 구현·운영 실행 승인은 아니다.
- 범위: 구현 우선순위·작업 배정·사전 확인·검사 계획·반복 종료. 게임 내용과 수치·기존 승인·독립 검수·Q0 인간/운영 관문은 유지한다.

## 문제와 근거

[세부 감사](../verification/implementation-audits/2026-10-03-03.md)는 시험 정지 오판, 실제 정상 입력의 늦은 검사, 모의 경계의 생산 연결 누락, 빈 배열 계열 재발, 오래된 선택 지문, 승인 순환, 부품 수용 이후 플레이 통합 배정의 공백을 확인했다. 현재 제품 소스/장면/프리팹/빌드124파일은 최초 감사와 같고 실제 연속 챕터와 사용자용 최신 플레이 빌드는 확인되지 않는다.

필요한 안전성·독립 검수는 유지한다. 검증 결과 수·문서 수를 게임 진척으로 세거나, 현재 승인 체계를 폐기하거나, 게임 기능을 무승인으로 연결하는 선택은 채택하지 않는다. 종속 증거의 엄격함을 유지하면서 비싼 단계 전에 실제 입력 경계를 검사하고 작업의 종료 조건을 사용자 전달물에 연결한다.

## 결정안

1. 다음 주력은 기존 부품을 잇는 최초 로컬 체험의 한정 제품 계약·실제 의존 조사다. 새 코드/장면 구현은 해당 제품 계약 Approved 이후이며 전체 데모 AC를 축소하지 않는다.
2. 게시/서명 작업의 완료를 모든 로컬 설계·구현의 암묵적 선행으로 두지 않는다. 실제 기술/권위 의존을 계약에 명시하고 동결 자료·현재 Q0 운영 승인 대기는 보존한다.
3. 같은 사용자 동작·위험/소유 경계는 한 구현 묶음·한 영향별 검사 계획으로 관리한다. 부분 수용/공동 최종 검증 의존은 비순환으로 설계한다.
4. 실제 생산 입구·정상 전체 계획·첫 캡처를 권한 소비/전체 실행 전에 확인한다. 모의 경계는 구별하고 동일 오류 계열은 관련 소비 경로도 한 번 점검한다.
5. 같은 오류 두 번이면 큰 재실행을 중단하고 최소 재현·원인/변경/새 관측 목적을 기록한다. 단회 계약은 첫 실패부터 그 제한을 따른다. 무로그만으로 정지를 판정하지 않는다.
6. 집중 검사·필수 회귀·증거 재사용을 구현 전에 명시한다. 기존 필수 검사는 유지하고 영향없는 증거만 독립 검토로 재사용한다.
7. 기본 아트 패키지와 실제 플레이 장면 수용을 먼저 닫고 변형을 확대한다. 전체 본편/의상 목표는 유지한다.
8. 현재 상태표를 하나의 [규범 구현 전략](../specs/work-contracts/2026-10-03-play-first-delivery-strategy.md)에 유지하고 중요 체크포인트에서 고정 감사의 이전/현재/증감과 플레이 가능 구간을 보고한다.

## 영향과 적용 범위

2026-10-03 최신 사용자 지시로 위 결정 8항의 진척 감사 주기만 대체한다. 매일 한국시간 오전 8시 하루 한 번 전일 대비로 보고하고 구현부·중요 체크포인트별 추가 진척 감사는 하지 않는다. 별도 사용자 요청은 예외다. 상태표 갱신·구현 증거 기록·필수 독립 검수는 유지한다. 원래 승인 기록과 지문은 당시 검토의 이력이며 이번 변경은 게임 기능이나 Q0 운영 권한을 추가 승인하지 않는다.

새 기능/권한을 승인한 문서가 아니다. 다음 작업의 제품 계약·허용 파일·로컬 실행 권위는 별도 승인해야 한다. 검증/게시 도구 수정으로 생긴 진척과 실제 게임 연결 진척은 별도 보고한다. 기존 역사 기록·ADR-0036/0037/0038은 덮어쓰지 않는다.

규범 절차는 REQ-PROC-001..010과 AC-PROC-001..010을 따른다. 문서 설계 수용과 향후 절차 실행 수용은 구별한다. 정책으로 필요한 실행까지 생략하거나 새 문서 절차를 무한 확장하는 것이 아니라, 사용자 행동·작업 소유·위험이 같은 범위의 완료를 앞당기는 것이 목적이다.

실제 아스트라의 검토 시점 ADR 지문은 `0576C7D32996752051D60AFB8122585F35DCCC53EF9981FB06BEE5849CC8A84B`이며 상태/승인 기록 변경 후 지문과 구별한다. 다음 주력 P0-LOCAL과 절차 범위만 승인했고 기존 Q0·미디어·제품 구현의 독립 승인 관문은 유지한다.
