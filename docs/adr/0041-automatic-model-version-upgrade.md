# ADR-0041: 실제 가용 상위 모델 버전의 자동 승격

- 상태: accepted — 2026-10-03 사용자 명시 지시.
- 범위: 현재 표준 모델 기준과 이후 배정·재시도·대체 호출의 같은 계열 상위 버전 적용. 제품·실행·게시 권한을 추가하지 않는다.

사용자는 새 모델 버전이 제공되면 기준 버전을 즉시 올리고 작업에 적용하도록 지시했다. 예시인 `gpt-6.1-sol`에서 `gpt-6.2-sol`로의 전환은 후자가 실제 호출 가능 목록에 제공될 때 자동 적용한다. 추가 승인을 기다리지 않는다.

## 선택과 적용

1. 새 작업 배정 직전에 현재 호출 도구의 실제 허용 모델과 지원 추론 설정을 확인한다. 아스트라·솔·루나 각 계열에서 현재보다 높은 안정 숫자 버전만 선택한다. 테라는 솔 기준 버전의 별도 구현 작업자다.
2. 숫자 버전을 정수 구성요소로 비교한다. 예를 들어 6.10은 6.2보다 높다. 같은 계열의 정확 식별자가 목록에 있는 경우만 채택한다. 발표·웹 문서만으로 계정 또는 도구 가용성을 추정하지 않는다. 이 세션의 목록에는 `gpt-6.2-sol`이 없어 아직 호출하거나 기준에 채택하지 않았다.
3. 현재 기준은 아스트라 `gpt-6-astra`, 솔·테라 `gpt-6.1-sol`, 루나 `gpt-6-luna`다. 이후 각 계열이 올라가면 현재 표준의 배정값을 함께 갱신한다. 다른 계열·임의 미리보기/Pro 식별자·5.6 이하 복귀·금지된 외부 모델은 허용하지 않는다.
4. 다음 신규 작업·재시도·대체 배정에 승격 모델을 사용한다. 실행 중인 작업을 모델 발견만으로 강제 중단하지 않는다. 완료된 사실·원시 증거·과거 승인·모델 참여 기록은 실제 사용 모델을 유지한다. 이전 기준 작업자를 다음 신규 과업에 재개하는 대신 승격 모델의 새 작업자에게 인계한다.
5. 구현·독립 검수·승인의 역할과 기존 추론 수준·실행 권한은 유지한다. 동결 계약이 정확 모델 식별자를 요구해 충돌하면 기준은 승격하되 해당 작업은 계약 호환 보정 후 실행한다. 새 모델을 옛 모델로 허위 표기하거나 동결 소스/인계/승인 원문을 자동 수정하지 않는다. 기존 실행 세대·키·기한·Q0 인간 승인·필수 검사·원격 게시 관문은 별도다.

## 대기 중 확인과 기록

현재 대화에 매시간 보조 확인 자동화 `automation-2`를 생성했다. 즉시 적용은 상위 버전을 실제 관측한 시점의 기준 갱신과 다음 배정 적용을 뜻하며, 출시 순간을 상시 감지하는 서비스라고 주장하지 않는다. 실제 호출 가용성을 확인할 수 없으면 기준을 유지한다. 인증·한도·모델 오류를 반복 탐색하거나 별도 유료 API·자격증명 추출·앱 설치로 우회하지 않는다.

실제 승격이 있을 때만 AGENTS.md, 운영 모델, 문서 지도와 현재 전략의 배정값 및 GPT 참여 원장에 이전→현재 모델·관측 시각·가용성 출처·적용 범위를 기록하고 사용자에게 알린다. 변화 없는 확인은 조용히 종료한다. 기존 일일 오전 8시 진척 감사 자동화는 변경하지 않는다. 모델 갱신을 게임 구현 진척으로 집계하지 않는다.

공식 문서도 계정의 모델 목록과 실제 사용 가능한 모델을 기준으로 선택할 것을 설명하며, 앱 서버의 목록은 캐시일 수 있음을 명시한다. [공식 모델 가용성 안내](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference). 이 정책에서는 자격증명에 직접 접근하지 않고 현재 작업에 노출된 호출 도구의 목록만 실행 가용성 근거로 사용한다.
