# ADR-0044 — 중간 사용자 조작 없이 1챕터 로컬 빌드 완성

- 상태: Accepted — 2026-10-21 사용자 직접 지시.
- 결정: Astra `gpt-6-astra`. 구현 Sol `gpt-6.1-sol`, 독립 검수 Luna `gpt-6-luna`.

## 배경

R01 관측 경로는 사용자의 재생·통지와 외부 보안창 처리 대기를 반복했고, 준비 성공이 1챕터 실행파일 전달을 대신했다. 사용자는 중간 승인·재생·키 입력을 더 수행하지 않고 정상 플레이 가능한 최종 결과물만 받도록 개발과 검사를 위임했다. r23도 준비 성공 뒤 종료됐으며 그 권위를 되살리지 않는다.

## 결정

새 로컬 개발 경로에서는 에이전트가 시험 시작·정지·게임 입력·재시도·빌드를 수행한다. Unity 공개 시험 API와 격리된 시험 입력, 명시적 개발 진입점, 배치 검사 및 Windows 단독 빌드를 우선 사용한다. 사람이 중간 재생 버튼을 누르거나 키 해제·경로 입력을 보고하는 관문은 이 경로에서 폐지한다. 기존 Q0·R01·G3의 동결 실행과 소비 기록은 수정하지 않는다. 그 과거 수용 조건을 새 자동 시험의 실행 조건으로 복제하지 않는다.

자동 입력은 시험 장치 또는 정확 대상 게임 창에만 한정한다. 보안창·인증·권한 설정 조작은 여전히 금지하며 해당 경로를 종료하고 가능한 다른 검증 경로로 진행한다. 원격 게시·키·서명·실사용 프로필 변경은 이번 위임에 포함하지 않는다. 게시 대기는 로컬 개발과 로컬 전달을 막지 않는다.

최종 목표는 CH1 시작→거점→원정→보스→유담 양선택→각 기술·봉쇄선→세령과 CH1 종결, 실패와 재시도를 포함하는 Windows 실행파일이다. 기존 CH1 §17/22/25와 C1-C Approved 설계를 우선 재사용한다. 앞부분의 Review 문구만으로 승인된 범위를 취소하지 않는다. 새로운 미승인 제품 행동은 단일 실행계약의 정확 변경 표에서 Astra가 내부적으로 닫으며 사용자에게 반복 승인 요청하지 않는다.

자동 시험·합성 입력·실제 창 조작·독립 검수·사용자 체험을 별도로 기록한다. 자동 검사를 사람 완주나 기존 3명 분량 검수로 표기하지 않는다. 사용자 최종 체험을 전달 전 선행으로 요구하지 않으며, 기존 인간 검수는 역사적 품질 조건으로 남긴다. 자동 검증 완료와 모든 과거 인증 완료를 구분한다.

## 결과와 대안

Editor 관측창과 장시간 녹화가 매 개발 실행의 선행이 되는 방식은 중단한다. 필요한 기능 증거는 짧고 목적이 명확한 시험·로그·화면·빌드 지문으로 모은다. 입력 전달·실제 렌더·창 초점은 화면 없는 시험으로 입증하지 않는다. 독립된 같은 릴리스 빌드의 실제 화면 조작 검증을 전달 조건으로 유지한다.

활성 범위와 유한 실행 예산은 [단일 계약](../specs/work-contracts/2026-10-21-autonomous-chapter1-delivery.md)에 둔다. 실패 후 무변경 반복과 성공 위조는 허용하지 않는다. 모델·단일 쓰기 소유·구현/독립 검수 분리는 ADR-0043을 유지한다.
