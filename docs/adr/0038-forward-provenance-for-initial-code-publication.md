# ADR-0038: 최초 게임 코드 게시의 현재 바이트 기준

- 상태: accepted — 2026-10-01 사용자 명시 선택, 아스트라 적용
- 범위: 최초 게임 코드 게시 후보의 출처를 앞으로 검증하는 기준. 게임 동작이나 기존 승인 명세를 변경하지 않는다.

초기 게시 후보 489개와 이후 C4 신규 12개의 원장에는 역사적 직접 근거 61개와 공백 428개가 남아 있다. 기존 C4 변경 10개 파일의 동결 기록에서는 서로 다른 지문 전이 14개를 관측했으나 당시 구현 바이트가 없어 14개 전부 미입증이다. 현재 파일이 실제 Unity 검증을 통과한 사실만으로 각 과거 변경의 바이트와 당시 승인을 재구성할 수 없다.

사용자는 누락된 과거 바이트를 모두 찾을 때까지 기다리는 선택 대신, **현재 바이트를 새 독립 출처 기준으로 검증하는 방식**을 선택했다. 과거 공백과 원래 후보 바이트 부재는 그대로 보존한다. 새 기준은 정확한 파일 경로·현재 SHA-256·조사 시각·승인된 요구·의존성을 파일별로 결속한다. 새 기준의 성공은 과거 14개 전이의 폐쇄나 과거 구현 승인을 뜻하지 않는다.

새 기준 후보는 로컬 원본 `artifacts/c4-initial-publication-byte-closure-v1.json`의 정확한 489+12경로에서 시작한다. 소스뿐 아니라 메타·GUID, 조립 정의, 자산·장면·프리팹, 패키지·설정, QA 도구와 선택 입력까지 조사한다. 누락된 의존 파일은 자동으로 포함하지 않고 별도 범위 결정에 올린다. 원격 기본 가지의 실제 개정·트리·파일 바이트를 다시 읽고, 서로 다른 기존 파일은 명시적으로 충돌 판정한다.

이 방향은 [읽기 전용 출처 조사 계약](../specs/work-contracts/2026-10-01-initial-code-publication-forward-provenance.md)의 제한된 승인으로 시작한다. 조사 결과와 독립 검수 뒤 아스트라가 정확한 파일별 허용·제외 목록을 별도로 판정한다. 그 다음 별도 계약으로 깨끗한 복제의 Unity 가져오기·컴파일·회귀와 Q0 Git 상태 조건을 검증해야 한다. 이 단계들이 끝나기 전에는 현재 바이트를 원격 게시하거나 빌드 가능한 초기 기반이라고 주장하지 않는다.

## 2026-10-02 사용자 선택에 따른 보충

사용자는 [Git 정규화 조사](../verification/2026-10-01-initial-publication-git-canonicalization-precheck.md)에서 확인한 18개 줄바꿈 차이에 대해 기존 저장소 규칙을 유지하고 **Git 기록 바이트를 새 후보 기준으로 재검증**하는 추천안을 선택했다. 원문 501개 기준과 과거 증거는 보존하며 정규화된 SHA를 과거 승인 지문으로 소급하지 않는다. 새 바이트의 독립 검수·실제 실행 검증은 별도로 남긴다.

또한 QA 검사기와 후보 밖 직접 입력 네 개를 함께 검토하는 추천안을 선택했다. [505개 검토 후보 계약](../specs/work-contracts/2026-10-02-publication-lf505-baseline.md)은 추가 범위와 전이 근거 작성만 허용한다. 505개 전부의 게시 승인이나 의존성 폐쇄가 아니다. [결정 기록](../approvals/2026-10-02-publication-byte-and-qa-scope-decision.md)에 적용 범위를 남긴다.

같은 날 사용자는 후속 추가 범위 판단을 아스트라에 위임했다. 아스트라는 [코드·필수 검증 입력 우선](../approvals/2026-10-02-code-first-publication-scope-decision.md)을 선택했다. 후보 밖523개 중 실제 코드·필수 검증 의존을 정확 경로로 선별하고 미디어/과거 기록은 개별 실제 의존 근거가 있는 경우에만 후보로 올린다. 이 위임 범위의 통상 기술 선택은 사용자에게 반복 질문하지 않고 계약·근거·검증 결과로 구체화한다. 파일별 게시 승인·독립 검수·기존 제품 계약은 유지한다.
